## 为了什么（Why）

**核心痛点**：后面每一章的公式都会出现矩阵乘法。不懂矩阵乘法，等于看天书。

举个反例：Ch29 的 Self-Attention 核心公式是 `softmax(QK^T/√d)`。如果你不懂：

- `√d` 是标量除法（每个元素都除）
- `softmax` 是按行做的（不是对整个矩阵）

那这个公式对你来说就是一堆字母堆在一起，根本看不出"哦，这是在算每个 query 和每个 key 的相似度"。

**这一章的目标**：把"向量、矩阵、点积、矩阵乘法"这四个概念彻底搞懂，让你看到 `A @ B` 时脑子里能立刻浮现出"行乘列"的画面。

## 做了什么（What）

线性代数的世界可以浓缩成四个概念：向量、矩阵、点积、矩阵乘法。它们的关系是这样的：

```
向量（一排数）
   │
   ├──> 点积（两个向量 → 一个数）
   │
   ▼
矩阵（一堆向量排成的表格）
   │
   └──> 矩阵乘法（行 × 列的批量点积）
```

### 逐组件拆解

**向量（Vector）**：一排数。比如 `[1.0, 2.0, 3.0]` 是一个长度为 3 的向量。可以理解为一个点在三维空间的坐标，也可以理解为一组特征（比如一个用户的"年龄、收入、消费"三个特征）。

**矩阵（Matrix）**：一堆向量排成的表格。比如 `[[1, 2], [3, 4]]` 是一个 2 行 2 列的矩阵。可以理解为"多个样本每个有多个特征"——一行一个样本，一列一个特征。

**张量（Tensor）**：矩阵的推广。矩阵是二维的，张量可以是任意维度。一张彩色图片是 3 维张量（高×宽×3 通道），一批图片是 4 维张量（批大小×高×宽×3）。PyTorch 里所有数据都是张量。

**点积（Dot Product）**：两个向量"对应相乘再求和"。结果是**一个数**（标量）。衡量两个向量的"相似度"——方向越一致，点积越大。

**矩阵乘法**：行 × 列的批量点积。`A @ B` 的第 i 行第 j 列，等于 A 的第 i 行和 B 的第 j 列做点积。

## 怎么算（How）

### 1. 向量点积

公式：`a · b = Σ(a_i × b_i) = a_1×b_1 + a_2×b_2 + ... + a_n×b_n`

**数值小例子**：

设 `a = [1.0, 2.0, 3.0]`，`b = [4.0, 5.0, 6.0]`。

逐步计算：
- 第 1 项：1.0 × 4.0 = 4.0
- 第 2 项：2.0 × 5.0 = 10.0
- 第 3 项：3.0 × 6.0 = 18.0
- 求和：4.0 + 10.0 + 18.0 = **32.0**

所以 `a · b = 32.0`。

### 2. 矩阵乘法（2×2 完整展开）

公式：`C[i][j] = Σ_k A[i][k] × B[k][j]`

设 `A = [[1, 2], [3, 4]]`（2×2），`B = [[5, 6], [7, 8]]`（2×2）。

**4 个元素全部展开**：

- `C[0][0] = A[0][0]×B[0][0] + A[0][1]×B[1][0] = 1×5 + 2×7 = 5 + 14 = 19`
- `C[0][1] = A[0][0]×B[0][1] + A[0][1]×B[1][1] = 1×6 + 2×8 = 6 + 16 = 22`
- `C[1][0] = A[1][0]×B[0][0] + A[1][1]×B[1][0] = 3×5 + 4×7 = 15 + 28 = 43`
- `C[1][1] = A[1][0]×B[0][1] + A[1][1]×B[1][1] = 3×6 + 4×8 = 18 + 32 = 50`

所以 `A @ B = [[19, 22], [43, 50]]`。

**直觉理解**：`C[0][0]` 是 A 的第 0 行 `[1, 2]` 和 B 的第 0 列 `[5, 7]` 的点积。行 × 列，这就是矩阵乘法的全部秘密。

### 3. 维度规则

`(m, n) @ (n, p) = (m, p)`

**关键**：内维度必须匹配。A 的列数 = B 的行数，否则报错。

**例子**：
- `A.shape = (3, 4)`，`B.shape = (4, 2)` → `A @ B.shape = (3, 2)` ✅
- `A.shape = (3, 4)`，`B.shape = (3, 2)` → 报错！内维度 4 ≠ 3 ❌

### 4. 矩阵乘法为什么这么定义？

这是很多人卡住的点——为什么不定义成"对应元素相乘"？

答案是：**矩阵乘法要表达"线性变换的复合"**。

把矩阵理解为一个"变换动作"：把一个向量"扭"成另一个向量。如果你先做变换 A 再做变换 B，合起来的效果就是 `B @ A`（注意顺序）。矩阵乘法的定义就是为了表达这种"先 A 后 B"的复合变换。

"对应元素相乘"也有用，叫 **Hadamard 积**（记作 `A * B`），但它的用途完全不同——主要用于"逐元素缩放"，比如神经网络的梯度逐元素相乘。

## 想多一点

> 矩阵乘法为什么不定义成"对应元素相乘"？
>
> 提示：因为矩阵乘法要表达"线性变换的复合"——先做变换 A 再做变换 B，合起来的效果。对应元素相乘叫 Hadamard 积，用途是"逐元素缩放"，两者解决的问题完全不同。如果你把矩阵乘法定义成对应元素相乘，那 `A @ B` 就无法表达"先 A 后 B"的复合变换，整个线性代数的体系就塌了。

## 易错点预警

- ❌ `np.array([1, 2, 3])` 的 shape 是 `(3,)` 不是 `(3, 1)` → ✅ 正确：用 `a.reshape(3, 1)` 得到列向量，或用 `np.array([[1], [2], [3]])`。一维数组既不是行向量也不是列向量，是"裸向量"。
- ❌ `A.shape=(2,3)`，`B.shape=(2,3)`，直接 `A @ B` 报错 → ✅ 正确：内维度 3 ≠ 2 不匹配。要么用 `A @ B.T`（转置后变成 (2,3)@(3,2)=(2,2)），要么用 `A * B`（Hadamard 积，对应元素相乘）。
- ❌ 把 `A * B`（Hadamard）和 `A @ B`（矩阵乘法）搞混 → ✅ 正确：`*` 是对应元素相乘，`@` 是行乘列。形状要求也不同：`*` 要求同形状（或可广播），`@` 要求内维度匹配。

## 章末小结

| 概念 | 一句话解释 | 易错点 |
|------|-----------|--------|
| 向量（Vector） | 一排数，一维数组 | NumPy 中 `shape=(n,)` 和 `shape=(n,1)` 不同 |
| 矩阵（Matrix） | 二维表格，m 行 n 列 | 行列顺序不能反，`(2,3)` 是 2 行 3 列 |
| 张量（Tensor） | 矩阵推广到任意维度 | PyTorch 的张量和 NumPy 的 ndarray 几乎一样 |
| 点积（Dot Product） | 对应相乘再求和，结果是一个数 | 两个向量维度必须相同 |
| 矩阵乘法 | 行 × 列的批量点积 | `(m,n)@(n,p)=(m,p)`，内维度必须匹配 |
| Hadamard 积 | 对应元素相乘，`A * B` | 与矩阵乘法 `A @ B` 完全不同 |
| 转置（Transpose） | 行列互换，`A.T` | `(m,n).T = (n,m)` |
