# 02-你的第一个后端程序

> "10 行代码，一个能跑的后端。从新建文件到浏览器看到 Hello World，再配上热重载——写完这一章，你就正式入门了。"

---

## 一、目标与完成效果

**一句话目标**：用 Express 写出人生中第一个 Node.js 后端程序，浏览器访问 `http://localhost:3000` 时显示 `Hello World`，并配上 nodemon 实现"保存即刷新"的热重载体验。

**完成后的可观测效果**：
- 在终端输入 `npm run dev`，服务器启动，输出 "Server is running on http://localhost:3000"。
- 浏览器访问 `http://localhost:3000`，页面显示 `Hello World`。
- 你修改代码中返回的文字，保存，浏览器刷新后立即看到新内容——不用手动重启服务器。
- 你按 `Ctrl+C` 能正常停止服务器。

## 三、分步操作

### 步骤 1：安装 Express

打开终端，进入 `blog-backend/` 目录，执行：

```bash
npm install express
```

输出类似：

```
added 65 packages, and audited 66 packages in 3s

13 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities
```

> **npm install 发生了什么？** npm 去它的在线仓库找到了 `express` 这个包，下载了最新版本，放到了 `node_modules/` 文件夹里。Express 自己又依赖了其他几十个小包（这叫"传递依赖"），npm 也一并下载了。所以你会看到 "added 65 packages"——你装了 1 个包，实际上进了 65 个。

#### `--save` vs `--save-dev` 是什么？

| 参数 | 含义 | 什么时候用 |
|------|------|-----------|
| `npm install express` | 安装并记录到 `dependencies` | **生产环境也需要的包**（如 Express、数据库驱动） |
| `npm install --save-dev nodemon` | 安装并记录到 `devDependencies` | **只在开发时需要**的包（如测试工具、热重载工具） |

> npm 5 以后，`npm install express` 默认就是 `--save`，不需要手动加 `--save`。但 `--save-dev` 仍然需要显式写出。

安装完成后，检查 `package.json`——你应该看到多了一个 `dependencies` 字段：

```json
{
  "dependencies": {
    "express": "^4.x.x"
  }
}
```

#### Express 版本号前面的 `^` 是什么意思？

`^4.18.2` 的意思是："接受 4.18.2 及以上，但不跨大版本（保持 4.x.x）"。也就是 `4.18.2` 到 `<5.0.0` 之间的任何版本都可以。这样做的好处是：别人拿到你的项目运行 `npm install` 时，如果 4.18.3 发布了（修了某个 bug），会自动安装 4.18.3，而不是死钉在 4.18.2。

#### `package-lock.json` 是什么？

`npm install` 之后，你的目录里多了一个 `package-lock.json` 文件。它的作用是 **锁定精确版本**——`package.json` 说"我要 4.x"，`package-lock.json` 说"具体是 4.18.2，以及它的 64 个依赖分别是这些精确版本"。

> `package.json` = "我要宫保鸡丁"（描述意图）。`package-lock.json` = "宫保鸡丁的精确配方：鸡胸肉 200g、花生 50g、干辣椒 10g……"（锁定具体实现）。你把 `package-lock.json` 提交到 Git，能保证所有人装出来的依赖完全一致。

### 步骤 2：写 10 行代码创建 server.js

在 `blog-backend/` 目录下新建一个文件，命名为 `server.js`。**一个字一个字敲进去**（不要复制粘贴）：

```javascript
const express = require('express');
const app = express();

app.get('/', (req, res) => {
    res.send('Hello World');
});

app.listen(3000, () => {
    console.log('Server is running on http://localhost:3000');
});
```

保存文件。

> **为什么让你手敲？** 就像学骑自行车，看别人骑一百遍不如自己上去摔一次。手敲代码能让你注意到每个字符：函数名是 `send` 还是 `sent`？端口号写在哪里？回调函数的参数顺序是什么？这些细节复制粘贴时你根本不会在意，但报错的时候它们就是元凶。

#### 逐行解释——这 10 行代码到底在说什么

我们用**开餐厅**的比喻来理解每一行。

---

```javascript
const express = require('express');
```

**翻译**：从 `node_modules/` 里找到 `express` 这个包，加载它，把它的功能赋给常量 `express`。

**比喻**：你去工商局领了一张营业执照模板。`require('express')` 就是走进工商局（node_modules），拿到 Express 框架这张"开店模板"。

---

```javascript
const app = express();
```

**翻译**：用刚拿到的模板，创建一家真正属于你的"餐厅"——命名为 `app`。

**比喻**：你在模板上填了餐厅名字，拿到了一张真实的营业执照。从此以后，这张执照（`app`）就代表你的整个餐厅（你的整个后端应用）。客人点什么菜、怎么接待、厨房怎么做——这些规则都挂在这张执照下面。

---

```javascript
app.get('/', (req, res) => {
    res.send('Hello World');
});
```

这三行要放在一起理解。

**`app.get('/')`**：在餐厅门口挂一个牌子："当有客人走到大门 `/` 的时候，执行下面这个接待流程"。

- `app` = 你的餐厅（营业执照）
- `.get()` = 一种接待方式（GET 是"客人只是来看看菜单"，不点菜、不修改）
- `'/'` = 餐厅大门（路径 `/` 代表首页，就像餐厅的正门入口）

**`(req, res) => { ... }`**：这是一个箭头函数。每当有客人走到大门，Express 就会调用这个函数。Express 会传进来两个重要参数：

- `req`（request，请求）= **"客人说了什么"**。客人是从哪来的？想点什么？带了什么证件？
- `res`（response，响应）= **"你怎么回应客人"**。用 `res.send()` 把菜端上去。

**比喻**：`req` 是服务员收到的小票（客人点的单），`res` 是服务员端的托盘（你要往托盘上放什么菜）。

**`res.send('Hello World')`**：往托盘上放一盘菜——内容是 `'Hello World'` 这个字符串。Express 会自动设置响应头（Content-Type），把它送回给客人（浏览器）。

---

```javascript
app.listen(3000, () => {
    console.log('Server is running on http://localhost:3000');
});
```

**翻译**：让餐厅在 3000 号窗口开始营业。开业之后，在收银台上贴一张字条，写上"餐厅已开张，地址是 http://localhost:3000"。

**比喻**：你租了一个商场里的铺位（3000 号），开业那天在门口放了个花篮（console.log），告诉大家"我们开始营业了！"。

> 🔥 **魔鬼细节**：`app.listen(3000, () => { ... })` 的第二个参数是一个回调函数。这个回调函数**在服务器启动完成后才执行**，不是在调用 `listen` 时立即执行。也就是说，只有当你看到 `console.log` 输出时，才说明服务器真的准备好了。如果 `console.log` 没输出但程序也没报错，说明服务器可能正在启动但还没完成。

### 步骤 4：浏览器访问 http://localhost:3000

打开你最喜欢的浏览器，在地址栏输入：

```
http://localhost:3000
```

回车。

你应该看到白底黑字：

```
Hello World
```

**🎉 恭喜！你的第一个 Node.js 后端程序跑起来了！**

#### 到底发生了什么？用餐厅比喻复盘

1. 你（浏览器）走进餐厅大门（访问 `http://localhost:3000/`）
2. 门口的引导员（Express 路由系统）看了一眼门牌号 `/`，查表发现："这个客人应该由 `(req, res) => { res.send('Hello World') }` 接待"
3. 服务员执行接待流程，往托盘上放了一盘菜：`'Hello World'`
4. 你（浏览器）吃到了这盘菜（显示了文字）

#### 三个关键概念

| 概念 | 解释 |
|------|------|
| **localhost** | 你电脑的"自言自语"地址。`localhost` = `127.0.0.1` = "我自己"。访问 `localhost` 就是在跟你自己的电脑通信。 |
| **端口（3000）** | 一台电脑可以同时跑很多程序。端口号就是区分这些程序的"门牌号"。3000 是 Node.js 社区的默认习惯（就像 Python 社区默认 8000，Java 社区默认 8080）。 |
| **Ctrl+C 停止服务器** | 服务器会一直运行，直到你主动停止。在终端按 `Ctrl+C`（Windows/macOS/Linux 都一样），服务器就会关闭。 |

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 | 原因 | 解决 |
|----------|------|------|
| `'node' 不是内部或外部命令` | Node.js 没装或 PATH 问题 | 回到 [01-环境搭建](01-环境搭建.md) 重装 Node.js |
| `Error: Cannot find module 'express'` | 忘了 `npm install express` | 执行 `npm install express` |
| `Error: listen EADDRINUSE :::3000` | 端口 3000 被占用了（可能是上次没关闭的服务器） | 换端口：把 `3000` 改成 `3001`；或找到占用进程杀掉（见步骤 8） |
| 改了代码浏览器没反应 | 你用的是 `node server.js` 启动的，没有热重载 | 按 `Ctrl+C` 停止，重新 `node server.js`；或看步骤 5 装 nodemon |
| `Cannot GET /xxx` | 你访问了 `/xxx`，但代码里只定义了 `/` | 访问正确的路径 `http://localhost:3000/` |
| 浏览器显示"无法访问此网站" | 服务器没启动，或端口号写错了 | 确认终端里能看到 "Server is running..."，确认端口号是 3000 |

### 步骤 5：安装 nodemon 实现热重载

现在你每次改代码，都要按 `Ctrl+C` 停止服务器，再敲 `node server.js` 重启。一天改 50 次代码就要做 50 次。

**nodemon** 就是帮你省掉这套机械劳动的工具。它会盯着你的文件，一旦发现变化，自动重启服务器。

安装 nodemon：

```bash
npm install --save-dev nodemon
```

> 注意是 `--save-dev`（不是 `--save`），因为 nodemon **只在开发时用**。你部署到服务器上时不需要它。

安装完成后，`package.json` 里会多一个 `devDependencies` 字段：

```json
{
  "devDependencies": {
    "nodemon": "^3.x.x"
  }
}
```

### 步骤 6：配置 npm scripts

我们不想每次都敲 `npx nodemon server.js`。把启动命令写入 `package.json` 的 `scripts` 里：

打开 `package.json`，把 `scripts` 字段改成：

```json
"scripts": {
  "start": "node server.js",
  "dev": "nodemon server.js",
  "test": "echo \"Error: no test specified\" && exit 1"
}
```

| 命令 | 用途 | 使用场景 |
|------|------|----------|
| `npm start` | 用 `node` 启动服务器（无热重载） | 生产环境、快速测试 |
| `npm run dev` | 用 `nodemon` 启动（有热重载） | 开发时用，改了代码自动重启 |

> **为什么 `npm start` 不加 `run`，而 `npm run dev` 要加 `run`？** `start`、`test`、`stop`、`restart` 是 npm 的内置脚本名，可以省略 `run`。其他自定义名字（如 `dev`、`build`、`deploy`）都必须加 `run`。

现在用新的方式启动服务器：

```bash
npm run dev
```

输出类似：

```
[nodemon] 3.x.x
[nodemon] to restart at any time, enter `rs`
[nodemon] watching path(s): *.*
[nodemon] watching extensions: js,mjs,cjs,json
[nodemon] starting `node server.js`
Server is running on http://localhost:3000
```

### 🤔 想多一点：为什么 Node.js 没有类似 Python `--reload` 那样的内置热重载？

你可能会想：Python 的 uvicorn 有 `--reload` 参数，为什么 Node.js 不自带热重载，还要额外装 nodemon？

**原因**：Node.js 核心团队有一个原则——**保持核心最小化**。Node.js 核心只包含最基础、最通用的功能（文件系统、网络、加密、流处理等）。热重载是"开发时的便利功能"，不是"运行时的核心功能"，所以被留给了社区——于是就有了 nodemon。

**这是 Node.js 社区的文化**：核心很小，功能靠生态。你想要的任何功能，基本都有 npm 包帮你实现。

> **nodemon 和 node 启动的区别**：`node server.js` 启动后，你对 `server.js` 的任何修改都不会生效，直到手动重启。`nodemon server.js` 启动后，它会用操作系统的文件监控机制（`fs.watch`）盯着项目目录，任何 `.js` 文件变化都会触发自动重启。**nodemon 不是"更快"的 node，它是一个包裹在 node 外面的"自动重启器"。**

### 步骤 8：常见错误排查表（扩展版）

| 序号 | 错误信息 | 原因 | 解决 |
|------|----------|------|------|
| 1 | `'node' 不是内部或外部命令` | Node.js 没装好 | 重装 Node.js 或重启终端 |
| 2 | `Error: Cannot find module 'express'` | 没装 express | `npm install express` |
| 3 | `Error: listen EADDRINUSE :::3000` | 端口被占用 | ① 换端口：`app.listen(3001, ...)` ② 杀进程：见下方 |
| 4 | `nodemon : 无法加载文件...禁止运行脚本` | Windows PowerShell 执行策略限制 | 管理员运行 PowerShell，执行 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| 5 | `[nodemon] app crashed` | 代码有语法错误 | 仔细检查代码，nodemon 会在终端输出具体错误位置 |
| 6 | `req is not defined` | 箭头函数参数写错了 | 参数必须是 `(req, res)`，顺序不能变，名字约定俗成但理论上可以改 |
| 7 | 改了代码 nodemon 没重启 | 可能只改了非 JS 文件，或 nodemon 没在运行 | 确认终端里是 `npm run dev` 启动的 |

#### 如何杀掉占用端口的进程？

```powershell
# Windows PowerShell：找到占用 3000 端口的进程
netstat -ano | findstr :3000

# 输出类似：TCP  0.0.0.0:3000  0.0.0.0:0  LISTENING  12345
# 记下最后一列的 PID（如 12345），然后：
taskkill /PID 12345 /F
```

```bash
# macOS / Linux
lsof -i :3000
# 记下 PID，然后：
kill -9 <PID>
```

| `--save-dev` | 标记"这个包只在开发时需要"，生产环境不装 |
| `localhost:3000` | 你电脑的"自言自语地址"的 3000 号门 |
| `Ctrl+C` | 在终端中停止正在运行的程序 |

## 八、已知坑点与禁止事项

1. **`Cannot find module 'express'`**：忘了 `npm install express`。注意——是 `express`，不是 `Express`（npm 包名是小写）。

2. **端口 3000 被占用**：常见于上次没正常关闭服务器（直接关了终端窗口而不是按 `Ctrl+C`）。解决方法：换端口或杀进程（见步骤 8）。

3. **箭头函数的参数顺序不能乱**：`(req, res)` 是 Express 的约定——第一个参数是请求对象，第二个是响应对象。写成 `(res, req)` 的话，`res.send()` 就会报错。

4. **nodemon 在 Windows PowerShell 上被阻止**：如果报 "无法加载文件...禁止运行脚本"，用管理员身份运行 PowerShell，执行 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`。

5. **改了代码 nodemon 没反应**：确认是用 `npm run dev` 而不是 `node server.js` 启动的。如果确实用的 dev，检查终端里是否有 `[nodemon]` 字样。有些情况下重命名文件不会被 nodemon 检测到——新建文件通常可以。

6. **不要在生产环境用 nodemon**：`npm run dev` 只在开发时用。部署到服务器上时，用 `npm start`（无热重载）或 PM2 等进程管理工具。
