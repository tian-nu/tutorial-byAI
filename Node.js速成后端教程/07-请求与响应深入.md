## 三、分步操作

### 步骤 1：req 对象——"客人说了什么"的完整档案

每一次 HTTP 请求到来时，Express 会把请求的所有信息打包成一个 `req` 对象，传给路由处理函数。`req` 包含了**客人是谁、从哪来、想要什么、带了什么**的所有信息。

#### 1.1 req.method——请求方法

```javascript
req.method  // "GET" | "POST" | "PUT" | "DELETE" | ...
```

**用途**：判断请求是哪种 HTTP 方法。虽然你通常不需要手动判断（因为路由已经按方法区分了），但在某些场景下（比如在中间件中记录日志），`req.method` 很有用。

#### 1.2 req.url——请求的完整路径

```javascript
req.url  // "/api/articles?page=1&limit=10"
```

**用途**：获取请求的完整路径（不含域名和端口）。注意——`req.url` 包含查询参数。

**比喻**：`req.url` 就是客人点菜时说的完整话："我要川菜区的宫保鸡丁，微辣，不要花生"（`/api/articles?category=tech&page=1`）。`req.path` 是去掉查询参数的部分（`/api/articles`）。

#### 1.3 req.query——查询参数

```javascript
// 访问 GET /api/articles?page=1&limit=10&category=tech
req.query  // { page: '1', limit: '10', category: 'tech' }
```

在 05 章已经详细讲过。补充一个细节：如果查询参数有重名（如 `?tag=js&tag=node`），`req.query.tag` 会是一个数组 `['js', 'node']`。

#### 1.4 req.params——路径参数

```javascript
// 路由为 /api/articles/:id，访问 /api/articles/5
req.params  // { id: '5' }
```

同样在 05 章已经详细讲过。补充：`req.params` 是一个普通对象，所有值都是字符串。

#### 1.5 req.body——请求体

```javascript
// POST /api/articles，Body: { "title": "Hello" }
req.body  // { title: 'Hello' }
```

**前提条件**：必须配置了 `express.json()` 中间件，否则 `req.body` 是 `undefined`。

#### 1.6 req.headers——请求头

```javascript
req.headers
// {
//   'content-type': 'application/json',
//   'user-agent': 'Thunder Client (https://www.thunderclient.com)',
//   'accept': '*/*',
//   'host': 'localhost:3000',
//   ...
// }
```

**用途**：获取请求附带的元信息。常用场景：
- `req.headers['content-type']`：判断请求体格式。
- `req.headers['authorization']`：获取 JWT Token（后面认证章节会用到）。
- `req.headers['user-agent']`：判断客户端类型（浏览器 / App / 测试工具）。

> 🔥 **魔鬼细节**：HTTP 头名称在 Express 中**全部转为小写**。即使客户端发的是 `Content-Type`，`req.headers['content-type']` 才能正确获取。这是 HTTP 协议的规定——头名称大小写不敏感。

#### 1.7 req.ip——客户端 IP 地址

```javascript
req.ip  // "::1"（IPv6 的 localhost）或 "127.0.0.1"（IPv4）
```

**用途**：记录请求来源、做频率限制、安全审计等。

#### 1.8 req.path——不含查询参数的路径

```javascript
// 访问 GET /api/articles?page=1
req.path  // "/api/articles"
```

**与 `req.url` 的区别**：`req.url` 包含查询参数，`req.path` 不包含。

#### req 属性速查表

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `req.method` | string | HTTP 方法 | `"GET"` |
| `req.url` | string | 完整路径（含查询参数） | `"/api/articles?page=1"` |
| `req.path` | string | 路径（不含查询参数） | `"/api/articles"` |
| `req.query` | object | 查询参数对象 | `{ page: '1' }` |
| `req.params` | object | 路径参数对象 | `{ id: '5' }` |
| `req.body` | object/undefined | 请求体（需 `express.json()`） | `{ title: 'Hello' }` |
| `req.headers` | object | 请求头 | `{ 'content-type': 'application/json' }` |
| `req.ip` | string | 客户端 IP | `"::1"` |

### 步骤 2：res 对象——"你怎么回应客人"的完整工具包

`res` 对象提供了各种方法，让你告诉 Express **怎么回应客人**。

#### 2.1 res.json()——发送 JSON 响应

```javascript
res.json({ message: 'Hello' });
```

**自动做了三件事**：
1. 把 JavaScript 对象转成 JSON 字符串（`JSON.stringify()`）
2. 设置响应头 `Content-Type: application/json`
3. 发送响应

> 这是你**最常用的方法**。API 开发中 90% 的响应都是 `res.json()`。

#### 2.2 res.status()——设置状态码

```javascript
res.status(201).json({ message: '创建成功' });
res.status(404).json({ error: '文章不存在' });
res.status(500).json({ error: '服务器内部错误' });
```

**注意**：`res.status()` **不发送响应**，它只是设置状态码，然后返回 `res` 对象本身（支持链式调用）。你必须链式调用 `.json()` 或 `.send()` 才能真正发送响应。

#### 2.3 res.send()——发送任意内容

```javascript
res.send('Hello World');          // 发送字符串
res.send('<h1>Hello</h1>');       // 发送 HTML
res.send({ message: 'Hello' });   // 发送对象（会自动转 JSON）
```

**用途**：`res.send()` 比 `res.json()` 更通用——它能发送任何类型的内容。Express 会根据你传的参数类型，自动设置 `Content-Type`。

| 你传的 | Express 自动设置 Content-Type |
|--------|------------------------------|
| 字符串 | `text/html` |
| Buffer | `application/octet-stream` |
| 对象/数组 | `application/json` |

> 虽然 `res.send()` 能处理对象，但**推荐用 `res.json()` 发送 JSON 数据**——语义更明确，代码可读性更好。

#### 2.4 res.setHeader()——设置响应头

```javascript
res.setHeader('X-Custom-Header', 'my-value');
res.setHeader('Cache-Control', 'no-cache');
```

**用途**：设置自定义响应头。通常不需要手动设置 `Content-Type`——`res.json()` 和 `res.send()` 会自动处理。

#### 2.5 res.redirect()——重定向

```javascript
res.redirect('/new-page');                // 相对路径
res.redirect('https://www.example.com');  // 绝对 URL
res.redirect(301, '/new-page');           // 指定状态码（永久重定向）
```

**用途**：让浏览器跳转到另一个 URL。默认状态码是 302（临时重定向）。

#### 2.6 res.status(code) 常用状态码

| 状态码 | 场景 | 代码示例 |
|--------|------|----------|
| 200 | 请求成功 | `res.status(200).json(data)` |
| 201 | 资源创建成功 | `res.status(201).json(newArticle)` |
| 204 | 成功但无内容（如删除成功） | `res.status(204).send()` |
| 400 | 请求参数错误 | `res.status(400).json({ error: '缺少必填字段' })` |
| 404 | 资源不存在 | `res.status(404).json({ error: '文章不存在' })` |
| 500 | 服务器内部错误 | `res.status(500).json({ error: '服务器错误' })` |

### 步骤 3：链式调用——`res.status(201).json({...})` 的原理

你可能会好奇：为什么能写成 `res.status(201).json({...})` 而不是：

```javascript
res.status(201);
res.json({...});
```

**答案**：`res.status()` 返回的是 `res` 对象本身。这就是**链式调用**（Method Chaining）——每个方法都返回 `this`（即 `res`），所以你可以连续调用。

```javascript
// 这三行是等价的：
res.status(201).json({ message: '创建成功' });

// 等价于：
res.status(201);
res.json({ message: '创建成功' });

// 也等价于（但不推荐，看得眼花）：
res.status(201).setHeader('X-Custom', 'value').json({ message: 'OK' });
```

**比喻**：链式调用就像你在餐厅里跟服务员连续说三句话——"靠窗的位置（status(201)），给我菜单（这是一个中间状态），来一份宫保鸡丁（json(...)）"。你不需要等服务员回应每一句，因为你最终要的是那盘菜（响应）。

> 🔥 **魔鬼细节**：`res.status()` 只是设置状态码，**不发送响应**。必须链式调用 `.json()` 或 `.send()` 才能真正把响应发出去。如果你只写了 `res.status(201)` 而没有 `.json()`，浏览器会一直等——直到超时。

### 步骤 4：Echo 接口实战——返回你发的所有东西

现在我们来写一个完整的 Echo 接口。Echo 的意思是"回声"——你发什么，它就返回什么。这个接口能帮你一次性验证 `req` 的所有属性。

#### 4.1 修改 `POST /api/echo` 路由

在 `server.js` 中，把之前的 Echo 接口改成完整版：

```javascript
// POST /api/echo — 返回请求的所有信息
app.post('/api/echo', (req, res) => {
    res.json({
        method: req.method,
        url: req.url,
        path: req.path,
        headers: req.headers,
        query: req.query,
        body: req.body,
        ip: req.ip,
        timestamp: new Date().toISOString()
    });
});
```

#### 4.2 测试

用 Thunder Client 发 `POST http://localhost:3000/api/echo?source=test`：

- **方法**：POST
- **URL**：`http://localhost:3000/api/echo?source=test`
- **Body** 标签 → JSON：

```json
{
    "name": "张三",
    "message": "Hello Echo!"
}
```

- **Headers** 标签 → 添加一个自定义头：`X-Custom-Header: my-secret-value`

发送后，你应该看到类似这样的响应：

```json
{
    "method": "POST",
    "url": "/api/echo?source=test",
    "path": "/api/echo",
    "headers": {
        "content-type": "application/json",
        "x-custom-header": "my-secret-value",
        "user-agent": "Thunder Client (...)",
        "host": "localhost:3000",
        ...
    },
    "query": {
        "source": "test"
    },
    "body": {
        "name": "张三",
        "message": "Hello Echo!"
    },
    "ip": "::1",
    "timestamp": "2026-06-12T10:30:00.000Z"
}
```

> 这个 Echo 接口是一个极好的调试工具。以后遇到"请求到底有没有传这个参数？"的问题时，发一个 Echo 请求，一目了然。

### 步骤 5：请求体大小限制——防止恶意大请求

你现在的 `express.json()` 没有限制请求体大小。如果有人故意发一个 1GB 的 JSON 请求，你的服务器内存会被撑爆。

**设置方法**：

```javascript
// 限制 JSON 请求体最大 1MB
app.use(express.json({ limit: '1mb' }));

// 限制表单数据最大 1MB
app.use(express.urlencoded({ extended: true, limit: '1mb' }));
```

> `limit` 的值可以用字节数（`1048576`）或带单位的字符串（`'1mb'`、`'100kb'`、`'10mb'`）。Express 使用 `bytes` 库解析这些字符串。

**如果请求体超过限制会怎样？** Express 会返回 413（Payload Too Large），并且错误会被全局错误处理中间件捕获。你不需要额外处理。

> 🔥 **魔鬼细节**：`limit` 的默认值是 `'100kb'`。对于博客文章这种场景，正文可能超过 100KB——所以建议设置为 `'1mb'` 或 `'5mb'`。**不要设为 `'100mb'` 或更大**——那就失去了限制的意义。

### 🤔 想多一点：响应只能发一次——`ERR_HTTP_HEADERS_SENT`

这是一个经典的 Express 错误。来看一个例子：

```javascript
app.get('/api/bad', (req, res) => {
    res.json({ message: '第一次响应' });
    res.json({ message: '第二次响应' });  // ❌ 报错！
});
```

**错误信息**：

```
Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client
```

**为什么？** HTTP 协议中，一个请求只能有一个响应。就像你点了一份宫保鸡丁，服务员端上来之后，不能再端一盘麻婆豆腐给你——这一单已经结束了。

**Express 内部的保护机制**：第一次调用 `res.json()` 后，Express 会把响应头发送出去，然后标记 `res.headersSent = true`。第二次调用 `res.json()` 时，Express 发现 `headersSent` 已经是 `true`，就抛出错误。

**常见场景**：你在路由处理函数中不小心写了两个 `res.json()`，或者先 `res.json()` 又调了 `next()`（导致后面的中间件也尝试发响应）。

```javascript
// ❌ 错误——响应后还调了 next()
app.use((req, res, next) => {
    res.json({ message: '我发了响应' });
    next(); // 这会导致后面的中间件也尝试发响应
});

// ✅ 正确——响应后 return，不调 next()
app.use((req, res, next) => {
    if (condition) {
        return res.json({ message: '提前返回' });
    }
    next();
});
```

---

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| `req.body` 是 `undefined` | 没配 `express.json()` 或放在了路由后面 | 确保 `app.use(express.json())` 在路由之前 |
| `req.headers['content-type']` 是 `undefined` | 用了大写 `Content-Type` | HTTP 头在 Express 中全部转为小写，用 `req.headers['content-type']` |
| `ERR_HTTP_HEADERS_SENT` | 尝试发送两次响应 | 检查代码中是否多次调了 `res.json()` 或 `res.send()`；响应后不要调 `next()` |
| `res.status(404)` 后浏览器一直转圈 | 只设置了状态码，没发响应 | 需要链式调用：`res.status(404).json({ error: '...' })` |
| 413 Payload Too Large | 请求体超过 `express.json()` 的 `limit` 限制 | 增大限制：`express.json({ limit: '5mb' })` |
| `req.query` 的值是 `undefined` | URL 中没有写查询参数，或参数名写错了 | 检查 URL 中 `?` 后面的键名是否与代码中一致 |

| 响应头（Headers） | Response Headers | 响应附带的元信息，告诉客户端"我返回的是什么格式"、"数据有多大"、"缓存策略"等。 | 步骤 2.4 | 不是"响应的开头"——是附加在响应数据外面的一层说明信息。 |
| Content-Type | — | 响应头中的一个字段，告诉客户端"我返回的数据是什么格式"（`application/json`、`text/html` 等）。 | 步骤 3 | 历史名词，源自 MIME（Multipurpose Internet Mail Extensions），比 HTTP 还古老。 |
| 413 Payload Too Large | — | HTTP 状态码，表示请求体超过了服务器允许的大小限制。 | 步骤 5 | "Payload"不是"工资"——在网络中，Payload 指"传输的有效数据"。 |

---

## 八、已知坑点与禁止事项

1. **`req.headers` 的键名全部是小写**：无论客户端发送什么大小写的头（`Content-Type`、`CONTENT-TYPE`、`content-type`），Express 都转为小写。所以必须用 `req.headers['content-type']`，不能写 `req.headers['Content-Type']`。

2. **`res.status()` 不发送响应**：它只是设置状态码，必须链式调用 `.json()` 或 `.send()`。如果只写了 `res.status(404)` 而没有后续调用，浏览器会一直等到超时。

3. **响应只能发一次，第二次会报错**：`res.json()` 或 `res.send()` 只能调用一次。如果路由中多次调用，或者响应后又调了 `next()`，会报 `ERR_HTTP_HEADERS_SENT`。

4. **`res.json()` 会自动设置 Content-Type**：不需要手动 `res.setHeader('Content-Type', 'application/json')`。`res.json()` 已经帮你做了。

5. **`express.json()` 的 `limit` 默认只有 100KB**：对于博客文章内容可能不够。建议显式设置 `express.json({ limit: '1mb' })`。

6. **`req.query` 和 `req.params` 的值都是字符串**：这是 05 章已经强调过的，但在这里再强调一次——因为它们太容易忘了。
