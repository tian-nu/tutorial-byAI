# Ch31 · Positional Encoding 给序列加位置感

> 所属篇：第五篇 · 预计耗时：25 分钟

Self-Attention 有个致命问题：它把"猫追老鼠"和"老鼠追猫"看成**完全一样**的输入——因为 Self-Attention 对输入顺序是"置换不变"的，谁先谁后对它没区别。但语言里顺序决定意义："我打你"和"你打我"意思完全相反。怎么办？2017 年 Transformer 论文用了一个简单优雅的招：**给每个位置加一个独特的"位置编号牌"**，让模型知道谁在前谁在后。这就是 Positional Encoding（位置编码），本章把正弦编码公式彻底拆开，并手算前几个位置的编码。

---

## 为了什么（Why）

**核心痛点**：Self-Attention 对输入顺序完全不变（**置换不变性**，Permutation Invariance）。无论你把序列怎么打乱，输出只是行对应打乱，不会"感知"到顺序。

**举个反例**：没有位置编码的 Transformer 处理"我打你"和"你打我"——
- "我打你"输入 `X = [[v_我], [v_打], [v_你]]`
- "你打我"输入 `X' = [[v_你], [v_打], [v_我]]`

由于 Self-Attention 是 `softmax(QK^T/√d_k)·V`，把行顺序换一下，输出也只是行顺序跟着换，**模型完全感知不到顺序错乱**。所以"我打你"和"你打我"在模型眼里是同一种结构——这显然不对。

**Positional Encoding 的解法**：给每个位置 `pos` 加一个独特的"位置编码向量"`PE(pos)`，让最终输入变成 `X' = X + PE`。这样不同位置的同一个词会有不同的最终表示，模型就能感知顺序。

**这一章的目标**：理解正弦位置编码公式，能手算 `d_model=4, pos=0,1,2` 的前几个位置编码，能解释为什么低维变化快、高维变化慢。

## 要做到（Goal）

- **输入**：Ch29 的 Self-Attention、知道 sin/cos 函数。
- **输出**：理解正弦位置编码公式，能手算前几个位置的编码值。
- **成功标准**：给定 `pos=1, d_model=4`，能算出 `PE(1) = [0.841, 0.540, 0.01, 1.0]`。

## 做了什么（What）

Positional Encoding 的核心思想：**给每个位置生成一个独特的向量，加到该位置的词嵌入上**。

```
输入序列 X：
   x_0       x_1       x_2
   │         │         │
   ▼         ▼         ▼
  +PE(0)    +PE(1)    +PE(2)    ← 每个位置加自己的位置编码
   │         │         │
   ▼         ▼         ▼
  x'_0      x'_1      x'_2      ← 最终输入 = X + PE
```

位置编码主要有三种实现方式：

1. **正弦编码（Sinusoidal PE）**：原始 Transformer 用。用 sin/cos 不同频率生成，**无参数、可外推**到训练时没见过的长度。
2. **学习式编码（Learned PE）**：BERT 用。把位置当成可训练参数 `nn.Embedding(max_len, d_model)`，**可学习但不能外推**。
3. **相对位置编码（Relative PE）**：T5 用。编码相对距离而非绝对位置，**适合翻译**但实现复杂。

本章重点讲**正弦编码**——原始 Transformer 论文的方案。

### 正弦编码公式

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

其中：
- `pos`：位置（0, 1, 2, ...）
- `i`：维度索引（0, 1, 2, ..., d_model/2 - 1）
- `2i` 和 `2i+1` 是一对（偶数维用 sin，奇数维用 cos）
- `10000` 是个常数，控制最高频率和最低频率的比例

## 怎么算（How）

### 数值小例子（d_model=4，前 3 个位置）

`d_model=4`，所以 `i` 取 0 和 1（`2i` 取 0 和 2）。先算两个频率：

- `i=0`：除数 `= 10000^(0/4) = 10000^0 = 1`，频率 `= 1/1 = 1`（最高频）
- `i=1`：除数 `= 10000^(2/4) = 10000^0.5 = 100`，频率 `= 1/100 = 0.01`（最低频）

注意：**i 小对应低维（前几维），频率高，变化快；i 大对应高维（后几维），频率低，变化慢。**

**pos=0**：
- `PE(0, 0) = sin(0/1) = sin(0) = 0`
- `PE(0, 1) = cos(0/1) = cos(0) = 1`
- `PE(0, 2) = sin(0/100) = sin(0) = 0`
- `PE(0, 3) = cos(0/100) = cos(0) = 1`

```
PE(0) = [0, 1, 0, 1]
```

**pos=1**：
- `PE(1, 0) = sin(1/1) = sin(1) = 0.841`
- `PE(1, 1) = cos(1/1) = cos(1) = 0.540`
- `PE(1, 2) = sin(1/100) = sin(0.01) ≈ 0.010`
- `PE(1, 3) = cos(1/100) = cos(0.01) ≈ 1.000`

```
PE(1) = [0.841, 0.540, 0.010, 1.000]
```

**pos=2**：
- `PE(2, 0) = sin(2/1) = sin(2) = 0.909`
- `PE(2, 1) = cos(2/1) = cos(2) = -0.416`
- `PE(2, 2) = sin(2/100) = sin(0.02) ≈ 0.020`
- `PE(2, 3) = cos(2/100) = cos(0.02) ≈ 1.000`

```
PE(2) = [0.909, -0.416, 0.020, 1.000]
```

### 关键观察：低维变化快，高维变化慢

把三个位置的编码列在一起对比：

| 维度 | pos=0 | pos=1 | pos=2 | 变化幅度 | 频率 |
|------|-------|-------|-------|---------|------|
| 0 (sin, i=0) | 0 | 0.841 | 0.909 | 0.909 | 高（频率=1）|
| 1 (cos, i=0) | 1 | 0.540 | -0.416 | 1.416 | 高（频率=1）|
| 2 (sin, i=1) | 0 | 0.010 | 0.020 | 0.020 | 低（频率=0.01）|
| 3 (cos, i=1) | 1 | 1.000 | 1.000 | 0.000 | 低（频率=0.01）|

**前 2 维（i=0，频率 1）**：从 pos=0 到 pos=2 剧烈变化，sin 从 0 跳到 0.909，cos 从 1 跌到 -0.416。
**后 2 维（i=1，频率 0.01）**：从 pos=0 到 pos=2 几乎没变，sin 始终接近 0，cos 始终接近 1。

### 为什么低维变化快（高频），高维变化慢（低频）？

这是位置编码最容易让人困惑的点。答案藏在公式里的除数 `10000^(2i/d_model)` 上：

- **低维（i 小）**：除数 `10000^(2i/d_model)` 小。`i=0` 时除数 = 1，频率 = 1/1 = 1。频率高，所以 sin/cos 在 pos 变化时跑得快——就像秒针，pos 走 1 步它就跑了一圈。
- **高维（i 大）**：除数 `10000^(2i/d_model)` 大。`i=d_model/2-1` 时除数接近 10000，频率 = 1/10000。频率低，所以 sin/cos 在 pos 变化时几乎不动——就像时针，pos 走 1 步它几乎没动。

打个**钟表比喻**：PE 就像一个多指针的钟表。
- 第 0,1 维是秒针（频率最高）——pos 变 1 它就动一格
- 中间几维是分针——pos 变几十它才动一格
- 最后两维是时针（频率最低）——pos 变几千它才动一格

不同频率的"指针"组合起来，能**唯一表示任意位置**——就像年月日时分秒组合能定位任意时刻。哪怕序列长度从 100 扩到 1000，高频维度负责区分相邻位置，低频维度负责区分远距离段落，整体仍然能保持区分度。这就是正弦编码"可外推到训练时没见过的长度"的根本原因。

### 为什么用 sin/cos 而不是直接用 1, 2, 3...？

如果直接把位置编号加到嵌入上（`X + pos`）会有三个问题：

1. **数值无界**：`pos=1000` 时位置编码 = 1000，远大于嵌入值（通常 |x| < 10），会把嵌入淹没。
2. **不能外推**：训练时只见过 `pos < 100`，推理时遇到 `pos=200` 模型完全没见过这个数。
3. **没有相对关系**：绝对位置 `pos=5` 和 `pos=10` 的关系（差 5）无法从数字本身看出来。

sin/cos 解决了这三个问题：
1. **有界**：sin/cos 输出始终在 `[-1, 1]`，不会淹没嵌入。
2. **可外推**：sin/cos 是周期函数，超出训练范围的位置仍然能用已有频率组合表示。
3. **相对关系**：根据三角恒等式 `sin(a+b) = sin(a)cos(b) + cos(a)sin(b)`，`PE(pos+k)` 可以表示为 `PE(pos)` 的线性变换。这意味着"位置 pos+k"和"位置 pos"的关系，可以通过一个固定的线性变换表达——这对模型学习相对位置关系非常有利。

## 怎么用（Use）

代码文件：`深度学习从0到Transformer教程/code/ch31_positional_encoding.py`

关键片段：

```python
import numpy as np

def positional_encoding(T, d_model):
    """生成 (T, d_model) 的正弦位置编码矩阵。"""
    pe = np.zeros((T, d_model))
    pos = np.arange(T)[:, None]                    # (T, 1)
    # div_term[i] = 10000^(2i/d_model)，用 exp+log 避免数值溢出
    div = np.exp(np.arange(0, d_model, 2) * (-np.log(10000) / d_model))
    pe[:, 0::2] = np.sin(pos * div)                # 偶数维 sin
    pe[:, 1::2] = np.cos(pos * div)                # 奇数维 cos
    return pe

pe = positional_encoding(10, 64)
print(pe[1, :4])  # [0.841, 0.540, 0.010, 1.000]
```

## 想多一点

> 为什么位置编码是"相加"而不是"相乘"或"拼接"？
>
> 答案是：**相加是最简洁的方案**，且在数学上等价于"在嵌入空间里多加一个维度"。
> - 相乘 `X * PE` 会破坏嵌入的语义（让数值不稳定，且 PE=0 的位置会把整个嵌入清零）。
> - 拼接 `concat(X, PE)` 会把维度从 `d_model` 变成 `2·d_model`，破坏后续网络结构。
> - 相加 `X + PE` 维度不变，且 sin/cos 的值域 `[-1, 1]` 与典型嵌入值域 `[-1, 1]` 量级匹配，不会淹没嵌入。
>
> 另外，原始 Transformer 论文做过实验：相加和拼接效果差不多，但相加更省参数。后来的研究还证明，相加位置编码等价于在频率域里把位置信息"调制"到嵌入上，这与傅立叶变换的思想一致。

## 易错点预警

- ❌ 位置编码与输入**相乘**而非相加 → ✅ 正确：`X' = X + PE`，是相加。相乘会破坏嵌入语义。
- ❌ 忘记 2i 和 2i+1 的奇偶区分 → ✅ 正确：**偶数维（0,2,4,...）用 sin**，**奇数维（1,3,5,...）用 cos**。代码里用 `pe[:, 0::2] = sin(...)` 和 `pe[:, 1::2] = cos(...)` 实现。
- ❌ 用 `10000**(2i/d_model)` 直接算除数导致数值溢出 → ✅ 正确：用等价的 `np.exp(np.arange(0, d_model, 2) * (-np.log(10000) / d_model))` 计算，更稳定。
- ❌ 把 PE 当成可学习参数（实际想要正弦编码） → ✅ 正确：正弦 PE 是**固定**的，不参与训练。如果要可学习就用 `nn.Embedding`，那是另一种方案。
- ❌ 把"低维高频"和"高维高频"搞反 → ✅ 正确：**低维（i 小）对应高频率，变化快**；**高维（i 大）对应低频率，变化慢**。从公式 `10000^(2i/d_model)` 看，i 小则除数小，频率 `1/除数` 大，所以变化快。

## 章末小结

| 编码方式 | 公式 | 优势 | 劣势 | 适用场景 |
|---------|------|------|------|---------|
| 正弦编码 | `sin(pos/10000^(2i/d))` / `cos(...)` | 无参数、可外推、有相对位置关系 | 无法学习适应任务 | 原始 Transformer |
| 学习式编码 | `nn.Embedding(max_len, d_model)` | 可学习、能适应任务 | 不能外推到训练时没见过的长度 | BERT、GPT |
| 相对位置编码 | 基于距离 `pos_q - pos_k` | 直接编码相对关系，适合翻译 | 实现复杂 | T5、Transformer-XL |
