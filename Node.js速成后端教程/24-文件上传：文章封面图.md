# 24-文件上传：文章封面图

> "你的文章写得再好，没有封面图就像一本没有封面的书——没人想翻开。但文件上传又是一个'坑中坑'的功能：文件类型不对怎么办？文件太大怎么办？文件名冲突怎么办？恶意文件怎么办？生产环境怎么存？本章用 `multer` 一次性解决所有问题，让你不仅能上传图片，还能说出每一个安全措施背后的原因。"

---

## 一、目标与完成效果

**一句话目标**：使用 `multer` 中间件实现图片上传功能，配置存储路径、文件名校验、类型白名单、大小限制，将上传的图片通过 `express.static` 对外提供访问，并将封面图关联到文章的创建和更新接口。

**完成后的可观测效果**：
- `POST /api/upload` — 上传一张图片（需登录），返回图片 URL，图片保存到 `uploads/` 目录。
- `GET /uploads/<文件名>` — 浏览器能直接访问上传的图片（通过 `express.static`）。
- `POST /api/articles` — 创建文章时可传入 `cover_image` 字段关联封面图。
- `PUT /api/articles/:id` — 更新文章时可修改封面图。
- 上传非图片文件（如 `.exe`）→ 被 `fileFilter` 拦截，返回 400。
- 上传超过 5MB 的图片 → 被 `limits.fileSize` 拦截，返回 413。
- `uploads/` 目录被加入 `.gitignore`，不会提交到 Git。

## 三、分步操作

### 步骤 1：安装 `multer`

```bash
npm install multer
```

**`multer` 是什么？**

`multer` 是 Express 的一个中间件，专门处理 `multipart/form-data` 格式的请求——也就是**文件上传**。普通的 `express.json()` 和 `express.urlencoded()` 只能处理文本数据，无法处理二进制文件。

| 中间件 | 处理的数据格式 | 用途 |
|--------|--------------|------|
| `express.json()` | `application/json` | 处理 JSON 请求体（如 `{"title": "xxx"}`） |
| `express.urlencoded()` | `application/x-www-form-urlencoded` | 处理 HTML 表单提交 |
| `multer` | `multipart/form-data` | 处理文件上传 |

> 餐厅比喻：`express.json()` 是服务员记录客人点的菜名（文本），`multer` 是服务员拍下客人画的菜样（图片）。

### 步骤 2：创建 `middleware/upload.js`——配置 multer

在 `blog-backend/middleware/` 下新建 `upload.js`：

```javascript
const multer = require('multer');
const path = require('path');
const crypto = require('crypto');

// ========== 1. 配置存储位置和文件名 ==========
const storage = multer.diskStorage({
    // 存储目录
    destination: function (req, file, cb) {
        cb(null, 'uploads/');
    },
    // 文件名规则
    filename: function (req, file, cb) {
        // 生成唯一文件名：时间戳 + UUID + 原始扩展名
        const uniqueSuffix = Date.now() + '-' + crypto.randomUUID();
        const ext = path.extname(file.originalname);
        cb(null, uniqueSuffix + ext);
    }
});

// ========== 2. 文件类型过滤器（白名单） ==========
const fileFilter = (req, file, cb) => {
    // 只允许图片类型
    const allowedTypes = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];

    if (allowedTypes.includes(file.mimetype)) {
        cb(null, true);   // 接受文件
    } else {
        cb(new Error('只允许上传 JPG、PNG、GIF、WebP 格式的图片'), false);  // 拒绝文件
    }
};

// ========== 3. 创建 multer 实例 ==========
const upload = multer({
    storage: storage,
    fileFilter: fileFilter,
    limits: {
        fileSize: 5 * 1024 * 1024   // 限制 5MB
    }
});

module.exports = upload;
```

**关键点解析**：

| 配置项 | 在做什么 | 为什么 |
|--------|----------|--------|
| `diskStorage` | 告诉 multer 把文件存到硬盘上 | 另一种是 `memoryStorage`（存内存），适用于小文件或需要立即处理的情况 |
| `destination: 'uploads/'` | 存储目录 | 相对于 `process.cwd()`（项目根目录），文件存到 `blog-backend/uploads/` |
| `filename: Date.now() + '-' + crypto.randomUUID() + ext` | 生成唯一文件名 | 防止两个用户上传同名文件互相覆盖；防止通过文件名猜测其他文件 |
| `fileFilter` | 白名单检查 `file.mimetype` | 只允许图片类型，防止上传恶意文件（如 `.exe`、`.php`） |
| `limits.fileSize: 5MB` | 文件大小限制 | 防止用户上传超大文件撑爆服务器磁盘 |

> 🔥 **魔鬼细节**：`multer` 默认**没有文件大小限制**。如果不设置 `limits.fileSize`，用户可以上传任意大小的文件——包括 10GB 的视频。这是最常见的安全漏洞之一。**永远要设置 `limits.fileSize`。**

### 步骤 3：创建 `routes/upload.js`

在 `blog-backend/routes/` 下新建 `upload.js`：

```javascript
const express = require('express');
const router = express.Router();
const upload = require('../middleware/upload');
const { authenticate } = require('../middleware/auth');
const AppError = require('../utils/AppError');

// ========== 文件上传接口 ==========

// POST /api/upload — 上传单张图片（需登录）
router.post('/upload', authenticate, (req, res, next) => {
    // 使用 multer 中间件处理上传
    upload.single('image')(req, res, function (err) {
        // multer 的错误处理
        if (err) {
            if (err.code === 'LIMIT_FILE_SIZE') {
                return next(new AppError('文件大小不能超过 5MB', 413));
            }
            if (err.message.includes('只允许上传')) {
                return next(new AppError(err.message, 400));
            }
            return next(new AppError('文件上传失败', 500));
        }

        // 没有上传文件
        if (!req.file) {
            return next(new AppError('请选择要上传的图片', 400));
        }

        // 返回图片 URL
        const imageUrl = `/uploads/${req.file.filename}`;

        res.status(201).json({
            success: true,
            data: {
                url: imageUrl,
                filename: req.file.filename,
                size: req.file.size,
                mimetype: req.file.mimetype
            }
        });
    });
});

module.exports = router;
```

**关键点解析**：

| 步骤 | 在做什么 | 为什么 |
|------|----------|--------|
| `upload.single('image')` | 接收**单个**文件，表单字段名为 `image` | 如果前端传的是 `file` 字段，这里要改成 `upload.single('file')` |
| `err.code === 'LIMIT_FILE_SIZE'` | 文件超大时的特殊错误 | multer 在文件超限时会抛出 `LIMIT_FILE_SIZE` 错误码，单独处理返回 413 |
| `!req.file` | 用户没上传文件 | `req.file` 是 multer 挂到请求对象上的文件信息 |
| `req.file.filename` | multer 生成的文件名 | 就是 `Date.now() + '-' + crypto.randomUUID() + ext` |
| `req.file.size` | 文件大小（字节） | 可以用来在前端显示文件大小 |
| 返回 201 | 创建了新资源（图片文件） | 和创建文章、评论一样，用 201 Created |

> 🔥 **魔鬼细节**：`upload.single('image')` 中的 `'image'` 是**表单字段名**，不是文件属性。前端上传时，请求体中的字段名必须是 `image`（Thunder Client 中 Body → Form-encode → 添加字段，字段名填 `image`，类型选 `File`）。如果前后端字段名不一致，`req.file` 会是 `undefined`。

### 步骤 4：配置静态文件服务

打开 `server.js`，确认静态文件服务已配置：

```javascript
const path = require('path');

// 静态文件服务：让浏览器能直接访问 uploads/ 目录中的文件
app.use('/uploads', express.static(path.join(__dirname, 'uploads')));
```

**`express.static` 是什么？**

`express.static` 是 Express 内置的静态文件服务中间件。它把服务器上的一个文件夹"映射"到一个 URL 路径上：

```
浏览器访问: http://localhost:3000/uploads/abc.jpg
          ↓
服务器返回: blog-backend/uploads/abc.jpg 文件的内容
```

**`path.join(__dirname, 'uploads')` 为什么不是 `'uploads'`？**

- `express.static('uploads')` 是相对于 `process.cwd()`（运行 `node` 命令时所在的目录）。
- 如果你在 `blog-backend/` 下运行 `node server.js`，`process.cwd()` 就是 `blog-backend/`，`'uploads'` 正确。
- 但如果你在别的目录运行（如 `cd .. && node blog-backend/server.js`），`process.cwd()` 就变了，`'uploads'` 找不到。
- `path.join(__dirname, 'uploads')` 是相对于**当前文件（server.js）所在的目录**——无论你在哪里运行命令，都能正确找到 `uploads/`。

> 🔥 **魔鬼细节**：`express.static` 会把文件夹中的文件**公开暴露**——任何人都可以用浏览器访问。所以 `uploads/` 目录中只能放公开文件（如图片），**绝对不能放配置文件、数据库文件、密钥等敏感内容**。

### 步骤 6：在文章创建/更新接口中关联封面图

#### 6.1 给 `articles` 表新增 `cover_image` 字段

打开 `database/schema.js`，在 `articles` 表的建表语句中添加 `cover_image` 字段：

```sql
CREATE TABLE IF NOT EXISTS articles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    author_id INTEGER NOT NULL,
    cover_image TEXT,             -- ← 新增：封面图路径（可为 NULL）
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (author_id) REFERENCES users(id)
);
```

如果数据库已经存在，需要用 `ALTER TABLE` 添加字段：

```javascript
// 在 database/schema.js 的 initializeSchema 函数中添加
db.exec(`
    ALTER TABLE articles ADD COLUMN cover_image TEXT;
`);
```

或者更安全的方式——先检查字段是否存在：

```javascript
// 检查 cover_image 列是否存在，不存在则添加
const hasColumn = db.prepare("PRAGMA table_info(articles)").all()
    .some(col => col.name === 'cover_image');

if (!hasColumn) {
    db.exec('ALTER TABLE articles ADD COLUMN cover_image TEXT');
    console.log('✅ articles 表已添加 cover_image 字段');
}
```

> 🔥 **魔鬼细节**：SQLite 的 `ALTER TABLE` 只支持有限的操作（`ADD COLUMN`、`RENAME TABLE`、`RENAME COLUMN`）。如果字段已经存在，再次执行 `ALTER TABLE ADD COLUMN` 会报错 `duplicate column name`。所以必须先检查字段是否存在。

#### 6.2 修改 `POST /api/articles`——接收 `cover_image`

```javascript
// POST /api/articles — 创建文章（需登录）
router.post('/', authenticate, (req, res) => {
    const { title, content, cover_image } = req.body;  // ← 新增 cover_image

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const author_id = req.user.id;
    const now = new Date().toISOString();

    const insertArticle = db.prepare(`
        INSERT INTO articles (title, content, author_id, cover_image, created_at, updated_at)
        VALUES (?, ?, ?, ?, ?, ?)
    `);

    const result = insertArticle.run(
        title,
        content,
        author_id,
        cover_image || null,  // ← 没有封面图时为 null
        now,
        now
    );

    const newArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(result.lastInsertRowid);

    res.status(201).json({
        success: true,
        data: newArticle
    });
});
```

#### 6.3 修改 `PUT /api/articles/:id`——接收 `cover_image`

```javascript
// PUT /api/articles/:id — 更新文章（只能改自己的）
router.put('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const { title, content, cover_image } = req.body;  // ← 新增 cover_image
    const userId = req.user.id;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }
    if (article.author_id !== userId) {
        throw new AppError('只能修改自己的文章', 403);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, cover_image = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(
        title,
        content,
        cover_image !== undefined ? cover_image : article.cover_image,  // ← 没传则保留原值
        now,
        id
    );

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});
```

> 🔥 **魔鬼细节**：`cover_image !== undefined ? cover_image : article.cover_image` —— 如果用户传了 `cover_image`（即使是空字符串 `""`），就用新值；如果没传（`undefined`），就保留原有封面图。这避免了"更新标题时不小心把封面图清空"的问题。

### 🤔 想多一点：生产环境为什么不用本地存储？

本教程用本地磁盘存储（`uploads/` 目录），但生产环境几乎不会这样做：

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 本地磁盘（本教程） | 简单，零配置 | 多服务器无法共享；磁盘满了影响服务；备份困难 | 学习、原型、单机小项目 |
| 对象存储（OSS/S3） | 无限容量；CDN 加速；多服务器共享 | 需要配置；有费用 | 生产环境首选 |
| 存数据库（BLOB） | 数据统一管理 | 数据库膨胀；查询变慢；备份巨大 | 几乎不推荐 |

> 如果你以后要把项目部署到云端，把 `multer` 的 `storage` 换成 `multer-s3`（AWS S3）或 `multer-aliyun-oss`（阿里云 OSS）即可——接口代码完全不用改，因为 `routes/upload.js` 不关心文件最终存在哪里。

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| `req.file` 为 `undefined` | 表单字段名不匹配 | Thunder Client 中字段名必须是 `image`（与 `upload.single('image')` 一致） |
| `Error: ENOENT: no such file or directory, open 'uploads/xxx.jpg'` | `uploads/` 目录不存在 | 手动创建 `mkdir uploads`，或在 `server.js` 启动时自动创建 |
| 上传成功但浏览器访问 404 | `express.static` 未配置或路径不对 | 确认 `app.use('/uploads', express.static(path.join(__dirname, 'uploads')))` 在 `server.js` 中 |
| `LIMIT_FILE_SIZE` 错误但没返回 413 | `upload.js` 中 `multer` 错误处理不完整 | 在 `upload.single()` 的回调中检查 `err.code === 'LIMIT_FILE_SIZE'` 并返回 413 |
| 上传非图片文件没被拦截 | `fileFilter` 没生效或 `mimetype` 判断错误 | 检查 `fileFilter` 中 `allowedTypes` 是否包含正确的 MIME 类型 |
| `ALTER TABLE ADD COLUMN` 报错 `duplicate column name` | 字段已存在 | 先检查字段是否存在：`PRAGMA table_info(articles)` |
| 创建文章时 `cover_image` 为 `null` 但预期是路径 | 请求体中没传 `cover_image` 或字段名写错了 | 确认 JSON 中有 `"cover_image": "/uploads/xxx.jpg"` |
| 更新文章时 `cover_image` 被清空 | 更新时没传 `cover_image`，代码用 `undefined` 覆盖了原值 | 用 `cover_image !== undefined ? cover_image : article.cover_image` 保留原值 |

### `blog-backend/middleware/upload.js`（本章新建）

```javascript
const multer = require('multer');
const path = require('path');
const crypto = require('crypto');

// 配置存储位置和文件名
const storage = multer.diskStorage({
    destination: function (req, file, cb) {
        cb(null, 'uploads/');
    },
    filename: function (req, file, cb) {
        const uniqueSuffix = Date.now() + '-' + crypto.randomUUID();
        const ext = path.extname(file.originalname);
        cb(null, uniqueSuffix + ext);
    }
});

// 文件类型过滤器（白名单）
const fileFilter = (req, file, cb) => {
    const allowedTypes = ['image/jpeg', 'image/png', 'image/gif', 'image/webp'];

    if (allowedTypes.includes(file.mimetype)) {
        cb(null, true);
    } else {
        cb(new Error('只允许上传 JPG、PNG、GIF、WebP 格式的图片'), false);
    }
};

// 创建 multer 实例
const upload = multer({
    storage: storage,
    fileFilter: fileFilter,
    limits: {
        fileSize: 5 * 1024 * 1024   // 5MB
    }
});

module.exports = upload;
```

```javascript
const express = require('express');
const router = express.Router();
const upload = require('../middleware/upload');
const { authenticate } = require('../middleware/auth');

    upload.single('image')(req, res, function (err) {
        if (err) {
            if (err.code === 'LIMIT_FILE_SIZE') {
                return next(new AppError('文件大小不能超过 5MB', 413));
            }
            if (err.message.includes('只允许上传')) {
                return next(new AppError(err.message, 400));
            }
            return next(new AppError('文件上传失败', 500));
        }

        if (!req.file) {
            return next(new AppError('请选择要上传的图片', 400));
        }

        const imageUrl = `/uploads/${req.file.filename}`;

        res.status(201).json({
            success: true,
            data: {
                url: imageUrl,
                filename: req.file.filename,
                size: req.file.size,
                mimetype: req.file.mimetype
            }
        });
    });
});
```

### `blog-backend/routes/articles.js`（本章修改：添加 `cover_image` 支持）

```javascript
const express = require('express');
const router = express.Router();
const { db } = require('../database/db');
const { authenticate } = require('../middleware/auth');
const AppError = require('../utils/AppError');

// ========== 文章 CRUD 接口（数据库版） ==========

// GET /api/articles — 获取所有文章（支持分页 + 搜索 + 封面图 + 评论数）
router.get('/', (req, res) => {
    let page = parseInt(req.query.page) || 1;
    let limit = parseInt(req.query.limit) || 10;
    const search = req.query.search ? req.query.search.trim() : '';

    if (page < 1) page = 1;
    if (limit < 1) limit = 1;
    if (limit > 100) limit = 100;

    const offset = (page - 1) * limit;

    const baseFrom = `
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
    `;

    let searchCondition = '';
    const params = [];

    if (search) {
        searchCondition = 'WHERE (articles.title LIKE ? OR articles.content LIKE ?)';
        const searchPattern = `%${search}%`;
        params.push(searchPattern, searchPattern);
    }

    const countSql = `SELECT COUNT(*) AS total ${baseFrom} ${searchCondition}`;
    const { total } = db.prepare(countSql).get(...params);

    const selectSql = `
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        ${baseFrom}
        ${searchCondition}
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `;

    const dataParams = [...params, limit, offset];
    const articles = db.prepare(selectSql).all(...dataParams);

    const totalPages = Math.ceil(total / limit);

    res.json({
        success: true,
        data: {
            articles: articles
        },
        pagination: {
            page: page,
            limit: limit,
            total: total,
            totalPages: totalPages
        }
    });
});

// GET /api/articles/:id — 获取单篇文章
router.get('/:id', (req, res) => {
    const { id } = req.params;

    const selectArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `);

    const article = selectArticle.get(id);

    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    res.json({
        success: true,
        data: article
    });
});

// POST /api/articles — 创建文章（需登录，支持封面图）
router.post('/', authenticate, (req, res) => {
    const { title, content, cover_image } = req.body;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const author_id = req.user.id;
    const now = new Date().toISOString();

    const insertArticle = db.prepare(`
        INSERT INTO articles (title, content, author_id, cover_image, created_at, updated_at)
        VALUES (?, ?, ?, ?, ?, ?)
    `);

    const result = insertArticle.run(
        title,
        content,
        author_id,
        cover_image || null,
        now,
        now
    );

    const newArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(result.lastInsertRowid);

    res.status(201).json({
        success: true,
        data: newArticle
    });
});

// PUT /api/articles/:id — 更新文章（只能改自己的，支持封面图）
router.put('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const { title, content, cover_image } = req.body;
    const userId = req.user.id;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }
    if (article.author_id !== userId) {
        throw new AppError('只能修改自己的文章', 403);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, cover_image = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(
        title,
        content,
        cover_image !== undefined ? cover_image : article.cover_image,
        now,
        id
    );

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.cover_image,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});

// DELETE /api/articles/:id — 删除文章（只能删自己的，级联删除评论）
router.delete('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const userId = req.user.id;

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);

        throw new AppError('文章不存在', 404);
    }

    if (article.author_id !== userId) {
        throw new AppError('只能删除自己的文章', 403);
    }

    db.prepare('DELETE FROM comments WHERE article_id = ?').run(id);
    db.prepare('DELETE FROM articles WHERE id = ?').run(id);

    res.status(204).send();
});

module.exports = router;
```

## 七、术语附录

| 术语 | 英文 | 通俗解释 | 本章出现位置 | 字面陷阱 |
|------|------|----------|-------------|----------|
| multer | — | Express 的文件上传中间件。名字来源于德语 "multer"（粉碎机），意为"处理（粉碎）上传的文件"。 | 步骤 1 | 不是 "mutter"（喃喃自语）——是 multer，一个 npm 包名。 |
| multipart/form-data | — | HTTP 的一种内容类型，用于在表单中传输文件。请求体被分成多个"部分"，每个部分可以是一个字段或一个文件。 | 步骤 1 | 不是"多部分表单数据"= 数据被分成多份——是"一个请求体包含多个部分"，每部分可以是文本或二进制。 |
| 静态文件服务 | Static File Serving | 服务器把某个文件夹中的文件直接提供给浏览器，不做任何处理。就像餐厅服务员直接把菜单递给客人，不需要厨师加工。 | 步骤 4 | 不是"静态"= 文件不变——是"服务器不处理，直接返回文件内容"。 |

| MIME 类型 | MIME Type | 标识文件类型的标准字符串。`image/jpeg` 表示 JPEG 图片，`text/html` 表示 HTML 文件。浏览器根据 MIME 类型决定如何显示文件。 | 步骤 2 | 不是"MIME"= 一种加密——MIME 是 "Multipurpose Internet Mail Extensions" 的缩写，最初用于邮件附件，现在用于 HTTP。 |

## 八、已知坑点与禁止事项

1. **`multer` 默认无文件大小限制**：必须设置 `limits.fileSize`，否则用户可以上传任意大小的文件。5MB 是一个合理的默认值，但你可以根据需求调整。

2. **文件类型白名单比黑名单安全**：用 `fileFilter` 只允许已知的图片格式（白名单），而不是禁止已知的危险格式（黑名单）。因为新的危险格式不断出现，黑名单永远赶不上。

3. **`uploads/` 目录必须加入 `.gitignore`**：上传的文件属于运行时数据，不应该提交到 Git。提交了会导致仓库体积快速膨胀。

4. **生产环境不要用本地存储**：多台服务器部署时，A 服务器上的 `uploads/` 文件 B 服务器访问不到。生产环境用对象存储（OSS/S3）+ CDN。

5. **`express.static` 的路径使用 `path.join(__dirname, 'uploads')`**：不要用相对路径 `'uploads'`，因为 `process.cwd()` 可能不是你预期的目录。

6. **`ALTER TABLE ADD COLUMN` 前检查字段存在**：SQLite 不允许重复添加同名字段，直接执行会报错。用 `PRAGMA table_info()` 先检查。

7. **`cover_image` 更新时注意保留原值**：如果用户更新文章时没传 `cover_image`，应该保留原有封面图，而不是清空为 `null`。

8. **`upload.single('image')` 的字段名 `'image'` 必须和前端一致**：前后端不一致时 `req.file` 为 `undefined`，会返回 400 "请选择要上传的图片"。
