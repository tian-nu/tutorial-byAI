## 27.1 SSH：加密的远程遥控器

**SSH（Secure Shell）** 是你作为开发者每天都会用的东西——登录远程服务器。它的核心价值：**在不可信网络上建立加密的远程管理通道**。

端口：**22**（TCP）。

### 你每天都在做的事

```bash
# Linux / macOS
ssh user@your-server.com

# Windows PowerShell
ssh user@your-server.com
```

这条命令背后有三件事：
1. 两台机器通过 TLS 类似的机制建立一个**加密通道**
2. 验证——你真的是你要登录的那个用户吗？（密码或密钥）
3. 在这个加密通道里传输终端输入和输出

### SSH 公钥认证（比密码安全 10 倍）

密码登录 SSH 有个致命问题：如果服务器的 SSH 服务被人动了手脚（或者你自己连到了冒充服务器），密码就泄露了。而且密码会被暴力破解。

**公钥认证**是最佳实践：

```
1. 本地生成密钥对
你本机：ssh-keygen -t ed25519 -C "your_email@example.com"
      生成两个文件：
      私钥：~/.ssh/id_ed25519（绝对不能给任何人）
      公钥：~/.ssh/id_ed25519.pub（可以公开）

2. 把公钥放到服务器上
ssh-copy-id user@your-server.com
      把你的公钥追加到服务器的 ~/.ssh/authorized_keys 文件里

3. 以后登录
ssh user@your-server.com
      SSH 自动用你的私钥签名一封信，服务器用公钥验证，
      验证通过就登录，不需要输入密码
```

整个过程没有传输私钥——你的私钥一直在本地。这就是非对称加密的妙用。

### SSH 端口转发（SSH Tunneling）

SSH 还有一个超实用的功能：**端口转发**。你可以把本机的一个端口"映射"到远程服务器的某个端口：

```bash
# 把本机 8080 端口转发到服务器 localhost:3306（服务器上的 MySQL）
ssh -L 8080:localhost:3306 user@your-server.com

# 现在访问本机 localhost:8080 = 服务器的 localhost:3306（MySQL）
```

这在以下场景非常有用：
- 访问不能直接暴露的公网的后端服务
- 在不安全 WiFi 上安全访问内部网站
- 绕过防火墙

## 27.2 DHCP：你连 WiFi 的"第一句话"

你手机连上 WiFi 的那一刻，**还没拿到 IP 地址**，但 TCP/IP 协议栈需要有 IP 才能通信——这就成了"鸡生蛋蛋生鸡"的死锁。

DHCP（**Dynamic Host Configuration Protocol**，动态主机配置协议）就是专门解决这个死锁的。端口：服务器 **67**，客户端 **68**（UDP）。

### 为什么必须用 UDP？

你的机器还没 IP 地址时，TCP 根本没法建立（TCP 需要 IP 地址来标记"连接"）。所以 DHCP 只能跑 UDP——**无连接的协议**，直接广播发消息，不需要先建立"连接"。

### DORA 流程：四步拿到 IP

```
客户端                                     DHCP 服务器
(还没IP)                                   (192.168.1.1)

  │                                            │
  │─── ① Discover ────────────────────────────→│
  │    广播："有人在吗？我需要一个IP！"             │
  │    源IP：0.0.0.0 → 目的IP：255.255.255.255  │
  │                                            │
  │←── ② Offer ───────────────────────────────│
  │    "我可以给你 192.168.1.105，租期24小时"       │
  │                                            │
  │─── ③ Request ─────────────────────────────→│
  │    "好，我就要 192.168.1.105！"               │
  │    （可能多个服务器Offer，选一个确认）      │
  │                                            │
  │←── ④ Acknowledge ─────────────────────────│
  │    "确认！192.168.1.105 归你了。租期、网关、DNS如下"│
  │                                            │
  ⚡ 客户端配置好 IP、子网掩码、网关、DNS，开始正常上网
```

D = Discover（发现服务器）
O = Offer（服务器出价给 IP）
R = Request（客户端确认要这个 IP）
A = Acknowledge（服务器锁定分配）

DHCP 分配的 IP 是有**租期（Lease）**的——通常 24 小时。租期过半时客户端自动续约，租期到了没续自动收回。

💡 **想多一点**：当你看到浏览器报 `ERR_NAME_NOT_RESOLVED`（DNS 查询失败），实际上 DNS 服务器地址也是 DHCP 分配的。所以如果你上不了网但 `ping 8.8.8.8` 能通——说明 IP 拿到手了（DHCP 没问题），但 DNS 挂了。

## 27.3 FTP：上古时代的文件传输

FTP（**File Transfer Protocol**）估计你很少会主动用它了，但你可能在老系统里碰到。端口：**20**（数据）、**21**（控制命令），TCP。

FTP 有一个著名的"特色"让它很麻烦：**主动模式**和**被动模式**。

- **主动模式**：服务器**主动**连回客户端来传数据。问题：客户端可能在 NAT/防火墙后面，服务器根本连不回来。多数情况下被防火墙直接拦截。
- **被动模式**：客户端主动连服务器的数据端口。防火墙友好很多。

❌ **常见错误**：配置 FTP 后发现能登录但传不了文件，80% 的情况是主动/被动模式搞错了，或者防火墙拦截了 20 号端口。

✅ 现在实际场景：基本都用 **SFTP**（SSH File Transfer Protocol，基于 SSH 端口 22）或 HTTPS 下载替代了。如果你要写文件传输应用，别用 FTP——直接 HTTPS 或 SFTP。

## 27.4 SMTP：你每天发的邮件经过了什么

你看不到的协议，但每天都得靠它。SMTP（**Simple Mail Transfer Protocol**）是电子邮件系统的"发送"端。端口：**25**（传统，已被大量封锁）、**587**（现代推荐，带 TLS）、**465**（SSL/TLS）。

### 邮件系统三角关系

```
发送人                               接收人
  │                                    ↑
  │─ SMTP ──→ 发件服务器 ── SMTP ──→ 收件服务器
              (smtp.gmail.com)        (imap.gmail.com)
                                         │
                                   收件人用 POP3/IMAP 下载
```

三种角色：
- **SMTP**：负责**发送**和邮件服务器之间中转
- **POP3**（端口 110）：老式下载协议——把邮件下载到本机，服务器就删了
- **IMAP**（端口 143）：现代协议——邮件存在服务器上，多设备同步查看

核心记忆：SMTP 管发（Send），IMAP/POP 管收（Receive）。

## 27.5 NTP：全网设备的时钟同步

NTP（**Network Time Protocol**，网络时间协议），端口 **123**（UDP）。用途：**让所有设备的时间精确对齐到 UTC**。

NTP 听起来像小众协议，但它是**全网关键基础设施**：

- **TLS 证书**：证书有效期的判断依赖精确时间——如果你服务器时间偏了几天，HTTPS 可能被当成已过期的假证书
- **日志关联**：分布式系统出了问题，你要把几十台服务器的日志串起来排错——如果每台机器时间差 5 分钟，根本拼不起来时间线
- **金融交易**：订单顺序依赖精确时间戳
- **分布式数据库**：多副本一致性协议依赖时间戳排序

NTP 采用分层架构（Stratum）：Stratum 0 是原子钟/GPS → Stratum 1 直接连原子钟 → Stratum 2 连 Stratum 1……通常你的服务器连的是 Stratum 2~4。

## 27.6 小结

| 协议 | 端口 | 协议 | 核心用途 | 一句话 |
|------|------|------|----------|--------|
| **SSH** | 22 | TCP | 加密远程管理 | 公钥认证比密码安全，还有端口转发 |
| **DHCP** | 67/68 | UDP | 自动分配 IP 地址 | DORA：发现→Offer→请求→确认 |
| **FTP** | 20/21 | TCP | 文件传输 | 主动/被动模式坑多，现在用 SFTP 或 HTTPS |
| **SMTP** | 25/587 | TCP | 邮件发送 | 发邮件用 SMTP，收邮件用 IMAP/POP3 |
| **NTP** | 123 | UDP | 时间同步 | 证书验证、日志关联、交易排序都靠它 |

## 术语表

| 术语 | 解释 |
|------|------|
| **SSH (Secure Shell)** | 加密的远程登录协议，端口 22，支持公钥认证和端口转发 |
| **DHCP (Dynamic Host Configuration Protocol)** | 动态主机配置协议，自动分配 IP 地址、子网掩码、网关和 DNS |
| **DORA 流程**（此术语需进附录） | DHCP 分配 IP 的四步：Discover→Offer→Request→Acknowledge |
| **FTP (File Transfer Protocol)** | 文件传输协议，端口 20/21，因主动/被动模式复杂，逐渐被 SFTP 取代 |
| **SFTP (SSH File Transfer Protocol)** | 基于 SSH 的文件传输，使用端口 22，推荐替代 FTP |
| **SMTP (Simple Mail Transfer Protocol)** | 简单邮件传输协议，发送邮件的标准协议，端口 587（带加密） |
| **IMAP / POP3** | 接收邮件的两种协议；IMAP（143）保留服务器副本，POP3（110）下载后删除 |
| **NTP (Network Time Protocol)** | 网络时间协议，端口 123，全网设备时钟同步，精确到毫秒 |

## 验证方法

1. **SSH**：打开终端，运行 `ssh -V`，确认 SSH 客户端可用（绝大多数系统都已预装）。
2. **DHCP**：
   - Windows：PowerShell 运行 `ipconfig /all`，找到 DHCP Server 地址。
   - Linux/macOS：`cat /var/log/syslog | grep -i dhcp` 或 `ip addr show` 看 IP 是否动态分配。
3. **SMTP**：查看域名的 MX 记录（邮件交换记录）：
   ```bash
   # Windows / Linux / macOS 通用
   nslookup -type=mx gmail.com
   ```
   看到 Google 的邮件服务器列表，说明理解了 SMTP 在 DNS 里的定位。
4. **NTP**：运行 `ntpq -p`（Linux/macOS；Windows 用 `w32tm /query /status`）查看当前连接的时间服务器。

## 最可能出错的地方及原因

1. **SSH 私钥泄露**：私钥 `id_ed25519` 一旦泄露，拿到它的人可以登录你所有的服务器。私钥绝不能通过任何方式传输——用 `ssh-keygen` 在本地生成，永不离机。

2. **FTP 主动模式被防火墙拦截**：这是几十年来的经典坑。服务器主动连客户端数据端口，客户端在 NAT 后面根本连不回来。解决方案：切换被动模式（Passive Mode），或者直接抛弃 FTP 改用 SFTP。

3. **NTP 未配置导致 TLS 证书"过期"**：你买了一年的证书，服务器时间却慢了 3 个月——浏览器觉得证书还在一年多前，还没生效，直接弹安全警告。投产环境第一件事就是配 NTP。
