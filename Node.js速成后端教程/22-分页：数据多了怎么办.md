# 22-分页：数据多了怎么办

> "你写了 10000 篇文章，然后一个 GET /api/articles 全部返回——浏览器卡死了，数据库也哭晕在厕所。分页不是什么高深技术，但它是一个后端开发者必须像呼吸一样自然的操作。本章我们用餐厅点菜做比喻，把 LIMIT、OFFSET、总页数、边界情况全部讲透——包括一个让你以后面试能装逼的词：游标分页。"

## 一、目标与完成效果

**一句话目标**：在文章列表接口中实现完整的分页功能，支持 `page` 和 `limit` 查询参数，处理边界情况（负数、超大值、超出范围），返回规范的 `pagination` 元数据。

- 响应中包含 `pagination: { page, limit, total, totalPages }` 元数据。
- 搜索接口（第 23 章）也会复用这套分页逻辑。

## 三、分步操作

### 步骤 1：为什么需要分页——餐厅比喻

想象你去一家餐厅：

> 服务员："这是我们的菜单，共 10000 道菜。"
> 你："......"

**现实中，餐厅把菜单分成一页 20 道菜，你翻一页看一页。** 这就是分页。

分页的每个要素在餐厅里都有对应：

| 分页概念 | 数据库术语 | 餐厅比喻 |
|----------|-----------|----------|
| 页码 | `page` | 菜单的第几页 |
| 每页条数 | `limit`（也叫 `pageSize`） | 每页几道菜 |
| 跳过条数 | `OFFSET` | 翻到第 3 页时跳过前 2 页的菜 |
| 总条数 | `total` | 餐厅一共有多少道菜 |
| 总页数 | `totalPages` | 菜单一共有多少页 |

**没有分页的后果**：
- 10000 篇文章一次返回 → 浏览器渲染 10000 行 → 卡死。
- 数据库一次读取 10000 行 → 内存占用暴增 → 服务器崩溃。
- 用户只想看最新的 10 篇 → 却被迫下载了 9990 篇不需要的数据 → 浪费流量。

### 步骤 2：GET /api/articles 的完整分页实现

打开 `routes/articles.js`，重写 `GET /` 路由，加入完整的参数校验和边界处理：

```javascript
// GET /api/articles — 获取所有文章（支持分页 + 搜索 + 评论数）
router.get('/', (req, res) => {
    // ========== 1. 解析查询参数 ==========
    let page = parseInt(req.query.page) || 1;
    let limit = parseInt(req.query.limit) || 10;

    // ========== 2. 参数校验与修正 ==========
    // 页码不能小于 1
    if (page < 1) {
        page = 1;
    }

    // 每页条数范围：1 ~ 100
    if (limit < 1) {
        limit = 1;
    }
    if (limit > 100) {
        limit = 100;  // 防止恶意请求拉取全量数据
    }

    // 计算偏移量
    const offset = (page - 1) * limit;

    // ========== 3. 查询总数 ==========
    const { total } = db.prepare('SELECT COUNT(*) AS total FROM articles').get();

    // ========== 4. 查询数据 ==========
    const selectArticles = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `);

    const articles = selectArticles.all(limit, offset);

    // ========== 5. 计算总页数 ==========
    const totalPages = Math.ceil(total / limit);

    // ========== 6. 返回结果 ==========
    res.json({
        success: true,
        data: {
            articles: articles
        },
        pagination: {
            page: page,
            limit: limit,
            total: total,
            totalPages: totalPages
        }
    });
});
```

**关键点解析**：

| 步骤 | 在做什么 | 为什么 |
|------|----------|--------|
| `parseInt` | 把字符串转为整数 | `req.query.page` 是字符串 `"1"`，`parseInt` 转成数字 `1` |
| `\|\| 1` / `\|\| 10` | 默认值 | 如果没传 `page`（`undefined`），`NaN \|\| 1` = `1` |
| `page < 1` → `page = 1` | 负数修正 | 用户传 `page=-1` 是无意义的 |
| `limit > 100` → `limit = 100` | 上限限制 | 防止恶意请求 `?limit=999999` 拉取全量数据 |
| `offset = (page - 1) * limit` | 计算偏移量 | 第 2 页（每页 10 条）= 跳过前 10 条 |
| `Math.ceil(total / limit)` | 计算总页数 | 向上取整：27 条 / 10 条每页 = 2.7 → 3 页 |

> 🔥 **魔鬼细节**：`OFFSET 20` 是跳过前 20 条，不是跳过第 20 条。`LIMIT 10 OFFSET 20` = 跳过前 20 条，取第 21~30 条。`OFFSET` 从 0 开始计数——跳过 0 条就是第 1 条开始。

### 步骤 3：`pagination` 返回格式的设计

```json
{
    "success": true,
    "data": {
        "articles": [ ... ]
    },
    "pagination": {
        "page": 1,
        "limit": 10,
        "total": 57,
        "totalPages": 6
    }
}
```

**为什么把 `pagination` 放在顶层而不是 `data` 里面？**

- `data` 是"你要的数据"（文章列表）。
- `pagination` 是"关于这份数据的元信息"（当前第几页、总共多少页）。
- 分开后，前端可以快速提取 `pagination.totalPages` 来渲染分页按钮，不需要解析 `data` 内部结构。

**为什么还要返回 `total` 和 `totalPages`？只返回 `totalPages` 不行吗？**

- `totalPages` 告诉前端"有几页"（渲染分页按钮）。
- `total` 告诉前端"共多少条"（显示"共 57 篇文章"）。
- 两者用途不同，都返回更灵活。

### 步骤 4：边界情况处理表格

| 输入 | 处理逻辑 | 结果 |
|------|----------|------|
| `page=1&limit=10` | 正常分页 | 返回第 1~10 条 |
| `page=2&limit=10` | OFFSET = 10 | 返回第 11~20 条 |
| `page=0` | `page < 1` → 修正为 1 | 返回第 1 页 |
| `page=-5` | 同上 | 返回第 1 页 |
| `page=abc`（非数字） | `parseInt("abc")` = `NaN`，`NaN \|\| 1` = `1` | 返回第 1 页 |
| `limit=0` | `limit < 1` → 修正为 1 | 每页 1 条 |
| `limit=9999` | `limit > 100` → 修正为 100 | 每页 100 条 |
| `page=999&limit=10`（超出范围） | 正常查询，返回空数组 | `articles: []`，`totalPages` 仍正确 |
| 不传参数 | `page=1`, `limit=10`（默认值） | 返回第 1 页，每页 10 条 |

> 🔥 **魔鬼细节**：`Math.ceil(total / limit)` 计算总页数。`Math.ceil(0 / 10)` = `0`——如果总数为 0，总页数也是 0。前端可以据此判断"暂无数据"。

### 步骤 5：`OFFSET` 的性能问题——预告

当数据量很大时（百万级别），`OFFSET` 会有性能问题。

**为什么 OFFSET 在大数据量时很慢？**

```sql
SELECT * FROM articles LIMIT 10 OFFSET 1000000;
```

数据库需要**扫描并跳过前 100 万条记录**，然后才取 10 条。跳过的行越多，查询越慢。这就像你拿着一本 1000 页的书，想翻到第 999 页——你必须一页一页翻过去（或者用目录/索引）。

**解决方案（预告）**：

- **游标分页（Cursor-based Pagination）**：不按页码，而是按"上一页最后一条的 ID"来定位。查询变成 `WHERE id > 上页最后一条的id LIMIT 10`。这种方式利用了索引，速度极快。
- 本教程暂不实现——用传统分页（`OFFSET`）已经足够支撑 99% 的项目。等你数据量到百万级别再考虑优化。

> 🤔 **想多一点**：为什么叫"游标"？就像你用鼠标光标在文本中定位——游标指向"上次读到哪了"，下一次从那里继续读。在数据库中，游标通常是一个记录的唯一标识（如自增 ID 或时间戳）。

### 🤔 想多一点：`page` 从 1 开始还是从 0 开始？

**答案：从 1 开始。**

| 方式 | 页码 | 计算 | 用户体验 |
|------|------|------|----------|
| 从 1 开始 | 第 1 页、第 2 页... | `OFFSET = (page-1) * limit` | 直观，非程序员也懂 |
| 从 0 开始 | 第 0 页、第 1 页... | `OFFSET = page * limit` | 程序员觉得"还行"，但给用户看"第 0 页"很奇怪 |

**API 是给人用的（前端开发者也是人），所以用 1 作为起始页码。** 几乎所有公开 API（GitHub、Twitter、YouTube）都使用从 1 开始的页码。

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| `GET /api/articles?page=2&limit=10` 返回的数据和 page=1 一样 | 忘记计算 OFFSET，或 OFFSET 计算错误 | 确认 `offset = (page - 1) * limit`，而不是 `offset = page * limit` |
| `totalPages` 算出来是小数（如 2.7） | 忘了用 `Math.ceil()` 向上取整 | `Math.ceil(total / limit)` |
| `page=0` 时 OFFSET 为负数 → SQLite 报错 | `(0-1) * 10 = -10`，OFFSET 不能为负数 | 加 `if (page < 1) page = 1` |
| `limit=0` 时 SQLite 报错或返回空 | LIMIT 0 表示"取 0 条"，SQLite 虽然允许但无意义 | 加 `if (limit < 1) limit = 1` |
| `parseInt(undefined)` 返回 `NaN`，导致 `NaN * 10` = `NaN` | 没传参数时 `req.query.page` 为 `undefined` | 用 `parseInt(x) \|\| 默认值` 处理 |
| `page` 和 `limit` 都是字符串，`*` 乘法变成了 `"1" * 10` | JavaScript 的隐式类型转换 | `parseInt` 已解决——`parseInt("1")` 返回数字 `1` |
| `totalPages` 为 0 但实际有数据 | `total` 查询未正确执行 | 检查 `SELECT COUNT(*) AS total FROM articles` 的返回值 |

## 四、完整代码清单

### `blog-backend/routes/articles.js`（本章修改：完整分页实现）

```javascript
const express = require('express');
const router = express.Router();
const { db } = require('../database/db');
const { authenticate } = require('../middleware/auth');
const AppError = require('../utils/AppError');

// ========== 文章 CRUD 接口（数据库版） ==========

// GET /api/articles — 获取所有文章（支持分页 + 带评论数）
router.get('/', (req, res) => {
    // 解析查询参数
    let page = parseInt(req.query.page) || 1;
    let limit = parseInt(req.query.limit) || 10;

    // 参数校验与修正
    if (page < 1) page = 1;
    if (limit < 1) limit = 1;
    if (limit > 100) limit = 100;

    const offset = (page - 1) * limit;

    // 查询总数
    const { total } = db.prepare('SELECT COUNT(*) AS total FROM articles').get();

    // 查询数据
    const selectArticles = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `);

    const articles = selectArticles.all(limit, offset);

    // 计算总页数
    const totalPages = Math.ceil(total / limit);

    res.json({
        success: true,
        data: {
            articles: articles
        },
        pagination: {
            page: page,
            limit: limit,
            total: total,
            totalPages: totalPages
        }
    });
});

// GET /api/articles/:id — 获取单篇文章
router.get('/:id', (req, res) => {
    const { id } = req.params;

    const selectArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `);

    const article = selectArticle.get(id);

    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    res.json({
        success: true,
        data: article
    });
});

// POST /api/articles — 创建文章（需登录）
router.post('/', authenticate, (req, res) => {
    const { title, content } = req.body;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const author_id = req.user.id;
    const now = new Date().toISOString();

    const insertArticle = db.prepare(`
        INSERT INTO articles (title, content, author_id, created_at, updated_at)
        VALUES (?, ?, ?, ?, ?)
    `);

    const result = insertArticle.run(title, content, author_id, now, now);

    const newArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(result.lastInsertRowid);

    res.status(201).json({
        success: true,
        data: newArticle
    });
});

// PUT /api/articles/:id — 更新文章（只能改自己的）
router.put('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const { title, content } = req.body;
    const userId = req.user.id;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }
    if (article.author_id !== userId) {
        throw new AppError('只能修改自己的文章', 403);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(title, content, now, id);

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});

// DELETE /api/articles/:id — 删除文章（只能删自己的，级联删除评论）
router.delete('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const userId = req.user.id;

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    if (article.author_id !== userId) {
        throw new AppError('只能删除自己的文章', 403);
    }

    // 先删除文章的所有评论（级联删除）
    db.prepare('DELETE FROM comments WHERE article_id = ?').run(id);

    // 再删除文章本身
    db.prepare('DELETE FROM articles WHERE id = ?').run(id);

    res.status(204).send();
});

module.exports = router;
```

## 六、小结表格

| 学到的东西 | 一句话解释 |
|-----------|-----------|
| 分页（Pagination） | 把大量数据分成一页一页返回，每次只取一小部分 |
| `LIMIT` | 限制查询返回的行数：`LIMIT 10` = 最多 10 条 |
| `OFFSET` | 跳过前面的行：`OFFSET 20` = 跳过前 20 条 |
| `OFFSET = (page - 1) * limit` | 从页码计算偏移量的公式 |
| `Math.ceil(total / limit)` | 向上取整计算总页数：27 条 / 10 每页 = 3 页 |
| 参数校验 | `page < 1` → 修正为 1；`limit > 100` → 限制为 100 |
| `pagination` 元数据 | 返回 `page, limit, total, totalPages` 给前端渲染分页组件 |
| 游标分页（Cursor-based） | 不用页码，用"上一页最后一条的 ID"定位，大数据量下比 OFFSET 快得多 |
| OFFSET 性能问题 | 大数据量时 OFFSET 需要跳过前面所有行，很慢；百万级数据需考虑游标分页 |

## 八、已知坑点与禁止事项

1. **`OFFSET` 从 0 开始**：`OFFSET 0` = 不跳过 = 从第 1 条开始。`OFFSET 20` = 跳过前 20 条 = 从第 21 条开始。不要搞混。

2. **`page` 从 1 开始**：公式 `OFFSET = (page - 1) * limit`。如果 page 从 0 开始，公式变成 `OFFSET = page * limit`。本教程统一用从 1 开始的页码。

3. **`limit` 必须限制上限**：不做限制的话，恶意请求 `?limit=999999999` 会让数据库尝试返回所有数据——内存爆炸。本教程限制最大 100。

4. **`Math.ceil(total / limit)` 在 `total = 0` 时返回 0**：如果数据库中没有文章，`totalPages = 0`。前端应据此显示"暂无数据"。

5. **`SELECT COUNT(*)` 也会被 `LIMIT` 和 `OFFSET` 影响吗？** 不会——`COUNT(*)` 是聚合函数，不受 `LIMIT/OFFSET` 影响。但如果你在一个查询中同时用了 `SELECT *` 和 `COUNT(*)`，需要分开两条查询或在子查询中处理。

6. **OFFSET 大数据量性能问题**：本教程暂不解决，但你需要知道它存在。`OFFSET 1000000` 在百万级数据中会明显变慢。后续优化方向：游标分页或 Elasticsearch。
