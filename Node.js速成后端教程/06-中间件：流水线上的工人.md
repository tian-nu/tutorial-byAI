## 三、分步操作

### 步骤 1：中间件的比喻——"工厂流水线"

在理解中间件之前，先看一个场景。

**没有中间件时**：客人点菜 → 服务员直接端菜。中间没有任何环节。

```
请求 → 路由处理函数 → 响应
```

**有中间件时**：客人点菜 → 门口迎宾（记录谁来了）→ 安检（检查有没有会员卡）→ 服务员（点菜）→ 后厨（做菜）→ 端菜员（加个餐巾纸）→ 客人。

```
请求 → [中间件1] → [中间件2] → [中间件3] → 路由处理函数 → [中间件4] → 响应
```

**中间件就是流水线上的工人。每个工人只做一件事，做完传给下一个工人。**

#### Express 中的中间件长什么样？

```javascript
function myMiddleware(req, res, next) {
    // 做点什么……
    console.log('一个请求进来了！');
    next(); // 交给下一个工人
}
```

三个参数：
- `req`：请求对象（和路由处理函数里的一样）
- `res`：响应对象（和路由处理函数里的一样）
- `next`：**一个函数，调用它表示"我干完了，传给下一个"**

> 🔥 **魔鬼细节**：`next` 不是"下一个中间件"的意思，而是**一个函数**。调用 `next()` 这个函数，Express 才会执行下一个中间件。**不调 `next()`，请求就卡住了，浏览器一直转圈，直到超时。**

---

### 步骤 2：中间件的函数签名详解

每个中间件都是一个函数，签名为 `(req, res, next) => { ... }`。

```javascript
function myMiddleware(req, res, next) {
    // 1. 可以读取 req（请求信息）
    console.log(req.method, req.url);  // 比如：GET /api/articles

    // 2. 可以修改 req（给后面的中间件/路由传递数据）
    req.requestTime = new Date().toISOString();

    // 3. 可以修改 res（但通常不在这里发响应）
    res.setHeader('X-Powered-By', 'My App');

    // 4. 调用 next() 传给下一个
    next();

    // 5. next() 之后的代码也会执行——但一般不在 next() 后面写逻辑
}
```

**比喻**：中间件 = 流水线上的质检员。他拿到一个产品（req），检查一下（读取 req.method），在上面贴个标签（修改 req），然后按传送带按钮（next()），产品就流到下一个工位了。

> 🔥 **重要**：中间件**可以提前结束请求**（不调 `next()`，直接 `res.send()`）。比如认证中间件发现用户没登录，直接返回 401，不用往下传。但**一旦调了 `next()`，就不能再发响应了**——因为响应已经由后面的中间件/路由处理了。

---

### 步骤 3：next() 的重要性——忘记调 next() 的后果

这是中间件最经典的坑。我们来亲手制造一个"事故"。

在 `server.js` 中，在所有路由**之前**添加一个测试中间件——**故意不调 next()**：

```javascript
// ⚠️ 危险示范：这个中间件忘了调 next()
app.use((req, res, next) => {
    console.log('请求进来了，但我不打算往下传……');
    // 忘了写 next()！
});
```

保存后，用 Thunder Client 发 `GET http://localhost:3000/`。

**结果**：浏览器/Thunder Client 一直转圈，最终超时。终端有日志输出，但没有任何响应。

**为什么？** 请求被这个中间件拦截了，但中间件既没有调用 `next()` 继续往下传，也没有调用 `res.send()` 返回响应。请求就"悬"在那里了。

**修复**：加上 `next()`：

```javascript
// ✅ 正确版本
app.use((req, res, next) => {
    console.log('请求进来了，我记录一下，然后传给下一个');
    next(); // 必须调用！
});
```

> **比喻**：中间件不像拦路虎，而是像接力赛。每个工人做完自己的事，必须把棒子（next()）交给下一个工人。如果某个工人拿着棒子不传，整个接力赛就卡住了。

---

### 🤔 想多一点：中间件可以提前返回，但必须 return

如果你在中间件里想"提前结束"（比如发现用户没权限），可以这样做：

```javascript
app.use((req, res, next) => {
    if (req.headers['x-api-key'] !== 'secret') {
        return res.status(403).json({ error: '无效的 API Key' });
        // 注意：这里有 return！不调 next()，直接返回响应
    }
    next(); // 有权限，继续往下
});
```

> 🔥 **魔鬼细节**：`return res.status(403).json(...)` 中的 `return` 很重要。如果没有 `return`，`res.json()` 之后代码还会继续执行到 `next()`，然后 Express 会尝试发送两次响应，导致 `ERR_HTTP_HEADERS_SENT` 错误。**提前返回响应时，必须加 `return`。**

### 步骤 4：内置中间件——express.json() 和 express.urlencoded()

Express 自带了一些中间件，最常用的两个是：

#### 4.1 express.json()——解析 JSON 请求体

**问题**：到目前为止，你的 POST 和 PUT 请求没有接收过请求体数据。试试看：

在 `server.js` 中添加一个测试路由：

```javascript
// 测试——看看 req.body 是什么
app.post('/api/echo', (req, res) => {
    res.json({
        body: req.body,        // 请求体
        method: req.method     // 请求方法
    });
});
```

用 Thunder Client 发 `POST http://localhost:3000/api/echo`，在 **Body** 标签中，选择 **JSON**，输入：

```json
{
    "name": "张三",
    "age": 25
}
```

发送。**结果**：`req.body` 是 `undefined`！

**原因**：Express 默认不会解析请求体。你需要告诉它："如果请求体是 JSON 格式，帮我解析成 JavaScript 对象"。

在 `server.js` 中，在所有路由**之前**添加：

```javascript
// 解析 JSON 格式的请求体
app.use(express.json());
```

> 🔥 **位置极其重要**：`express.json()` 必须在所有路由**之前**。因为它是一个中间件——它解析请求体，然后把解析好的数据放到 `req.body` 上。如果路由在它之前，路由里的 `req.body` 就还是 `undefined`。

现在再发一次 `POST /api/echo`——`req.body` 应该是 `{ name: '张三', age: 25 }`。

#### 4.2 express.urlencoded()——解析表单数据

如果前端用 HTML `<form>` 提交数据（而不是用 JavaScript 的 `fetch`），数据格式是 URL 编码的（`name=张三&age=25`），需要另一个中间件：

```javascript
// 解析 URL 编码格式的请求体（表单提交）
app.use(express.urlencoded({ extended: true }));
```

> `extended: true` 允许解析嵌套对象。对于本教程的博客系统，JSON 格式已经足够，但加上 `urlencoded` 是社区标准实践，不加也没关系。

#### 4.3 当前的 server.js 中间件部分

现在 `server.js` 的开头应该是：

```javascript
const express = require('express');
const app = express();

// ========== 中间件（顺序很重要！） ==========
app.use(express.json());           // 解析 JSON 请求体
app.use(express.urlencoded({ extended: true })); // 解析表单数据

// ========== 引入路由模块 ==========
const articlesRouter = require('./routes/articles');
const authRouter = require('./routes/auth');

// ========== 挂载路由 ==========
app.use('/api/articles', articlesRouter);
app.use('/api/auth', authRouter);

// ... 其他路由
```

### 步骤 5：自定义中间件实战——日志中间件

现在来写一个真正有用的自定义中间件。我们创建一个日志中间件，记录每个请求的方法、路径、时间、耗时。

#### 5.1 创建 `middleware/` 文件夹和 `logger.js`

在 `blog-backend/` 下创建 `middleware/` 文件夹，然后在里面新建 `logger.js`：

```javascript
// middleware/logger.js — 日志中间件
function logger(req, res, next) {
    // 记录请求开始的时间
    const start = Date.now();

    // 获取当前时间的格式化字符串
    const timestamp = new Date().toISOString();

    // 打印请求信息
    console.log(`[${timestamp}] ${req.method} ${req.url}`);

    // 监听响应完成事件，计算耗时
    res.on('finish', () => {
        const duration = Date.now() - start;
        console.log(`[${timestamp}] ${req.method} ${req.url} — ${res.statusCode} (${duration}ms)`);
    });

    // 传给下一个中间件
    next();
}

module.exports = logger;
```

#### 逐行解释

```javascript
const start = Date.now();
```

`Date.now()` 返回当前时间戳（毫秒）。记录请求进来的时间，用处是等一下计算耗时。

```javascript
res.on('finish', () => { ... });
```

`res.on('finish', ...)` 是一个**事件监听器**。当响应发送完毕时，Express 会触发 `finish` 事件。我们在这个时机打印最终日志——包括状态码和耗时。

> 🔥 **魔鬼细节**：为什么不在 `console.log` 之后直接算耗时，而要用 `res.on('finish')`？因为 `next()` 只是把请求传给下一个中间件，并不代表响应已经发完了。响应可能还要经过路由处理函数、数据库查询等。只有 `finish` 事件触发时，才表示响应真正发出去了。

#### 5.2 在 server.js 中全局使用

在 `server.js` 中，在 `express.json()` 之前引入并使用：

```javascript
const express = require('express');
const app = express();

// 引入日志中间件
const logger = require('./middleware/logger');

// ========== 中间件 ==========
app.use(logger);                     // 日志（放在最前面，记录所有请求）
app.use(express.json());             // 解析 JSON
app.use(express.urlencoded({ extended: true })); // 解析表单

// ... 路由等
```

> `app.use(logger)` 的意思是：**所有请求**都要经过 `logger` 这个中间件。因为 `logger` 的路径是 `/`（默认），匹配所有路径。

#### 5.3 验证

保存文件，nodemon 重启。用 Thunder Client 发几个请求，观察终端输出：

```
[2026-06-12T10:30:00.000Z] GET /api/articles
[2026-06-12T10:30:00.015Z] GET /api/articles — 200 (15ms)
[2026-06-12T10:30:05.000Z] POST /api/echo
[2026-06-12T10:30:05.003Z] POST /api/echo — 200 (3ms)
```

每行请求都有时间戳、方法、路径、状态码和耗时。现在你可以一眼看出哪个接口慢、哪个接口报错了。

### 步骤 6：第三方中间件——morgan 和 cors

社区有大量现成的中间件，不用自己写。我们装两个最常用的：

#### 6.1 morgan——专业的 HTTP 日志中间件

你刚才写的 `logger.js` 功能不错，但 `morgan` 是更专业的版本，功能更强、输出更美观。

安装：

```bash
npm install morgan
```

在 `server.js` 中使用：

```javascript
const morgan = require('morgan');

// 使用 morgan 的 'dev' 格式（彩色输出，适合开发环境）
app.use(morgan('dev'));
```

> morgan 有多种格式：`'dev'`（开发用，彩色简洁）、`'combined'`（生产用，Apache 标准格式）、`'tiny'`（极简）、`'short'`（简短）。本教程用 `'dev'`。

现在终端输出会变成：

```
GET /api/articles 200 15.234 ms - 345
POST /api/echo 200 2.567 ms - 42
```

彩色输出，格式为：`方法 URL 状态码 耗时 - 响应体大小（字节）`。

> **要不要保留自己的 logger.js？** 你可以二选一。如果你是初学者，建议保留 `logger.js`——因为它是你自己写的，你能完全理解它的每一行代码。`morgan` 是黑盒，但生产环境更推荐用它。本教程两个都保留——`logger.js` 用于学习，`morgan` 用于实际使用。

#### 6.2 cors——跨域资源共享

**问题**：如果你的前端代码部署在 `http://localhost:5173`（Vite），后端在 `http://localhost:3000`，浏览器会阻止前端发请求到后端——这叫**跨域限制**（CORS policy）。

**解决**：装 `cors` 中间件：

```bash
npm install cors
```

在 `server.js` 中使用：

```javascript
const cors = require('cors');

// 允许跨域请求
app.use(cors());
```

> `cors()` 不传参数表示"允许所有来源的跨域请求"。在开发阶段这样没问题，上线时应该配置具体的允许域名：`app.use(cors({ origin: 'https://your-frontend.com' }))`。

### 步骤 7：app.use() 的位置顺序——中间件顺序就是执行顺序

这是理解中间件最重要的一条规则。

**Express 按照 `app.use()` 的书写顺序，从上到下执行中间件和路由。**

```
请求进来
  ↓
app.use(logger)          ← 第 1 个执行
  ↓
app.use(express.json())  ← 第 2 个执行
  ↓
app.use('/api/articles', articlesRouter)  ← 第 3 个匹配（如果路径匹配）
  ↓
app.get('/', ...)        ← 第 4 个匹配（如果路径匹配）
  ↓
（没有匹配的路由 → 404）
```

#### 顺序错误示例

```javascript
// ❌ 错误——express.json() 在路由后面
app.use('/api/articles', articlesRouter); // 路由先执行
app.use(express.json());                  // 中间件后执行

// 结果：articlesRouter 里的 POST 路由拿不到 req.body！
```

```javascript
// ✅ 正确——express.json() 在路由前面
app.use(express.json());                  // 先解析 body
app.use('/api/articles', articlesRouter); // 路由后执行，req.body 已经有了
```

> 🔥 **金科玉律**：`express.json()` 必须在所有路由之前。日志中间件通常放在最前面（记录所有请求）。`cors()` 放在最前面（在处理请求之前就设置好跨域头）。

### 步骤 8：错误处理中间件——四个参数的特殊中间件

到目前为止，你的代码出错时，Express 会返回一个默认的 HTML 错误页面。对于 API 来说，这不够好——我们需要返回 JSON 格式的错误信息。

#### 8.1 错误处理中间件的特殊签名

Express 通过**参数个数**来区分普通中间件和错误处理中间件：

```javascript
// 普通中间件——3 个参数
(req, res, next) => { ... }

// 错误处理中间件——4 个参数
(err, req, res, next) => { ... }
```

> 🔥 **魔鬼细节**：Express 判断一个函数是不是错误处理中间件，**只看参数个数**。即使你不需要 `next`，也必须写四个参数，否则 Express 不会把错误传给它。

#### 8.2 创建 `middleware/errorHandler.js`

```javascript
// middleware/errorHandler.js — 全局错误处理中间件
function errorHandler(err, req, res, next) {
    // 打印错误到控制台（方便调试）
    console.error('❌ 服务器错误:', err.message);
    console.error(err.stack);

    // 设置默认状态码（如果 err 对象上没有 statusCode 属性，默认 500）
    const statusCode = err.statusCode || 500;

    // 返回 JSON 格式的错误信息
    res.status(statusCode).json({
        success: false,
        error: {
            message: err.message || '服务器内部错误',
            // 开发环境返回错误堆栈，生产环境不返回
            ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
        }
    });
}

module.exports = errorHandler;
```

#### 逐行解释

```javascript
const statusCode = err.statusCode || 500;
```

如果错误对象上有 `statusCode` 属性（说明是"已知错误"，如 404），就用它；否则默认 500（服务器内部错误）。

```javascript
...(process.env.NODE_ENV === 'development' && { stack: err.stack })
```

这是 JavaScript 的展开运算符（spread）配合条件表达式。如果当前是开发环境，就把 `stack` 字段加到响应中；如果是生产环境，不加——防止把代码细节暴露给攻击者。

#### 8.3 在 server.js 中使用

错误处理中间件必须放在**所有路由之后**：

```javascript
// ... 所有路由定义 ...

// ========== 错误处理中间件（必须放在最后） ==========
app.use(errorHandler);
```

> 🔥 **位置极其重要**：错误处理中间件必须放在所有 `app.use()` 和路由定义的**最后面**。它就像一个"安全网"——前面的中间件和路由中，任何没被捕获的错误，最终都会落到这个网里。

#### 8.4 测试错误处理

在 `server.js` 中临时添加一个会出错的路由：

```javascript
// 测试错误处理
app.get('/api/error', (req, res) => {
    throw new Error('这是一个测试错误！');
});
```

用 Thunder Client 发 `GET http://localhost:3000/api/error`。你应该看到：

```json
{
    "success": false,
    "error": {
        "message": "这是一个测试错误！",
        "stack": "Error: 这是一个测试错误！\n    at ..."
    }
}
```

而不是 Express 默认的 HTML 错误页面。

> 测试完记得删除这个测试路由，或者注释掉。

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| `req.body` 是 `undefined` | 没装 `express.json()` 中间件 | 在路由之前加 `app.use(express.json())` |
| 浏览器一直转圈，最终超时 | 中间件里忘了调 `next()` | 检查每个自定义中间件，确保路径通畅时调了 `next()` |
| `Cannot set headers after they are sent` | 发了两次响应——可能中间件里 `res.send()` 后又调了 `next()` | 发响应后加 `return`，不要调 `next()` |
| 错误处理中间件没有被触发 | 参数个数不是 4 个 | 错误处理中间件必须写 `(err, req, res, next)` 四个参数 |
| morgan 不输出日志 | 放在了 `express.json()` 之后，且顺序不对 | 把 `app.use(morgan('dev'))` 放在最前面 |
| `express.json()` 解析后 `req.body` 还是空对象 | 请求的 Content-Type 不是 `application/json` | 在 Thunder Client 中确认 Body 类型选的是 JSON |
| 中间件顺序错误导致功能异常 | `app.use()` 的顺序不对 | 检查：日志 → cors → express.json() → 路由 → 错误处理 |

## 四、完整代码清单

### `blog-backend/server.js`（本章最终状态）

```javascript
const express = require('express');
const morgan = require('morgan');
const cors = require('cors');
const app = express();

// 引入自定义中间件
const logger = require('./middleware/logger');
const errorHandler = require('./middleware/errorHandler');

// ========== 中间件（顺序很重要！） ==========
app.use(logger);                           // 1. 自定义日志
app.use(morgan('dev'));                    // 2. 专业日志
app.use(cors());                           // 3. 跨域
app.use(express.json());                   // 4. 解析 JSON 请求体
app.use(express.urlencoded({ extended: true })); // 5. 解析表单数据

// ========== 引入路由模块 ==========
const articlesRouter = require('./routes/articles');
const authRouter = require('./routes/auth');

// ========== 挂载路由 ==========
app.use('/api/articles', articlesRouter);
app.use('/api/auth', authRouter);

// 首页路由
app.get('/', (req, res) => {
    res.send('你好，世界！');
});

// API 测试路由
app.get('/api/hello', (req, res) => {
    res.json({ message: 'Hello API' });
});

// 测试四种 HTTP 方法
app.post('/api/test', (req, res) => {
    res.json({ message: 'POST 请求成功！' });
});
app.put('/api/test', (req, res) => {
    res.json({ message: 'PUT 请求成功！' });
});
app.delete('/api/test', (req, res) => {
    res.json({ message: 'DELETE 请求成功！' });
});

// Echo 接口——返回请求体
app.post('/api/echo', (req, res) => {
    res.json({
        body: req.body,
        method: req.method
    });
});

// ========== 错误处理中间件（必须放在最后） ==========
app.use(errorHandler);

app.listen(3000, () => {
    console.log('Server is running on http://localhost:3000');
});
```

### `blog-backend/middleware/logger.js`（本章新建）

```javascript
// middleware/logger.js — 自定义日志中间件
function logger(req, res, next) {
    const start = Date.now();
    const timestamp = new Date().toISOString();

    console.log(`[${timestamp}] ${req.method} ${req.url}`);

    res.on('finish', () => {
        const duration = Date.now() - start;
        console.log(`[${timestamp}] ${req.method} ${req.url} — ${res.statusCode} (${duration}ms)`);
    });

    next();
}

module.exports = logger;
```

### `blog-backend/middleware/errorHandler.js`（本章新建）

```javascript
// middleware/errorHandler.js — 全局错误处理中间件
function errorHandler(err, req, res, next) {
    console.error('❌ 服务器错误:', err.message);
    console.error(err.stack);

    const statusCode = err.statusCode || 500;

    res.status(statusCode).json({
        success: false,
        error: {
            message: err.message || '服务器内部错误',
            ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
        }
    });
}

module.exports = errorHandler;
```

## 六、小结表格

| 学到的东西 | 一句话解释 |
|-----------|-----------|
| 中间件的本质 | 一个函数 `(req, res, next)`，在请求到达路由之前/之后执行，对请求做处理 |
| `next()` 的作用 | 把请求传给下一个中间件/路由。**不调就卡住，浏览器一直转圈** |
| `express.json()` | 内置中间件——解析 JSON 格式的请求体，把结果放到 `req.body` 上 |
| `express.urlencoded()` | 内置中间件——解析 HTML 表单提交的数据 |
| 自定义中间件 | 写一个 `(req, res, next) => { ... }` 函数，用 `app.use()` 挂载 |
| `res.on('finish', ...)` | 监听响应完成事件，可以在此时记录耗时 |
| `morgan` | 第三方日志中间件，比手写 logger 更专业、输出更美观 |
| `cors` | 第三方跨域中间件，允许前端从其他域名访问后端 API |
| `app.use()` 顺序 | 中间件按书写顺序执行——`express.json()` 必须在路由之前 |
| 错误处理中间件 | 四个参数 `(err, req, res, next)`，放在所有路由最后，捕获所有未处理的错误 |
| 请求生命周期 | 请求 → 日志中间件 → JSON解析 → 路由匹配 → 处理函数 → 响应 → 错误处理（如果有错） |

## 八、已知坑点与禁止事项

1. **`express.json()` 必须放在路由之前**：这是最高频的错误。如果你先定义了路由，再 `app.use(express.json())`，路由里的 `req.body` 就是 `undefined`。**中间件顺序 = 执行顺序。**

2. **忘记调 `next()`**：中间件函数里如果忘记调 `next()`，请求就卡住了。浏览器会一直转圈直到超时，而且没有任何错误提示——你只能看到终端里没有后续日志。

3. **提前返回响应后必须 `return`**：如果你在中间件里 `res.status(403).json(...)` 但没有 `return`，后面的代码（包括 `next()`）会继续执行，导致尝试发送两次响应，报 `ERR_HTTP_HEADERS_SENT`。

4. **错误处理中间件必须四个参数**：Express 通过 `Function.length`（参数个数）来判断。如果你写了 `(err, req, res)` 三个参数，Express 不会把它当错误处理中间件。第四个参数 `next` 即使不用，也必须写。

5. **错误处理中间件必须放在所有路由之后**：它就像一个"安全网"——放在最后才能捕获前面所有中间件和路由中抛出的错误。

6. **`res.send()` / `res.json()` 只能调一次**：一个请求只能有一个响应。中间件里发了响应，就不能再调 `next()`；路由里发了响应，后面的中间件再发响应就会报错。
