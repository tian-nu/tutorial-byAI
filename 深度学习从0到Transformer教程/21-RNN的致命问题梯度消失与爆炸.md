# Ch21 · RNN 的致命问题 — 梯度消失与爆炸

> 所属篇：第三篇 · 预计耗时：25 分钟

RNN 训了半天，发现它只能记住最近几个词，远一点的就忘了。这不是你代码写错了，是 RNN 的"基因缺陷"——**梯度消失**。这个缺陷直接催生了 LSTM。这一章我们用数学看清这个缺陷的根源，并学会用梯度裁剪缓解"爆炸"那一半。

---

## 为了什么（Why）

**核心痛点**：RNN 在长序列上梯度消失/爆炸，无法学习**长距离依赖**——前面几十步的信息传不到后面。

举个反例：句子"我出生在法国……（100 词后）……我会说法语"。要正确预测最后的"法语"，模型必须把 100 步前的"法国"记到现在。但 RNN 的梯度从"法语"往"法国"反传时，每经过一个时间步都要乘以 `W_hh` 和 `tanh'(z)`，连乘 100 次后——梯度要么趋近 0（学不动），要么趋近 ∞（数值炸掉）。前者叫梯度消失，后者叫梯度爆炸。

**这一章的目标**：理解梯度消失/爆炸的数学根源，能用一句话解释"`|W_hh|<1` 梯度消失、`|W_hh|>1` 梯度爆炸"，并掌握梯度裁剪这个实用技巧。

## 要做到（Goal）

- **输入**：理解 Ch20 的 BPTT 梯度流。
- **输出**：理解梯度消失/爆炸的数学根源，掌握梯度裁剪。
- **成功标准**：能解释为什么 `|W_hh|<1` 梯度消失、`|W_hh|>1` 梯度爆炸，并说出梯度裁剪的局限。

## 做了什么（What）

问题出在 BPTT 的"连乘效应"——梯度沿时间反传时，每步都要乘以 `W_hh` 和 `tanh'(zₜ)`，连乘 T 步：

```
梯度连乘示意（从 t=T 反传到 t=1）

∂L/∂h₁ ≈ (W_hh · tanh'(z_T)) · (W_hh · tanh'(z_{T-1})) · ... · (W_hh · tanh'(z_2))
          └─────────────────────────────────────────────────────┘
                            共 T-1 个因子连乘

每个因子 = W_hh × tanh'
  - 若 |W_hh × tanh'| < 1 → 连乘趋近 0（梯度消失）
  - 若 |W_hh × tanh'| > 1 → 连乘趋近 ∞（梯度爆炸）
```

### 逐组件拆解

**连乘效应**：BPTT 反传梯度时，`∂L/∂h₁` 要经过 T-1 个时间步，每步乘以 `W_hh` 和 `tanh'(zₜ)`。数学上 `∂L/∂h₁ ≈ ∏(W_hh · tanh'(zₜ))`——T-1 个因子的连乘。

**梯度消失（Vanishing Gradient）**：当 `|W_hh · tanh'| < 1` 时，连乘结果趋近 0。`h₁` 收到的梯度几乎为 0，参数更新量为 0，模型学不到早期时间步的规律。

**梯度爆炸（Exploding Gradient）**：当 `|W_hh · tanh'| > 1` 时，连乘结果趋近 ∞。参数更新量巨大，损失突然变成 NaN，训练崩溃。

**为什么 tanh' 加剧消失**：`tanh'(z) = 1 - tanh²(z)` 最大值是 1（在 z=0 时），但大部分时候小于 1。所以即使 `|W_hh| = 1`，`|W_hh · tanh'|` 也常常小于 1，连乘依然消失。

## 怎么算（How）

### 核心公式

```
∂L/∂h₁ ≈ ∏ₜ₌₂ᵀ (W_hh · tanh'(zₜ))
```

### 关于 tanh' ≈ 0.5 的假设说明

> **关键说明**：`tanh'(z) = 1 - tanh²(z)` 的最大值是 1（当 z=0 时）。但在训练过程中，`z` 通常不为 0——`z = W_xh·x + W_hh·h + b` 的值分布在 0 附近的一个范围内。**平均下来 `tanh'(z)` 大约 0.5 左右**，这里用 0.5 作为示意值来演示连乘效应。
>
> 这不是精确值，而是用于说明问题的典型量级。实际训练中 `tanh'` 的真实值会随每步的 `z` 变化，但量级上确实在 0.5 附近波动。

### 数值小例子 1：梯度消失

设 `W_hh = 0.5`，`tanh' ≈ 0.5`（平均）：

每步乘 `W_hh × tanh' = 0.5 × 0.5 = 0.25`

连乘 T 步后梯度衰减：

| 步数 T | 0.25^T | 含义 |
|--------|--------|------|
| 1 | 0.25 | 还行 |
| 5 | 9.77e-4 | 已经很小 |
| 10 | 9.54e-7 | 几乎为 0 |
| 20 | 9.09e-13 | 完全消失 |

**逐步计算 10 步**：
- `0.25^1 = 0.25`
- `0.25^2 = 0.0625`
- `0.25^5 = 0.000977`
- `0.25^10 = 9.54e-7`（梯度几乎为 0）
- `0.25^20 = 9.09e-13`（完全消失）

含义：经过 10 个时间步，`h₁` 收到的梯度只有原始的 9.5e-7 倍——参数更新量微乎其微，模型学不到 10 步前的信息。20 步后梯度直接 1e-13 量级，等于没学。

### 数值小例子 2：梯度爆炸

设 `W_hh = 2.0`，`tanh' ≈ 0.8`（稍大一点的情况）：

每步乘 `W_hh × tanh' = 2.0 × 0.8 = 1.6`

连乘 T 步后梯度增长：

| 步数 T | 1.6^T | 含义 |
|--------|-------|------|
| 1 | 1.6 | 还行 |
| 5 | 10.49 | 开始变大 |
| 10 | 109.95 | 已经很大 |
| 20 | 12089.26 | 完全失控 |

**逐步计算 10 步**：
- `1.6^1 = 1.6`
- `1.6^2 = 2.56`
- `1.6^5 = 10.49`
- `1.6^10 = 109.95`（梯度爆炸）
- `1.6^20 = 12089.26`（完全失控，数值溢出）

含义：经过 10 个时间步，梯度放大了 110 倍——参数更新量巨大，损失直接变 NaN，训练崩溃。

> 注意：如果 `tanh' ≈ 0.5`，那么 `W_hh = 2.0` 时每步乘 `1.0`，连乘不增不减——刚好临界状态。所以"爆炸"需要 `W_hh × tanh' > 1`，即 `W_hh > 1/tanh'`。`tanh'` 越大（接近 1），越容易爆炸；`tanh'` 越小（接近 0.5），越不容易爆炸但越容易消失。

### 梯度裁剪（缓解爆炸）

梯度裁剪是缓解**爆炸**的实用技巧——当梯度范数超过阈值时，把梯度缩放到阈值范围内：

```python
# 梯度裁剪
def clip_gradient(grad, max_norm=5.0):
    norm = np.linalg.norm(grad)
    if norm > max_norm:
        grad = grad * max_norm / norm
    return grad
```

直觉理解：梯度是个向量，`np.linalg.norm(grad)` 是它的长度。如果长度超过 `max_norm`，就按比例缩短到 `max_norm`——方向不变，只缩短长度。这样保证每步更新量不会过大。

**PyTorch 内置实现**：

```python
import torch
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0)
```

一行调用，在 `loss.backward()` 之后、`optimizer.step()` 之前执行。

```python
import numpy as np

# 梯度裁剪
def clip_gradient(grad, max_norm=5.0):
    """把梯度范数限制在 max_norm 以内"""
    norm = np.linalg.norm(grad)
    if norm > max_norm:
        grad = grad * max_norm / norm
    return grad

# 演示梯度消失
def demo_vanishing(T=20, W_hh=0.5, tanh_prime=0.5):
    """模拟 T 步连乘"""
    grad = 1.0
    factor = W_hh * tanh_prime
    for t in range(1, T+1):
        grad *= factor
        if t in [1, 5, 10, 20]:
            print(f"  T={t:2d}: 梯度 = {grad:.2e}")
    return grad

# 演示梯度爆炸
def demo_exploding(T=20, W_hh=2.0, tanh_prime=0.8):
    """模拟 T 步连乘"""
    grad = 1.0
    factor = W_hh * tanh_prime
    for t in range(1, T+1):
        grad *= factor
        if t in [1, 5, 10, 20]:
            print(f"  T={t:2d}: 梯度 = {grad:.2e}")
    return grad

# 梯度裁剪演示
big_grad = np.array([10.0, 20.0, 30.0])  # 范数 ≈ 37.4
clipped = clip_gradient(big_grad, max_norm=5.0)
print(f"裁剪前范数: {np.linalg.norm(big_grad):.2f}")
print(f"裁剪后范数: {np.linalg.norm(clipped):.2f}")
```

## 想多一点

> 为什么梯度裁剪只能解决爆炸，不能解决消失？
>
> 答案是：**裁剪是把大梯度缩小，但小梯度无法放大**。
>
> 具体来说：梯度裁剪的逻辑是"如果 `||grad|| > max_norm`，就按比例缩小到 `max_norm`"——这只对**过大**的梯度起作用。对于过小的梯度（比如 1e-13），裁剪完全不影响它，梯度还是 1e-13，模型还是学不动。
>
> 那能不能反向操作——"放大"小梯度？理论上可以（比如梯度归一化到固定范数），但这会破坏不同参数之间的相对梯度比例，让训练不稳定。所以实际中很少这么做。
>
> 梯度消失需要从**架构层面**解决——这就是 LSTM（Ch22）的动机。LSTM 通过门控机制让梯度可以"长距离直通"，绕开连乘衰减。这是 RNN 进化到 LSTM 的根本原因。

## 易错点预警

- ❌ 以为梯度裁剪能解决梯度消失（觉得裁剪一劳永逸）→ ✅ 正确：**裁剪只解决爆炸，消失需要 LSTM 等架构层面的改进**。裁剪对小梯度无效，因为它只缩大不放大。
- ❌ 以为 `tanh'` 的最大值是 0.5（看到教程用 0.5 就以为是上限）→ ✅ 正确：**`tanh'` 的最大值是 1（在 z=0 时）**，0.5 只是训练中的"平均"示意值。`tanh'(z) = 1 - tanh²(z)`，z=0 时为 1，z 偏离 0 时迅速下降。
- ❌ 用 ReLU 替换 tanh 想解决梯度消失（觉得 ReLU 导数恒为 1）→ ✅ 正确：**RNN 用 tanh 不用 ReLU**。ReLU 无上界会让隐藏状态爆炸，而且 ReLU 在 RNN 中容易导致"激活值单调增长"的问题。LSTM 用 sigmoid 门控 + tanh 候选，才是正确的解法。

## 章末小结

| 概念 | 一句话解释 | 易错点 |
|------|-----------|--------|
| 梯度消失（Vanishing） | 连乘使梯度趋近 0 | tanh 的导数 < 1 加剧消失 |
| 梯度爆炸（Exploding） | 连乘使梯度趋近 ∞ | 用梯度裁剪缓解 |
| 连乘效应 | T 步反传 = T 个因子连乘 | 是 RNN 长依赖问题的根源 |
| 长依赖（Long-term Dependency） | 100 步前的信息 | RNN 学不到，需要 LSTM |
| 梯度裁剪（Gradient Clipping） | 把大梯度缩到阈值内 | 只治爆炸不治消失 |
| tanh' ≈ 0.5 | 训练中的平均示意值 | 最大值其实是 1（z=0 时） |
