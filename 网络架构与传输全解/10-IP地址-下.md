# 10 — IP 地址（下）——子网划分与 CIDR

## 学习目标

- 理解子网划分的动机——为什么有类编址行不通
- 掌握子网掩码的工作原理和 CIDR 表示法
- 能手算给定 CIDR 的子网范围、可用 IP 数量和起止地址
- 知道 RFC 1918 定义的三个私网保留段
- 对 IPv6 有基本认知（128 位、冒号分隔、解决地址枯竭）

---

## 10.1 问题——一个网络 1600 万台设备，谁用得了？

第 09 章我们学了有类编址。A 类网络一个就能容纳约 1677 万台设备。现实中有哪个组织会在**同一个局域网**里塞 1600 万台设备？

没有。别说 1600 万，一个公司超过 200 人，C 类（254 台设备）就扛不住了。按有类编址的方案，你得跳到 B 类（65534 台），然后又浪费了 99% 的地址。

**子网划分**（subnetting）就是来解决这个问题的：**打破"A/B/C"类的固定边界，按需切分。** 你可以从一个大网络里"切"出刚好够用的小网络。就像你有 100 亩地，不需要全用来种菜——你可以划出 30 亩种菜、20 亩养鱼、50 亩盖房。

## 10.2 子网掩码——分界线的标记

### 回到门牌号类比

第 09 章我们用了门牌号的类比：IP 地址 = 网络号（楼号）+ 主机号（房间号）。关键问题是——**你怎么知道楼号到哪一列结束、房间号从哪一列开始？**

`192.168.1.10` 这个地址，网络号可能是 `192`（如果是一栋超级大楼）、可能是 `192.168`（中等楼）、也可能是 `192.168.1`（小楼）。到底哪个？**子网掩码说了算。**

### 子网掩码长什么样

子网掩码也是 32 位二进制。规则很简单：**网络号部分全 1，主机号部分全 0**。

```
IP 地址：   192.168.1.10  →  11000000 10101000 00000001 00001010
子网掩码：  255.255.255.0 →  11111111 11111111 11111111 00000000
                              ←— 网络号 = 24 位 —→ ← 主机号 8 位→
```

把 IP 地址和子网掩码做**按位与**（AND）运算——任何位与 1 保持不变，与 0 变成 0——就得到了网络号：

```
  11000000 10101000 00000001 00001010  (192.168.1.10)
& 11111111 11111111 11111111 00000000  (255.255.255.0)
= 11000000 10101000 00000001 00000000  (192.168.1.0)
```

所以 `192.168.1.0` 就是这个网络的网络号。

> ❌ **常见误解**：以为子网掩码只能长成 `255.255.255.0` 这样。实际上掩码的 1 不一定要正好停在一个字节的边界上。比如 `255.255.255.128`（二进制 `11111111 11111111 11111111 10000000`，25 个 1）也是合法的掩码。
>
> ✅ **正确理解**：子网掩码的 1 必须是**连续**的（从左边开始不能断开）。`11111111 11111111 11111111 10000000`（25 个连续的 1）合法；`11111111 00111111 11111111 00000000`（1 中间断了）不合法。

## 10.3 CIDR 表示法——斜杠数字

每次写 `255.255.255.0` 既啰嗦又容易出错。**CIDR**（Classless Inter-Domain Routing，无类域间路由）表示法用一个斜杠数字解决问题：

```
192.168.1.10 / 255.255.255.0  →  192.168.1.10/24
```

斜杠后面的数字就是**子网掩码中 1 的个数**（也叫**前缀长度**）。`/24` 表示前 24 位是网络号，后 8 位是主机号。

常用对应关系：

| CIDR 表示 | 子网掩码 | 主机号位数 | 地址总数 | 可用地址数（减去网络地址和广播地址） |
|-----------|----------|-----------|---------|-------------------------------------|
| /8 | 255.0.0.0 | 24 位 | 约 1677 万 | 约 1677 万 - 2 |
| /16 | 255.255.0.0 | 16 位 | 65536 | 65534 |
| /24 | 255.255.255.0 | 8 位 | 256 | 254 |
| /25 | 255.255.255.128 | 7 位 | 128 | 126 |
| /26 | 255.255.255.192 | 6 位 | 64 | 62 |
| /28 | 255.255.255.240 | 4 位 | 16 | 14 |
| /30 | 255.255.255.252 | 2 位 | 4 | 2 |
| /32 | 255.255.255.255 | 0 位 | 1 | 1（主机路由，只有一个地址）|

> ⚠️ **记住**：可用地址数 = 2^(主机号位数) - 2。减掉的 2 是**网络地址**（主机号全 0）和**广播地址**（主机号全 1）。这是新手最容易忘记的地方。

## 10.4 手工计算训练——三道练习题

光看原理不够，你必须亲自算一遍。下面三道题从易到难，每题都有详细推导。

### 练习题一：入门级 —— 192.168.1.0/24

**问题**：算出 `192.168.1.0/24` 的网络地址、广播地址、可用 IP 范围和数量。

**推导过程**：

1. `/24` = 前 24 位是网络号，后 8 位是主机号
2. 网络地址 = 主机号全 0 = `192.168.1.0`
3. 广播地址 = 主机号全 1 = `192.168.1.255`
4. 可用 IP 范围：`192.168.1.1` ~ `192.168.1.254`
5. 可用 IP 数量：2⁸ - 2 = 256 - 2 = **254**

> ❌ **常见错误**：说"`/24` 有 256 个可用 IP"。你忘了减掉网络地址（`192.168.1.0`）和广播地址（`192.168.1.255`）。这两地址不能分配给任何设备，所以可用的只有 254 个。

---

### 练习题二：进阶级 —— 10.0.0.0/16

**问题**：算出 `10.0.0.0/16` 的网络地址、广播地址、可用 IP 范围和数量。

**推导过程**：

1. `/16` = 前 16 位是网络号，后 16 位是主机号
2. 子网掩码 = `255.255.0.0`
3. 网络地址 = `10.0.0.0`
4. 广播地址 = `10.0.255.255`（主机号 16 位全 1）
5. 可用 IP 范围：`10.0.0.1` ~ `10.0.255.254`
6. 可用 IP 数量：2¹⁶ - 2 = 65536 - 2 = **65534**

> 💡 **想多一点**：你注意到了吗？`10.0.0.0/16` 的广播地址是 `10.0.255.255` 而不是 `10.0.0.255`。因为 `/16` 的主机号是后 16 位（第三、四段），所以全 1 是把第三、四段都变成 255。这一点 `/24` 不明显是因为 `/24` 的边界刚好在字节边界上。

---

### 练习题三：高手级 —— 172.16.0.0/20（手把手教学）

**问题**：算出 `172.16.0.0/20` 的子网掩码、网络地址、广播地址、可用 IP 范围和数量。

这道题 `/20` 不是 8 的倍数，不能直接套 `/24` 或 `/16` 的经验。我们一步一步来。

**第 1 步：写出子网掩码**

`/20` = 前 20 位是 1，后 12 位是 0：
```
11111111 11111111 11110000 00000000
```

转十进制：
- 第一段 `11111111` = 255
- 第二段 `11111111` = 255
- 第三段 `11110000` = 240
- 第四段 `00000000` = 0

所以子网掩码 = **`255.255.240.0`**

**第 2 步：写出网络地址**

IP 地址 `172.16.0.0` 的第三段是 `0`。子网掩码第三段是 `240`（二进制 `11110000`）。

IP 第三段 `0` = `00000000`。和掩码 `11110000` 做 AND：
```
  00000000
& 11110000
= 00000000 = 0
```

所以网络地址 = `172.16.0.0`（第三段保持 0）

**第 3 步：计算广播地址**

广播地址 = 网络号保持，主机号全变成 1。

网络号的二进制：
```
172     . 16      . 00000000 . 00000000
10101100 . 00010000 . 0000xxxx . xxxxxxxx
                    ← 网络号 20 位 → ← 主机号 12 位 →
```

把主机号 12 位全变成 1：
```
172     . 16      . 00001111 . 11111111
10101100 . 00010000 . 00001111 . 11111111
```

转十进制：`172.16.15.255`

所以广播地址 = **`172.16.15.255`**

**第 4 步：可用 IP 范围**

- 起始：`172.16.0.1`（网络地址 + 1）
- 结束：`172.16.15.254`（广播地址 - 1）

**第 5 步：可用 IP 数量**

主机号 12 位，2¹² - 2 = 4096 - 2 = **4094**

**最终答案汇总**：

| 项目 | 值 |
|------|-----|
| 子网掩码 | 255.255.240.0 |
| 网络地址 | 172.16.0.0 |
| 广播地址 | 172.16.15.255 |
| 可用 IP 范围 | 172.16.0.1 ~ 172.16.15.254 |
| 可用 IP 数量 | 4094 |

> 💡 **想多一点**：为什么第三段广播地址是 `15` 而不是 `255`？因为 `/20` 的切割线穿过了第三段。第三段（8 位）里前 4 位属于网络号，后 4 位属于主机号。网络号那 4 位（都是 0）不变，主机号那 4 位全变 1 后，第三段就变成了 `00001111` = 15。初学者最容易在非 8 位对齐的 CIDR 上翻车——我们刻意选了 `/20` 来练这条"切割线穿过中间"的情况。

## 10.5 私网 IP（RFC 1918）——为地球省地址

IPv4 总共约 43 亿个地址。把全世界的设备（手机、电脑、服务器、IoT 设备、汽车……）都算上，早就远远超过了。互联网工程任务组（IETF）在 1996 年就想到了这个危机，于是发布了 **RFC 1918**，划出三段"仅供内部使用"的地址：

| 私网保留段 | CIDR 表示 | 地址范围 | 相当于 |
|-----------|----------|---------|--------|
| 10.0.0.0 | 10.0.0.0/8 | 10.0.0.0 ~ 10.255.255.255 | 一个 A 类 |
| 172.16.0.0 | 172.16.0.0/12 | 172.16.0.0 ~ 172.31.255.255 | 16 个连续 B 类 |
| 192.168.0.0 | 192.168.0.0/16 | 192.168.0.0 ~ 192.168.255.255 | 256 个连续 C 类 |

### 私网 IP 怎么重复使用？

你家路由器用 `192.168.1.0/24`，隔壁邻居家也用 `192.168.1.0/24`。两个网络里都有 `192.168.1.10` 这台设备。它们不会冲突——因为**私网地址不出家门**。

所有私网设备访问公网时，都走**NAT**（Network Address Translation，网络地址转换），把私网地址翻译成路由器那**唯一一个公网 IP**。第 12 章我们会详细拆解 NAT 的转换过程。

> ❌ **错误认知**：以为电脑的私网 IP（比如 `192.168.1.100`）可以直接和公网上的服务器通信。你的私网 IP 只有你家的路由器认识。公网路由器不认识 `192.168.x.x`——它们看到这个地址会直接丢弃。
>
> ✅ **正确理解**：私网设备通过 NAT 借用路由器的公网 IP 和外界通信。公网服务器回复时也是先把数据发给你的路由器（公网 IP），路由器再根据 NAT 表转回你的私网 IP。你是隐身在路由器后面的。

## 10.6 IPv6 速览——真正的解决方案

子网划分和 NAT 只是"续命方案"。真正解决 IPv4 地址枯竭的是 **IPv6**（Internet Protocol version 6）。

### 核心差异

| 对比维度 | IPv4 | IPv6 |
|---------|------|------|
| 地址长度 | 32 位 | **128 位** |
| 地址数量 | 约 43 亿 | 约 3.4×10³⁸（读作：340 涧） |
| 表示法 | 点分十进制 `192.168.1.1` | 冒号分隔十六进制 `2001:0db8:85a3:0000:0000:8a2e:0370:7334` |
| 地址数量类比 | 地球上的每一粒沙子都不够分 | 地球上每一粒沙子可以分到几万亿个 |
| 头部复杂度 | 可变长，有校验和 | 固定 40 字节，无校验和（交给链路层和上层） |
| NAT | 普遍需要 | **不需要**（地址足够，每台设备都可以有公网 IP） |
| 广播 | 有 | **取消广播**，用组播替代 |

### IPv6 地址缩写规则

完整 IPv6 地址写出来很长：`2001:0db8:0000:0000:0000:ff00:0042:8329`。可以缩写：

1. 每段前导零可省略：`2001:db8:0:0:0:ff00:42:8329`
2. 连续的全零段可以用 `::` 代替（**但只能一次**）：`2001:db8::ff00:42:8329`

`::1` 就是 IPv6 的环回地址（相当于 IPv4 的 `127.0.0.1`）。

### IPv6 普及现状

全球 IPv6 部署率已经超过 40%，中国三大运营商基本都支持 IPv6。但你日常接触的可能还是 IPv4 为主——因为大量老旧应用和设备只认 IPv4。过渡期内，双栈（同时支持 IPv4 和 IPv6）是主流方案。

> 💡 **想多一点**：IPv5 去哪了？IPv5 确实存在过——它是 1979 年提出的"互联网流协议"（Internet Stream Protocol），实验性质，从未大规模部署。为了避免混淆，新协议直接跳过 5，叫 IPv6。这不是版本号乱来，而是历史遗留。

本书以 IPv4 为主线展开（因为还在大规模使用），IPv6 在涉及地址、路由、ICMPv6 等章节时会做对比说明。

## 10.7 验证方法

**主练习题**：给定 `192.168.100.0/26`，算出：

1. 子网掩码
2. 网络地址
3. 广播地址
4. 可用 IP 范围
5. 可用 IP 数量

<details>
<summary>点击查看答案（先自己算，再看答案）</summary>

1. **子网掩码**：`/26` = 前 26 位是 1 → `11111111 11111111 11111111 11000000` → `255.255.255.192`
2. **网络地址**：192.168.100.0（题目已给）
3. **广播地址**：最后一段 `0` = `00000000`，把后 6 位（主机号）全变成 1 → `00111111` = 63 → `192.168.100.63`
4. **可用 IP 范围**：`192.168.100.1` ~ `192.168.100.62`
5. **可用 IP 数量**：2⁶ - 2 = 64 - 2 = **62**

</details>
