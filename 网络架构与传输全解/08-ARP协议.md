# 08 — ARP 协议：IP 地址怎么变成 MAC 地址

## 学习目标

- 理解 ARP 协议的完整工作流程：请求→响应→缓存
- 能用 `arp -a` 查看本机 ARP 缓存
- 知道 ARP 欺骗的风险和防护方向
- 理解跨网段通信时 ARP 请求的是网关 MAC 而不是目标 MAC

---

## 8.1 问题——知道 IP 但不知道 MAC

回顾一下我们学过的：

- 第 06 章：局域网内的每一帧必须有**目的 MAC 地址**才能发出
- 你马上要在第 09 章学到：IP 地址是跨网络通信用的

现在有个问题：**PC-A 知道 PC-B 的 IP 地址（比如 `192.168.1.5`），但要发数据需要对方的 MAC 地址。MAC 地址去哪找？**

这就是 ARP（Address Resolution Protocol，地址解析协议）要解决的问题——**把 IP 地址翻译成 MAC 地址**。

---

## 8.2 ARP 请求——在局域网里大声问

场景：PC-A（IP = `192.168.1.3`，MAC = `AA:AA:AA:AA:AA:AA`）想和 PC-B（IP = `192.168.1.5`，MAC 未知）通信。

### 步骤 1：PC-A 发 ARP 请求

PC-A 先查看自己的 **ARP 缓存**（`arp -a`）——没有 `192.168.1.5` 的记录。

于是 PC-A 在局域网内发送一个 ARP 请求，以太网帧长这样：

```
目的 MAC：FF:FF:FF:FF:FF:FF    ← 广播地址！所有设备都会收
源 MAC：  AA:AA:AA:AA:AA:AA
类型：    0x0806                ← 表示"这个帧里装的是 ARP 消息"

ARP 请求内容：
  发送方 IP：192.168.1.3
  发送方 MAC：AA:AA:AA:AA:AA:AA
  目标 IP：  192.168.1.5
  目标 MAC：  00:00:00:00:00:00  ← 不知道，填全零
```

这个帧被交换机泛洪到所有端口（还记得第 07 章吧——交换机收到广播帧 `FF:FF:FF:FF:FF:FF`，必然泛洪）。局域网内的所有设备都会收到，包括 `192.168.1.5`。

ARP 请求翻译成人话就是：**"谁是 192.168.1.5？请告诉 192.168.1.3（MAC=AA:AA:AA:AA:AA:AA）！"**

> 💡 **想多一点**：ARP 请求的目标 MAC 字段是 `00:00:00:00:00:00`（全零）。你可能觉得奇怪——为什么不直接在 ARP 消息里填上自己的 MAC？实际上，自己的 MAC 已经在以太网帧头的"源 MAC"字段里了，ARP 消息里再写一遍发送方 MAC，只是为了接收方方便——它拿到 ARP 请求后直接从 ARP 消息体里提取发送方 MAC，不用去翻帧头。

---

## 8.3 ARP 响应——只有目标回复

### 步骤 2：PC-B 收到请求，单播回复

PC-B 收到 ARP 请求，一看目标 IP = `192.168.1.5`——这就是我！于是它回复一个 **ARP 响应**：

```
目的 MAC：AA:AA:AA:AA:AA:AA    ← 单播！只发给 PC-A
源 MAC：  BB:BB:BB:BB:BB:BB
类型：    0x0806

ARP 响应内容：
  发送方 IP：192.168.1.5
  发送方 MAC：BB:BB:BB:BB:BB:BB
  目标 IP：  192.168.1.3
  目标 MAC：  AA:AA:AA:AA:AA:AA
```

翻译成人话：**"我是 192.168.1.5，我的 MAC 地址是 BB:BB:BB:BB:BB:BB！"**

注意：ARP 响应是**单播**（Unicast）——只发给 PC-A。因为 PC-B 已经从 ARP 请求里知道了 PC-A 的 MAC 地址，不需要再广播了。

### 步骤 3：PC-A 收到响应，写入缓存

PC-A 收到 ARP 响应后，把 `192.168.1.5 → BB:BB:BB:BB:BB:BB` 写入自己的 ARP 缓存。之后和 PC-B 通信就不需要再发 ARP 了，直接从缓存读。

---

## 8.4 查看和管理 ARP 缓存

ARP 缓存中的条目分两种：

- **动态条目**：通过 ARP 请求学到的，有**过期时间**（通常几十秒到几分钟），过期自动删除
- **静态条目**：手动添加的，不会过期

### 查看 ARP 缓存

**Windows（PowerShell 或 CMD）**：

```powershell
arp -a
```

输出示例：
```
接口: 192.168.1.3 --- 0x5
  Internet 地址         物理地址              类型
  192.168.1.1          00-11-22-33-44-55     动态
  192.168.1.5          bb-bb-bb-bb-bb-bb     动态
```

**Mac / Linux（bash）**：

```bash
arp -a
```

输出格式略有不同，但内容一致：IP 地址对应 MAC 地址。

### 动手验证 ARP

做一个实验来亲眼看到 ARP 的工作过程：

**Windows**：

```powershell
# 1. 先清空 ARP 缓存（需要管理员权限）
arp -d *

# 2. 确认缓存已清空
arp -a

# 3. ping 你的网关（通常是 192.168.1.1 或 192.168.0.1）
ping 192.168.1.1

# 4. 再次查看 ARP 缓存——网关的 MAC 地址出现了！
arp -a
```

**Mac / Linux（bash）**：

```bash
# 1. 删除特定条目（Linux 可能需要 sudo）
sudo arp -d 192.168.1.1     # Mac
sudo ip neigh flush all      # Linux 清空所有 ARP 缓存

# 2. 确认缓存状态
arp -a                       # Mac
ip neigh                     # Linux

# 3. ping 网关
ping -c 3 192.168.1.1

# 4. 再次查看——网关 MAC 回来了
arp -a                       # Mac
ip neigh                     # Linux
```

你亲眼看到了 ARP 协议在你面前工作——`ping` 触发 ARP 请求，ARP 响应写入缓存。

## 8.5 ARP 欺骗——中间人攻击

ARP 协议设计时没有任何身份验证——**谁回复我就信谁**。这带来了一个著名攻击：**ARP 欺骗**（ARP Spoofing / ARP Poisoning）。

### 攻击原理

```
正常情况：
  PC-B 发 ARP 响应："我是 192.168.1.5，MAC=BB"
  PC-A 信了，把缓存写成 BB

攻击情况：
  攻击者抢先发假 ARP 响应："我是 192.168.1.5，MAC=CC！"
  PC-A 信了，把缓存写成 CC → 之后给 PC-B 的数据全部发给攻击者
```

攻击者就这样变成了"中间人"：PC-A 发给 PC-B 的数据经过攻击者，攻击者可以偷看、修改——用户完全无感知。

### 安全指引

> ⚠️ **ARP 欺骗是真实存在的安全威胁**，尤其是在公共 Wi-Fi、咖啡店网络等环境。想知道怎么防的可以搜索以下关键词：
>
> - **ARP 防护** / **ARP 防火墙**：个人电脑可以安装专门的 ARP 防护软件
> - **DAI**（Dynamic ARP Inspection，动态 ARP 检测）：企业级交换机上的安全功能，交换机会检查 ARP 包的合法性，拦截可疑 ARP 响应
> - **静态 ARP 绑定**：在路由器上手动绑定 IP↔MAC，适合关键服务器
>
> 在企业网络环境下，ARP 防护一般由交换机层面统一处理——如果你在公司办公，大概率不需要自己操心。

## 8.6 跨网段通信——ARP 请求的不是目标的 MAC

这是 ARP 最容易误解的地方，我们专辟一节来讲。

### 场景

```
PC-A: 192.168.1.3  ────  网关: 192.168.1.1  ────  互联网  ────  服务器: 8.8.8.8
（同一个局域网）         （路由器的局域网口）       （不在同一个局域网！）
```

PC-A 要 `ping 8.8.8.8`。ARP 请求的是 `8.8.8.8` 的 MAC 吗？

### 答案：不是！

PC-A 先检查目标 IP `8.8.8.8` 是否在自己的网段内（通过子网掩码判断，第 09 章详解）。发现**不在同一网段**。

于是 PC-A 的正确做法是：**ARP 请求的不是 `8.8.8.8` 的 MAC，而是默认网关（`192.168.1.1`）的 MAC**。

逻辑是这样的：

1. PC-A："我不在 `8.8.8.8` 的局域网里，我唯一能接触到外界的就是网关（路由器）"
2. PC-A 发 ARP 请求："谁是 192.168.1.1？"（问网关）
3. 网关回复自己的 MAC
4. PC-A 把数据帧发到网关的 MAC 地址，由网关负责往互联网转发

> ❌ **错误认知**：ping 外网 IP（如 8.8.8.8）时，ARP 请求的是那个外网 IP 的 MAC。
>
> ✅ **正确理解**：ARP 只在局域网内有效，广播消息出不了路由器。跨网段通信时，ARP 请求的是**默认网关**（路由器）的 MAC 地址，数据先到网关，再由网关转发。

## 8.7 验证方法

按 8.4 节的步骤做这个实操：

1. `arp -d` 清缓存（或 `arp -d *`）
2. `arp -a` 确认为空
3. `ping` 你的默认网关
4. 再次 `arp -a`，看到网关 MAC 出现在缓存中

然后回答：
- 如果你 ping 一个外网地址（如 `8.8.8.8`），ARP 缓存里会多出 `8.8.8.8` 的条目吗？为什么？

## 本章术语（此术语需进附录）

| 术语 | 简要解释 |
|------|----------|
| **ARP** | Address Resolution Protocol，地址解析协议——把 IP 地址翻译成 MAC 地址 |
| **广播 MAC 地址** | `FF:FF:FF:FF:FF:FF`，发往这个地址的帧会被局域网内所有设备接收 |
| **ARP 缓存** | 本机维护的 IP↔MAC 映射表，避免每次通信都要发 ARP 请求，有过期时间 |
| **ARP 欺骗** | 攻击者发送伪造的 ARP 响应，把别人的 IP 映射到自己的 MAC 上，实现中间人攻击 |
