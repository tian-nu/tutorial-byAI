# 07 — 交换机：局域网的总机接线员

## 学习目标

- 理解 Hub（集线器）和交换机（Switch）的本质区别
- 能画出交换机 MAC 地址表的四步学习过程
- 区分半双工 / 全双工 / 泛洪 / 广播风暴这几个容易混淆的概念
- 知道广播域和 VLAN 的概念

---

## 7.1 Hub——最笨的"广播员"

在交换机出现之前，局域网用 **Hub**（集线器）连接设备。

Hub 的工作原理简单到让人无语：

```
Hub 收到一个信号 → 复制到所有其他端口 → 每个连接的主机自己判断"是不是给我的"
```

这就像公司前台收到一个包裹，不知道是给哪位员工的，于是用大喇叭对着整栋楼广播："张三的快递！张三的快递！"——所有 50 个人都听到了，但只有张三去拿。

### Hub 的两个致命问题

1. **所有端口共享带宽**：一个 100Mbps 的 Hub，4 台设备同时通信时，每台平均只有 25Mbps——而且同一时刻只能有一台设备发送数据（这叫**半双工**，Half-Duplex，一会儿解释）
2. **冲突频发**：两台设备同时发送数据 → 信号碰撞 → 两边的帧都废了 → 都得重发。这就像两个人同时拿起话筒说话，两边都听不清楚

---

## 7.2 半双工 vs 全双工——这里容易搞混

在继续讲交换机之前，我们先定清两个关键概念：

| 模式 | 英文 | 含义 | 生活类比 |
|------|------|------|----------|
| **半双工** | Half-Duplex | 同一时刻**只能收或只能发**，不能同时进行 | 对讲机——你按住说话时听不到对方，放开才能听 |
| **全双工** | Full-Duplex | 同一时刻**可以同时收发** | 打电话——双方可以同时说话，互不干扰 |

- Hub 连接的所有设备工作在半双工模式——有人发言时别人只能听
- 交换机连接的两台设备工作在全双工模式——A 给 B 发数据的同时，B 也可以给 A 发数据

> ❌ **错误认知**：Hub 也能同时收发——只是慢一点。
>
> ✅ **正确理解**：Hub 根本不允许同时收发，所有端口共享同一根"车道"，同时说话 = 碰撞 = 两败俱伤。交换机每个端口有独立的收发通道，端口之间不冲突。

---

## 7.3 交换机聪明在哪——MAC 地址表

交换机比 Hub 多一个关键能力：**它有一张"谁在哪个端口"的列表**。

这张表叫 **MAC 地址表**（MAC Address Table），也叫 CAM 表（Content Addressable Memory Table）。它的结构很简单：

```
MAC 地址            端口号
00:1A:2B:3C:4D:5E → 端口 1
00:AA:BB:CC:DD:EE → 端口 3
00:11:22:33:44:55 → 端口 7
```

有了这张表，交换机就不再盲目广播了——它看帧里的"目的 MAC 地址"，查表，直接送到对应端口。

---

## 7.4 MAC 地址表是怎么学出来的——四步时序

来看一个具体场景：PC-A（MAC = AA，接在端口 1）第一次要给 PC-B（MAC = BB，接在端口 2）发数据。

```
        ┌──────────┐
PC-A ───┤ 端口1     │
MAC=AA  │          │
        │  交换机   │
PC-B ───┤ 端口2     │
MAC=BB  │          │
        │  (刚开机， │
PC-C ───┤ 端口3   MAC地址表为空)
MAC=CC  └──────────┘
```

### 步骤 1：PC-A 发送帧

PC-A 构造一个以太网帧：`目的MAC=BB | 源MAC=AA | 数据...`，发送到端口 1。

### 步骤 2：交换机学习源 MAC

交换机收到帧后，第一件事不是查目的地——而是**先学来源**：

> "哦，MAC=AA 的设备在端口 1。"

交换机把 `AA → 端口1` 写入 MAC 地址表。

### 步骤 3：查表找不到目的 → 泛洪

交换机查表找 `MAC=BB`——表里没有（刚开机）。

交换机做**泛洪**（Flooding）：把帧复制到**除了来源端口**以外的所有端口（端口 2 和端口 3）。

> ⚠️ 重要区分：**泛洪（Flooding）是正常行为**——交换机不知道目的 MAC 在哪，把帧发给所有人，这是设计之内的操作。

### 步骤 4：目标回复，交换机学习

PC-B 收到帧后回复：`目的MAC=AA | 源MAC=BB | 数据...`。

交换机收到回复帧后，又先学来源：`BB → 端口2`。

然后查表找 `MAC=AA`——这次表里已经有了（端口 1），直接转发到端口 1。PC-C 这次收不到这个帧，因为交换机已经知道 AA 在哪。

**从此之后**，AA ↔ BB 之间的通信全部精准转发，不再泛洪。其他主机不再被打扰。

---

## 7.5 容易混淆的四个概念——一定要分清楚

这里最容易概念打架，我们用对比表来理清：

| 概念 | 英文 | 定义 | 正常/异常 |
|------|------|------|-----------|
| **半双工** | Half-Duplex | 同一时刻只能收或发 | 正常模式（Hub 下） |
| **全双工** | Full-Duplex | 同一时刻可以同时收发 | 正常模式（交换机下） |
| **泛洪** | Flooding | 交换机不知道目的 MAC 在哪，复制到所有端口 | ✅ 正常行为 |
| **广播风暴** | Broadcast Storm | 网络中大量广播帧循环转发，导致网络瘫痪 | ❌ 异常现象 |

> ❌ **错误认知**：看到交换机大量转发就以为网络出问题了——这肯定是广播风暴。
>
> ✅ **正确理解**：泛洪是交换机在"不知道目的地时的正常探索行为"，学完之后就不再泛洪。广播风暴是循环广播导致的网络瘫痪——**需要排查拓扑中的环路**。两者表现相似但本质完全不同。

> 💡 **想多一点**：广播风暴通常由网络环路（switch A 连 switch B，B 又连回 A）触发。一个广播帧在环路里被无限复制，几秒内就能把交换机 CPU 打满。STP（生成树协议，Spanning Tree Protocol）就是专门解决这个问题的——它自动检测并阻断环路。第 37 章会讲到。

## 7.6 MAC 地址表的老化

MAC 地址表里的条目不是永久的。如果一条记录在 **约 300 秒（5 分钟）**内没有活动，交换机会自动删除它。

为什么需要老化？

- 设备可能换了端口（你拔下笔记本从会议室搬到工位）
- 设备可能已关机
- 表空间有限，新设备要进来

## 7.7 广播域和 VLAN（先混个脸熟）

交换机所有端口默认在同一个**广播域**（Broadcast Domain）里——任何一个端口发出的广播帧，其他所有端口都能收到。

这有时候不太理想。比如公司财务部和研发部用同一台交换机，财务的广播流量研发部其实不需要看到。

**VLAN**（Virtual LAN，虚拟局域网）就是解决这个问题的：**在一台物理交换机上，逻辑划分出多个独立的小局域网**。VLAN 10（财务）和 VLAN 20（研发）之间的广播互不相通——就像物理上是同一栋楼，但财务部在 A 栋。这只是一个一句话简介，第 37 章会详细展开。

## 7.8 验证方法

拿出一张纸，画出下面这个场景的完整四步时序：

- 两台 PC 刚启动，交换机 MAC 地址表为空
- PC-A（MAC=AA，端口 1）向 PC-B（MAC=BB，端口 2）发送第一帧
- PC-B 回复

在你的图上标注每一步：① 交换机学到了什么？② 帧去了哪些端口？③ 泛洪发生在哪一步？

能独立画出来，你就真正理解了交换机。

## 本章术语（此术语需进附录）

| 术语 | 简要解释 |
|------|----------|
| **Hub（集线器）** | 最基础的网络连接设备，收到信号复制到所有端口，所有端口共享带宽 |
| **交换机（Switch）** | 有 MAC 地址表的智能连接设备，能精准转发帧到目标端口，支持全双工 |
| **MAC 地址表** | 交换机内部维护的映射表，记录"哪个 MAC 地址在哪个端口"，通过学习源 MAC 自动建立 |
| **泛洪（Flooding）** | 交换机不知道目的 MAC 在哪时，将帧复制到除来源端口外的所有端口——正常行为 |
| **广播域** | 能收到同一个广播帧的所有设备的集合——交换机所有端口默认在同一个广播域 |
| **半双工（Half-Duplex）** | 同一时刻只能收或发——像对讲机 |
| **全双工（Full-Duplex）** | 同一时刻可同时收发——像打电话 |
| **广播风暴（Broadcast Storm）** | 广播帧在网络环路中被无限复制导致的网络瘫痪——异常现象 |
| **VLAN** | 虚拟局域网，在一台物理交换机上划分多个逻辑隔离的局域网 |
