# 23-搜索：让用户找到内容

> "你写了一篇关于'Node.js 中间件'的深度好文，但用户只能一页一页翻列表来找——这和在大海捞针有什么区别？搜索功能不是锦上添花，而是必需品。本章我们给文章列表加上搜索，用 `LIKE` 做模糊匹配，关键词能搜标题也能搜内容。更重要的是，搜索和分页必须同时工作——搜索结果的第 2 页，不能是全部数据的第 2 页。"

---

## 一、目标与完成效果

**一句话目标**：在文章列表接口中添加搜索功能，通过 `search` 查询参数接收关键词，用 `LIKE` 模糊匹配文章的标题和内容，搜索和分页协同工作。

**完成后的可观测效果**：
- `GET /api/articles?search=Node` — 返回标题或内容中包含 "Node" 的文章，含分页。
- `GET /api/articles?search=Node&page=1&limit=5` — 搜索 + 分页同时生效，`pagination.total` 是搜索结果的总数。
- `GET /api/articles?search=`（空搜索词）— 返回全部文章（等同于无搜索）。
- `GET /api/articles`（不传 search）— 返回全部文章（搜索是可选的）。
- 搜索词自动去空格，空字符串不触发搜索。
- 搜索结果按创建时间倒序排列。

## 三、分步操作

### 步骤 1：搜索的餐厅比喻

搜索就像你去餐厅问服务员：

> 你："有没有带'辣'字的菜？"
> 服务员翻开菜单，把所有菜名或描述里带"辣"字的挑出来，给你一份小清单。

**SQL 中对应的就是 `LIKE`**：

```sql
SELECT * FROM articles WHERE title LIKE '%辣%' OR content LIKE '%辣%';
```

- `%` 是**通配符**（代表"任意字符，任意长度"）。
- `LIKE '%辣%'` = "包含'辣'字"。
- `LIKE '辣%'` = "以'辣'字开头"。
- `LIKE '%辣'` = "以'辣'字结尾"。

---

### 步骤 2：理解 `LIKE` 的三种通配符模式

| 模式 | SQL 示例 | 含义 | 匹配 "麻辣火锅" 吗？ | 匹配 "辣椒炒肉" 吗？ | 匹配 "水煮肉片" 吗？ |
|------|----------|------|:---:|:---:|:---:|
| 包含 | `LIKE '%辣%'` | 任意位置包含"辣" | ✅ | ✅ | ❌ |
| 开头 | `LIKE '辣%'` | 以"辣"开头 | ❌ | ✅ | ❌ |
| 结尾 | `LIKE '%辣'` | 以"辣"结尾 | ❌ | ❌ | ❌ |

> `%` 代表 0 个或多个任意字符。`_`（下划线）代表恰好 1 个任意字符，但本教程只用 `%`。

**本教程使用 `LIKE '%关键词%'`——前后都加 `%`，表示"包含"语义。** 用户搜 "Node"，应该能搜到 "Node.js 入门" 和 "学习 Node"。

### 步骤 3：修改 `GET /api/articles`——动态拼接搜索 SQL

打开 `routes/articles.js`，修改 `GET /` 路由：

```javascript
// GET /api/articles — 获取所有文章（支持分页 + 搜索 + 评论数）
router.get('/', (req, res) => {
    // ========== 1. 解析查询参数 ==========
    let page = parseInt(req.query.page) || 1;
    let limit = parseInt(req.query.limit) || 10;
    const search = req.query.search ? req.query.search.trim() : '';

    // ========== 2. 参数校验 ==========
    if (page < 1) page = 1;
    if (limit < 1) limit = 1;
    if (limit > 100) limit = 100;

    const offset = (page - 1) * limit;

    // ========== 3. 动态构建 SQL ==========
    // 基础 SQL 片段（不含 WHERE 搜索条件）
    const baseFrom = `
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
    `;

    // 搜索条件
    let searchCondition = '';
    const params = [];

    if (search) {
        searchCondition = 'WHERE (articles.title LIKE ? OR articles.content LIKE ?)';
        const searchPattern = `%${search}%`;
        params.push(searchPattern, searchPattern);
    }

    // ========== 4. 查询总数（搜索结果的总数） ==========
    const countSql = `SELECT COUNT(*) AS total ${baseFrom} ${searchCondition}`;
    const { total } = db.prepare(countSql).get(...params);

    // ========== 5. 查询数据 ==========
    const selectSql = `
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        ${baseFrom}
        ${searchCondition}
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `;

    const dataParams = [...params, limit, offset];
    const articles = db.prepare(selectSql).all(...dataParams);

    // ========== 6. 计算总页数 ==========
    const totalPages = Math.ceil(total / limit);

    // ========== 7. 返回结果 ==========
    res.json({
        success: true,
        data: {
            articles: articles
        },
        pagination: {
            page: page,
            limit: limit,
            total: total,
            totalPages: totalPages
        }
    });
});
```

**关键点解析**：

| 步骤 | 在做什么 | 为什么 |
|------|----------|--------|
| `req.query.search.trim()` | 获取搜索词并去空格 | 用户可能输入 `" Node "`（前后有空格），`trim()` 去掉 |
| `search ? ... : ''` | 空字符串不触发搜索 | 用户不传 `search` 参数时，`undefined` 变成 `''` |
| 动态拼接 SQL | 根据是否有搜索词决定是否拼 `WHERE` | 空搜索词时返回全部文章 |
| `%${search}%` 在 JS 中拼接 | 把 `%` 放在值外面 | 参数化查询中 `%` 是普通字符，必须拼在值上 |
| `...params` 展开 | 把搜索参数展开传入 `.get()` / `.all()` | `better-sqlite3` 接受可变参数 |
| 总数查询也用搜索条件 | `COUNT(*)` 也带 `WHERE` | 搜索结果的 `total` 应该是搜索结果的总数，不是全部文章的总数 |

> 🔥 **魔鬼细节**：参数化查询中，`%` 必须拼在**值外面**，不能放在 SQL 字符串里。为什么？因为 `db.prepare('... WHERE title LIKE ?').get('%Node%')` 中，`?` 会被当作**普通字符串**处理，`%` 不会有通配符语义。而 `db.prepare('... WHERE title LIKE ?').get('%' + search + '%')` 中，`%` 在传入参数之前就已经和值拼接好了——这才是正确的做法。

### 步骤 4：`...params` 展开语法详解

```javascript
const params = ['%Node%', '%Node%'];
// 等价于：
db.prepare(sql).get('%Node%', '%Node%');

// 如果加上 limit 和 offset：
const dataParams = [...params, limit, offset];
// 等价于：
db.prepare(sql).all('%Node%', '%Node%', 10, 0);
```

`...`（展开运算符）把数组"拆开"成独立的参数。这是 JavaScript ES6 的语法，在 `better-sqlite3` 中非常实用——因为 `?.?.?` 的参数数量是可变的（有搜索时 4 个参数，无搜索时 2 个参数）。

### 步骤 5：搜索 + 分页的协同——为什么 `COUNT` 也要带搜索条件？

**❌ 错误做法**：总数用全量，数据用搜索。

```javascript
// ❌ 错误：总数查的是全部文章，数据查的是搜索结果
const { total } = db.prepare('SELECT COUNT(*) AS total FROM articles').get();  // 总数 = 100
const articles = db.prepare('SELECT ... WHERE title LIKE ? ... LIMIT 10 OFFSET 0').all(...);  // 搜索结果 = 15 条
```

这样 `totalPages = Math.ceil(100 / 10) = 10`，但实际搜索结果只有 15 条（2 页就够了）。用户翻到第 3 页时发现是空的——因为"第 3 页"在搜索结果中根本不存在。

**✅ 正确做法**：总数和数据都用搜索条件。

```javascript
// ✅ 正确：总数和数据都带搜索条件
const { total } = db.prepare('SELECT COUNT(*) AS total FROM articles WHERE ...').get(...);  // 总数 = 15
const articles = db.prepare('SELECT ... WHERE ... LIMIT 10 OFFSET 0').all(...);  // 搜索结果 = 15 条
```

这样 `totalPages = Math.ceil(15 / 10) = 2`，分页按钮只显示 2 页——完美。

> 🔥 **魔鬼细节**：这是新手最容易犯的错误——总数和数据的查询条件不一致。**搜索时，`total` 必须是搜索结果的 `total`，不是全部数据的 `total`。**

### 步骤 6：`LIKE` 在 SQLite 中的大小写敏感性

SQLite 的 `LIKE` 对 ASCII 字符**默认大小写不敏感**：

| 搜索词 | 匹配 "Node.js" | 匹配 "node.js" | 匹配 "NODE.JS" |
|--------|:---:|:---:|:---:|
| `%Node%` | ✅ | ✅ | ✅ |

**但注意**：SQLite 的 `LIKE` 对 Unicode 字符（如中文、日文）**大小写敏感**。这是因为 SQLite 默认的 `LIKE` 不处理 Unicode 的大小写折叠。不过中文没有大小写，所以不影响本教程。

> 如果你需要真正的全语言大小写不敏感搜索，可以用 `COLLATE NOCASE` 或 SQLite 的 FTS5 全文搜索扩展。

### 🤔 想多一点：`LIKE '%keyword%'` 的性能问题

`LIKE '%keyword%'` 在 SQLite 中**无法使用普通索引**（因为前后都有通配符，数据库不知道从哪里开始匹配）。当数据量很大时（百万级），搜索会逐行扫描——非常慢。

**解决方案（预告）**：

- **SQLite FTS5**（Full-Text Search 5）：SQLite 内置的全文搜索引擎，比 `LIKE` 快 100 倍以上。它会把文章内容拆成词条建立索引，搜索时直接查索引。
- **Elasticsearch**：专业的搜索引擎，适合超大规模数据。
- 本教程暂不深入——`LIKE` 在万级数据量下完全够用。等你数据量到十万级别再考虑优化。

> 🤔 **想多一点**：为什么 `LIKE 'Node%'`（前缀匹配）可以用索引，但 `LIKE '%Node%'`（包含匹配）不能用？因为索引是按字母顺序排列的——数据库知道"以 Node 开头"的数据在索引的哪个位置，但不知道"包含 Node"的数据在哪里——它们可能散落在任何位置。所以只能全表扫描。

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| 搜索没结果，但明明有包含关键词的文章 | `%` 没拼对，或 `%` 放在了 SQL 字符串里而不是参数里 | 确认 `searchPattern = '%' + search + '%'` 在 JS 中拼接，不在 SQL 中 |
| 搜索时 `total` 还是全部文章的总数 | `COUNT(*)` 查询没有带搜索条件 | `COUNT` 查询也要动态拼接 `WHERE` 子句 |
| 搜索时翻到第 2 页，结果和"不搜索"的第 2 页一样 | 分页的 `total` 用的全量数据，而不是搜索结果 | 同上 |
| 传入 `search=%`（只有通配符）→ 返回全部 | `%` 在 `LIKE` 中是通配符，匹配所有 | 正常现象——`LIKE '%%%'` 匹配所有行。如果你不想这样，可以对搜索词做特殊字符过滤 |
| `search` 参数包含特殊字符（如 `_`、`\`） | `_` 在 `LIKE` 中也是通配符（匹配单字符） | 生产环境需要对 `_` 和 `%` 做转义（`\_`、`\%`），本教程暂不处理 |
| 中文搜索大小写敏感？ | SQLite 的 `LIKE` 对 Unicode 大小写敏感，但中文无大小写 | 不影响 |

### `blog-backend/routes/articles.js`（本章修改：完整搜索 + 分页）

```javascript
const express = require('express');
const router = express.Router();
const { db } = require('../database/db');
const { authenticate } = require('../middleware/auth');
const AppError = require('../utils/AppError');

// ========== 文章 CRUD 接口（数据库版） ==========

// GET /api/articles — 获取所有文章（支持分页 + 搜索 + 评论数）
router.get('/', (req, res) => {
    // 解析查询参数
    let page = parseInt(req.query.page) || 1;
    let limit = parseInt(req.query.limit) || 10;
    const search = req.query.search ? req.query.search.trim() : '';

    // 参数校验
    if (page < 1) page = 1;
    if (limit < 1) limit = 1;
    if (limit > 100) limit = 100;

    const offset = (page - 1) * limit;

    // 动态构建 SQL
    const baseFrom = `
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
    `;

    let searchCondition = '';
    const params = [];

    if (search) {
        searchCondition = 'WHERE (articles.title LIKE ? OR articles.content LIKE ?)';
        const searchPattern = `%${search}%`;
        params.push(searchPattern, searchPattern);
    }

    // 查询总数（搜索结果的总数）
    const countSql = `SELECT COUNT(*) AS total ${baseFrom} ${searchCondition}`;
    const { total } = db.prepare(countSql).get(...params);

    // 查询数据
    const selectSql = `
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        ${baseFrom}
        ${searchCondition}
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `;

    const dataParams = [...params, limit, offset];
    const articles = db.prepare(selectSql).all(...dataParams);

    // 计算总页数
    const totalPages = Math.ceil(total / limit);

    res.json({
        success: true,
        data: {
            articles: articles
        },
        pagination: {
            page: page,
            limit: limit,
            total: total,
            totalPages: totalPages
        }
    });
});

// GET /api/articles/:id — 获取单篇文章
router.get('/:id', (req, res) => {
    const { id } = req.params;

    const selectArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author,
            (SELECT COUNT(*) FROM comments WHERE comments.article_id = articles.id) AS comment_count
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `);

    const article = selectArticle.get(id);

    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    res.json({
        success: true,
        data: article
    });
});

// POST /api/articles — 创建文章（需登录）
router.post('/', authenticate, (req, res) => {
    const { title, content } = req.body;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const author_id = req.user.id;
    const now = new Date().toISOString();

    const insertArticle = db.prepare(`
        INSERT INTO articles (title, content, author_id, created_at, updated_at)
        VALUES (?, ?, ?, ?, ?)
    `);

    const result = insertArticle.run(title, content, author_id, now, now);

    const newArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(result.lastInsertRowid);

    res.status(201).json({
        success: true,
        data: newArticle
    });
});

// PUT /api/articles/:id — 更新文章（只能改自己的）
router.put('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const { title, content } = req.body;
    const userId = req.user.id;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }
    if (article.author_id !== userId) {
        throw new AppError('只能修改自己的文章', 403);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(title, content, now, id);

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});

// DELETE /api/articles/:id — 删除文章（只能删自己的，级联删除评论）
router.delete('/:id', authenticate, (req, res) => {
    const { id } = req.params;
    const userId = req.user.id;

    const article = db.prepare('SELECT * FROM articles WHERE id = ?').get(id);
    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    if (article.author_id !== userId) {
        throw new AppError('只能删除自己的文章', 403);
    }

    // 先删除文章的所有评论（级联删除）
    db.prepare('DELETE FROM comments WHERE article_id = ?').run(id);

    // 再删除文章本身
    db.prepare('DELETE FROM articles WHERE id = ?').run(id);

    res.status(204).send();
});

module.exports = router;
```

| 术语 | 英文 | 通俗解释 | 本章出现位置 | 字面陷阱 |

## 八、已知坑点与禁止事项

1. **`%` 必须拼在值外面**：`LIKE '%keyword%'` 中，`%` 是 SQL 的语法元素，不是参数。参数化查询中 `?` 是普通字符串占位符，必须把 `%keyword%` 当作一个完整的字符串传入。正确做法：`const pattern = '%' + keyword + '%'`，然后传入 `pattern`。

2. **搜索和分页的 `COUNT` 必须一致**：`SELECT COUNT(*)` 的 `WHERE` 条件必须和 `SELECT *` 的 `WHERE` 条件完全一致。否则 `total` 和实际数据对不上，翻页会出问题。

3. **空搜索词不拼接 `WHERE`**：`search.trim()` 为空时，不要拼接 `WHERE` 子句。拼接了 `WHERE title LIKE '%%' OR content LIKE '%%'` 虽然结果一样，但会导致不必要的全表扫描。

4. **`LIKE` 中的 `_` 也是通配符**：`_` 匹配恰好 1 个任意字符。如果用户的搜索词中包含 `_`（如搜索 "hello_world"），`LIKE '%hello_world%'` 会把 `_` 当作通配符——匹配 "helloXworld"、"helloYworld" 等。生产环境需要用 `ESCAPE` 子句处理。

5. **`LIKE` 在 SQLite 中默认大小写不敏感（仅 ASCII）**：对于 a-z 字母，`LIKE '%node%'` 能匹配 "Node.js"。但对于 Unicode 字符（如中文、日文），大小写敏感。本教程纯中文 + 英文搜索，不影响。
