# 12 — NAT——为什么你家 WiFi 只有一个公网 IP

## 学习目标

- 理解 IPv4 地址枯竭的背景下，NAT 为什么是"续命神器"
- 能完整描述 NAT 转换的全过程——从私网发出到收到回复
- 理解 NAPT（端口多路复用）怎么用一个公网 IP 服务多台设备
- 知道为什么 P2P 有时"打不通"，以及内网穿透的基本思路
- 能用命令查看自己的私网 IP 和公网 IP

---

## 12.1 场景——一栋办公楼共用一个前台电话

想象你在一栋有 500 人的办公楼里工作。这栋楼只有**一部对外电话**，电话号码是 `021-88888888`。所有员工要打外线电话，都只能通过这部电话。

这怎么可能？500 个人共用一部电话？

秘密在于**分机号**。大楼内部的电话系统给每人一个分机号——你是 101 号，同事是 102 号。你打电话出去时，前台电话帮你"冒名顶替"：对方看到的来电显示是 `021-88888888`，但内部系统记录着"这次通话来自分机 101"。对方打回来时，前台根据通话记录，自动转接给 101 号分机。

这就是 **NAT**（Network Address Translation，网络地址转换）的精确类比。

---

## 12.2 为什么需要 NAT——43 亿不够分

第 10 章讲过，IPv4 一共约 43 亿个地址。这是一个硬上限——就像电话号码只有固定的位数，位数决定了最多有多少个号码。

全球的手机、电脑、服务器、智能电视、IoT 设备早就超过了 43 亿。按理说，IPv4 地址应该早就不够分配了。但互联网还能正常运行，靠的就是 NAT——**让成百上千台设备共享一个公网 IP**。

NAT 不是 IPv4 设计时的计划，而是上世纪 90 年代为了"续命"想出来的巧妙方案。它和 CIDR（第 10 章）一起，把 IPv4 地址枯竭危机推迟了几十年。

## 12.3 NAT 转换过程——一个具体的例子

假设你家是这样的网络：

```
你家局域网 (私网 192.168.1.0/24)

  笔记本             手机              电视
192.168.1.10     192.168.1.20     192.168.1.30
     |                |                |
     └────────────────┼────────────────┘
                      |
               ┌──────┴──────┐
               │  你家路由器   │
               │ 私网: 192.168.1.1
               │ 公网: 203.0.113.5  ← 唯一公网 IP
               └──────┬──────┘
                      |
            ══════════╪══════════
                      |    互联网
                      |
              ┌───────┴───────┐
              │ Web 服务器      │
              │ 93.184.216.34  │
              └───────────────┘
```

现在，你的笔记本（`192.168.1.10`）想访问 Web 服务器（`93.184.216.34`）的 443 端口。

### 第 1 步：笔记本发出请求

笔记本构造一个数据包：

| 字段 | 值 |
|------|-----|
| 源 IP | `192.168.1.10`（私网） |
| 源端口 | `45678`（随机选的一个端口） |
| 目的 IP | `93.184.216.34` |
| 目的端口 | `443`（HTTPS） |

这个包发给路由器。

### 第 2 步：路由器做 NAT 转换

路由器收到后，查 NAT 表，发现这是一个"新会话"。它在 NAT 表里创建一条记录：

| 私网 IP | 私网端口 | 公网 IP | 公网端口 | 目的 IP | 目的端口 |
|---------|---------|---------|---------|---------|---------|
| 192.168.1.10 | 45678 | 203.0.113.5 | **54321** | 93.184.216.34 | 443 |

注意：路由器把源 IP 从 `192.168.1.10` 换成了 `203.0.113.5`，还把源端口从 `45678` 换成了 `54321`。为什么换端口？后面讲到 NAPT 时解释。

然后把这个修改后的包发到互联网上：

| 字段 | 值（转换后） |
|------|-------------|
| 源 IP | `203.0.113.5`（公网，路由器的） |
| 源端口 | `54321`（路由器分配的） |
| 目的 IP | `93.184.216.34`（不变） |
| 目的端口 | `443`（不变） |

### 第 3 步：Web 服务器回复

Web 服务器看到的请求来自 `203.0.113.5:54321`，它完全不知道背后是一台笔记本。它回复：

| 字段 | 值 |
|------|-----|
| 源 IP | `93.184.216.34` |
| 源端口 | `443` |
| 目的 IP | `203.0.113.5` |
| 目的端口 | `54321` |

### 第 4 步：路由器收到回复，反向翻译

路由器收到回复包，查 NAT 表——目的端口 `54321` 对应的是笔记本那条记录。它把目的 IP 改回 `192.168.1.10`，目的端口改回 `45678`，然后发给笔记本。

笔记本收到回复，整个过程对它来说完全透明——它以为自己直接在和 `93.184.216.34` 通信。

> 💡 **想多一点**：你有没有想过——如果路由器断电了，NAT 表丢了怎么办？所有正在进行的连接（你的在线视频、游戏、下载）全部断掉。因为服务器下次回复时，路由器认不出 `54321` 这个端口属于谁。这就是为什么重启路由器会导致所有设备断网一瞬间。新连接可以重建（建立新 NAT 条目），但旧连接的状态随着路由器的内存一起消失了。

## 12.4 NAPT——一个公网 IP，N 台设备

上面的例子中，路由器把笔记本的源端口从 `45678` 换成了 `54321`。为什么要换？

因为如果**不换端口**，问题就来了：笔记本用端口 `45678` 发起连接，手机也用端口 `45678` 同时发起连接。路由器只有一个公网 IP，两个连接都来自同一个公网 IP 的同一个端口——服务器回复时，路由器无法区分数据应该给笔记本还是手机。

**NAPT**（Network Address and Port Translation，网络地址和端口转换），也叫**PAT**（Port Address Translation），通过给每台设备分配**不同的公网端口**来区分：

| 设备 | 私网 IP | 私网端口 | 公网端口（路由器分配） |
|------|---------|---------|---------------------|
| 笔记本 | 192.168.1.10 | 45678 | 54321 |
| 手机 | 192.168.1.20 | 45678 | 54322 |
| 电视 | 192.168.1.30 | 12345 | 54323 |

三台设备使用同一个公网 IP `203.0.113.5`，但公网端口不同。路由器收到回复时，根据目标端口就知道该还给谁。就像大楼里共用一个总机号码，但不同分机号能找不同的人。

> 你家里用的 NAT 本质上都是 **NAPT**。日常交流中大家直接说"NAT"，但严格来说你做的是端口多路复用。知道这个区别就行，不用抠字眼。

## 12.5 NAT 类型与穿透问题——为什么 P2P 有时连不上

NAT 对"从内向外"发起的连接非常友好（自动建立映射），但对"从外向内"发起的连接非常不友好——外面的设备不知道该连哪个端口。这在 P2P 场景（在线游戏的玩家直连、视频通话、BT 下载）里是个大麻烦。

### 三种 NAT 类型简表

| NAT 类型 | 规则 | 穿透难度 |
|---------|------|---------|
| **完全锥形**（Full Cone） | 内部 IP:Port → 公网 Port 的映射建立后，**任何**外部主机都可以通过这个公网 Port 连进来 | 容易 |
| **受限锥形**（Restricted Cone） | 只有内部主机**先发过数据给对方**的外部 IP，才能连进来 | 中等 |
| **端口受限锥形**（Port Restricted Cone） | 只有内部主机**先发过数据给对方 IP + 端口**的外部端点，才能连进来 | 较难 |
| **对称 NAT**（Symmetric NAT） | 同一个内部 IP:Port 访问**不同的外部目的地**，路由器会分配**不同的公网端口** | 最难 |

你能记住的重点是：**对称 NAT 最难穿透**，因为外面的人根本猜不到你的公网端口是什么（每次连不同的人，端口号都变）。如果你的网络是对称 NAT，某些 P2P 游戏、视频通话可能连不上对方。

### 内网穿透——给 NAT 打个洞

如果两台设备都在各自家的 NAT 后面，它们怎么直连？这需要**内网穿透**（NAT traversal）。

常见思路是借助一台有公网 IP 的**中转服务器**：

- **frp**（Fast Reverse Proxy）：开源内网穿透工具，支持 TCP/UDP/HTTP，可以把你家里电脑的某个端口暴露到公网
- **ngrok**：商业 / 免费的内网穿透服务，适合测试时临时暴露本地服务
- **STUN / TURN**：WebRTC 使用的穿透协议族，视频通话底层就靠它

这些工具的原理大同小异：两台 NAT 后的设备都主动连到中继服务器，服务器帮忙"介绍"彼此的地址，或者直接帮忙转发数据。本书不展开实现细节，你只要知道名字，遇到 P2P 连不上的问题时能想起"可能是 NAT 类型不兼容"。

## 12.6 查看自己的私网 IP 和公网 IP

### 私网 IP

你已经会了第 09 章的命令：

**Windows：** `ipconfig`
**Mac / Linux：** `ifconfig` 或 `ip addr show`

找到 `192.168.x.x`、`10.x.x.x` 或 `172.16-31.x.x`——这些就是你的私网 IP。

### 公网 IP

最简单的办法：

**Windows / Mac / Linux 通用：**
```bash
curl ifconfig.me
```

这个网站会直接返回你的公网 IP 地址，纯文本，没有多余内容。

> ⚠️ **公司网络注意**：如果你在公司环境里执行这个命令，返回的可能不是你电脑所在路由器的公网 IP，而是**公司出口代理的公网 IP**。整个公司可能共用一个或几个公网 IP 出口。结果虽然能拿到一个公网 IP，但它不一定是你"自己家"的那个。

其他可用的查公网 IP 服务（当 `ifconfig.me` 不通时备用）：
```bash
curl ip.sb
curl ipinfo.io/ip
curl icanhazip.com
```

### 验证 NAT 存在

对比你的私网 IP 和公网 IP：
- 如果私网 IP 是 `192.168.1.10`，公网 IP 是 `203.0.113.5`——**这就证明了 NAT 在工作**。`192.168.1.10` 是 RFC 1918 私网地址，不可能出现在公网上，你访问外部网站时对方看到的一定是路由器翻译后的公网 IP。

## 12.7 验证方法

学完这一章，你能做到以下四点吗？

1. 执行 `ipconfig`（Win）或 `ifconfig`（Mac/Linux），找到你的私网 IP
2. 执行 `curl ifconfig.me`，找到你的公网 IP
3. 解释为什么私网 IP 和公网 IP 不一样——NAT 在这个过程中做了什么
4. 口头描述：你的手机和笔记本电脑同时访问同一个网站，路由器怎么区分这两个流量（NAPT 端口映射）
