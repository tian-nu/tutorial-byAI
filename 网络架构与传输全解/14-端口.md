# 14 — 端口：一台机器上的多个"门"

## 学习目标
- 理解端口号是什么，为什么 IP 地址不够用
- 掌握端口的分类：知名端口、注册端口、动态端口
- 能说出 10+ 常见服务的默认端口
- 理解 Socket = IP + 端口的含义
- 会用命令查看本机正在监听的端口

---

## 14.1 一栋楼，很多扇门

想象你住在一栋大型写字楼里。写字楼的地址是"科技路 88 号"——这就像 **IP 地址**，快递员靠它找到这栋楼。但楼里有几十家公司，快递不能把包裹扔在大门口就走。它必须知道送到哪个房间：3 楼的 A 公司，还是 12 楼的 B 公司？

**端口号**，就是这栋楼里的房间号。IP 地址找到机器，端口号找到机器上运行的具体程序。

```
科技路88号:3楼A室  →  把包裹交给A公司的前台
192.168.1.5:80     →  把数据交给Web服务器进程
```

网络层把数据包送到目标主机，传输层再根据端口号把数据交给正确的应用程序。这就是"IP 找机器，端口找程序"。

## 14.2 端口的范围：0 到 65535

端口号是一个 **16 位无符号整数**，所以范围是 **0 ~ 65535**（2¹⁶ - 1 = 65535）。IANA（互联网号码分配机构）把这个范围分成三段：

| 范围 | 名称 | 说明 |
|------|------|------|
| 0 ~ 1023 | **知名端口（Well-known Ports）** | 系统级服务专用，绑定需要管理员/root 权限 |
| 1024 ~ 49151 | **注册端口（Registered Ports）** | 应用程序可以向 IANA 注册，普通权限可使用 |
| 49152 ~ 65535 | **动态/私有端口（Dynamic/Private Ports）** | 客户端临时使用，操作系统自动分配 |

> 💡 **想多一点**：端口 0 在 TCP/UDP 中是一个特殊值——它表示"请操作系统帮我随便选一个可用的端口"。你不会在生产代码里看到 `bind(0)`，但底层 API 允许这样用，常用于客户端让系统自动分配源端口。

## 14.3 常见端口速览

下面这些端口，如果你做后端开发或运维，迟早会天天见到：

| 端口 | 协议 | 服务 |
|------|------|------|
| 22 | TCP | SSH（远程登录） |
| 53 | TCP/UDP | DNS（域名解析） |
| 80 | TCP | HTTP（网页） |
| 443 | TCP | HTTPS（加密网页） |
| 3306 | TCP | MySQL 数据库 |
| 5432 | TCP | PostgreSQL 数据库 |
| 6379 | TCP | Redis 缓存 |
| 27017 | TCP | MongoDB 数据库 |
| 21 | TCP | FTP（文件传输，控制连接） |
| 25 | TCP | SMTP（邮件发送） |
| 110 | TCP | POP3（邮件接收） |
| 8080 | TCP | HTTP 代理/开发服务器常用 |

❌ **常见错误**：
- 把 HTTP 和 HTTPS 的端口搞反——**80 是 HTTP，443 是 HTTPS**。一个口诀：80 不加锁（明文），443 加了锁（SSL）。
- 以为"一个端口号只能被一个程序占用"——不完全对。**同一协议（TCP 或 UDP）下，一个端口同一时刻只能被一个进程绑定**。但 TCP 的 80 端口和 UDP 的 80 端口是两回事，可以分别被不同程序占用。

✅ **正确理解**：端口号 + 协议类型才唯一标识一个绑定。`TCP:80` 和 `UDP:80` 不冲突。

## 14.4 源端口 vs 目的端口

当你用浏览器访问 `https://www.example.com` 时，发生了什么？

1. 浏览器向操作系统申请一个**随机源端口**（比如 52134），这是"我的房间号"
2. 目标端口固定为 **443**（HTTPS），这是"对方的房间号"
3. 服务器回包时，把目标端口设为 52134，源端口设为 443

```
你的电脑:52134  ──────────────→  服务器:443
                                    （Nginx 在 443 端口监听）

你的电脑:52134  ←──────────────  服务器:443
```

客户端每次发起新连接，操作系统从动态端口范围里随机挑一个空闲的作为源端口。这样一台机器上可以同时开几十个浏览器标签页访问同一个网站，互不干扰——因为每个连接的**源端口不同**。

服务器端就不一样了。它必须在固定端口上"蹲守"，等客户端来敲门。你不可能让全世界用户猜今天你的 Web 服务跑在哪个端口上。

## 14.5 Socket = IP 地址 + 端口号（重点）

如果你只记住本章的一个概念，那就记这个：

> **Socket（套接字）= IP 地址 + 端口号 + 协议**

它是网络编程中最基础的抽象。你可以把 Socket 理解为"电话听筒"——拿起听筒（创建 Socket），拨号（connect），说话（send），听对方说（recv），挂断（close）。

在代码层面：

```c
// 一个 TCP Socket 由五元组唯一标识：
// (源IP, 源端口, 目的IP, 目的端口, 协议)

// 例如：
// (192.168.1.5, 52134, 93.184.216.34, 443, TCP)
```

后端开发中，你写的 `server.listen(3000)` 就是在 3000 端口上创建一个监听 Socket。客户端 `connect("server.com", 3000)` 则创建一个连接 Socket。同一个服务器端口上可以同时存在成千上万个连接 Socket——它们靠不同的**客户端 IP + 客户端端口**组合来区分。

> 💡 **想多一点**：为什么一台服务器只监听一个 80 端口，却能同时处理几万个客户端请求？因为"监听 Socket"只有一个，但每个客户端连接进来后，操作系统会创建一个新的"连接 Socket"，这个新 Socket 的四元组（客户端 IP、客户端端口、服务器 IP、服务器端口）互不相同。就像银行只有一个门牌号，但可以同时开几十个柜台窗口。

## 14.6 实战：查看本机监听端口

### Windows

打开 PowerShell 或命令提示符：

```powershell
# 查看所有 TCP 连接和监听端口（-a=所有, -n=数字形式, -o=显示进程ID）
netstat -ano

# 只看监听中的端口
netstat -ano | findstr LISTENING

# 查找特定端口（比如 443）
netstat -ano | findstr :443
```

### Linux

```bash
# 查看所有 TCP 监听端口（-t=TCP, -l=监听, -n=数字, -p=进程名）
netstat -tlnp

# 推荐使用 ss（比 netstat 更快）
ss -tlnp

# 只看某个端口
ss -tlnp | grep :443
```

### macOS

```bash
# lsof 列出打开的文件，-i 过滤网络连接
lsof -iTCP -sTCP:LISTEN -nP

# 查特定端口
lsof -i :443
```

运行这些命令后，你会看到类似这样的输出：

```
Proto  Local Address          Foreign Address        State
TCP    0.0.0.0:443            0.0.0.0:0              LISTENING
TCP    127.0.0.1:3306         0.0.0.0:0              LISTENING
```

- `0.0.0.0:443` 表示**监听本机所有 IP 地址的 443 端口**（外网可访问）
- `127.0.0.1:3306` 表示**只监听本机回环地址的 3306 端口**（只有本机能连）

这是一个重要的安全区别：数据库端口通常只绑 `127.0.0.1`，不允许外部直连。

## 14.7 小结

| 概念 | 要点 |
|------|------|
| 端口号 | 16 位，0~65535，用于区分同一台机器上的不同应用程序 |
| 知名端口 | 0~1023，系统服务专用，绑定需管理员权限 |
| 注册端口 | 1024~49151，应用程序注册使用 |
| 动态端口 | 49152~65535，客户端临时使用 |
| 源端口 vs 目的端口 | 客户端随机选源端口，服务器固定目的端口 |
| Socket | **IP + 端口 + 协议**的三元组，网络编程的基础抽象 |
| 监听地址 | `0.0.0.0` 监听所有网卡，`127.0.0.1` 只允许本机连接 |

---

## 术语表

| 术语 | 解释 |
|------|------|
| **端口号（Port Number）** | 16 位整数（0~65535），传输层用于区分不同应用程序的逻辑编号 |
| **知名端口（Well-known Port）** | 0~1023 范围的端口，由 IANA 分配给标准服务，绑定需要系统特权 |
| **Socket（套接字）** | IP 地址 + 端口号 + 协议的抽象，网络编程的基本操作单元 |
| **监听（Listening）** | 服务器在某个端口上等待客户端连接的状态 |
| **IANA** | 互联网号码分配机构，负责全球 IP 地址、端口号、协议号等资源的分配 |

## 验证方法

打开终端，执行以下命令，确认你能看到至少一个 `LISTENING` 状态的端口：

**Windows：**
```powershell
netstat -ano | findstr LISTENING
```

**Linux/macOS：**
```bash
ss -tlnp | head -20
```

如果你能认出输出中某个端口对应什么服务（比如 443 是 HTTPS，22 是 SSH），说明本章目标达成。
