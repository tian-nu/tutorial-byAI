# Ch17 · 为什么需要 RNN — 序列数据的挑战

> 所属篇：第三篇 · 预计耗时：20 分钟

MLP 处理一张图片没问题——输入固定大小，喂进去就出结果。但"我今天去看了电影，剧情很___"——下一个词是什么？你需要看完前面的词才能猜。这种"有顺序、有上下文"的数据叫**序列数据**，MLP 处理不了。这一章我们就来搞清楚：为什么 MLP 不行，到底需要什么样的模型。

---

## 为了什么（Why）

**核心痛点**：MLP 只能处理**固定大小**的输入，而且没有"记忆"机制——给它什么它就看什么，前面的输入和后面的输入对它来说是独立的。

举个反例：你想用 MLP 预测"我今天去看了电影，剧情很___"下一个词。最直白的做法是把整句话编码成一个固定向量喂进去。问题来了：

- 句子长度不固定——"剧情很"是 2 个词，"我今天去看了电影剧情很"是 8 个词，MLP 的输入维度是写死的（比如 8 维），8 个词能塞进去，10 个词就塞不下了。
- 即使硬塞进去，MLP 也把每个词当独立特征处理，**不知道"我→今天→去→看"是有顺序的**。把"我看电影"和"电影看我"喂给 MLP，它会觉得是两套特征，但顺序携带的关键信息它捕捉不到。

**这一章的目标**：搞清楚"序列数据"到底长什么样、为什么 MLP 处理不了、我们需要什么样的模型。

## 要做到（Goal）

- **输入**：理解什么是序列数据（变长、有序、有上下文）。
- **输出**：能说清楚 MLP 处理序列的两个根本缺陷。
- **成功标准**：能用一句话回答"为什么序列数据不能直接喂给 MLP"。

## 做了什么（What）

先把"序列数据"这个概念具象化——它不是抽象定义，而是一类非常常见的数据：

```
序列数据的四种典型形态
├── 文本：一句话的词序列        "我 爱 编程"
├── 语音：按时间采样的声波帧    [帧1, 帧2, ..., 帧100]
├── 股价：按时间排列的收盘价    [100.5, 101.2, 99.8, ...]
└── 视频：按时间排列的图像帧    [图1, 图2, ..., 图30]
```

### 逐组件拆解

**序列（Sequence）**：一个有序的数据点列表 `[x₁, x₂, ..., xₜ]`。关键词是"有序"——打乱顺序，含义就变了。"我爱你"和"你爱我"是两个序列，词一样、顺序不同、意思不同。

**上下文（Context）**：前面时刻的信息影响后面时刻的理解。比如"爱"这个字，在"我___编程"里大概率填"爱"，在"我___吃苹果"里也大概率填"爱"——但你必须看前面的"我"和后面的"编程/吃苹果"才能确定。"爱"的语义依赖上下文。

**变长（Variable Length）**：不同样本的长度可以不同。一句"你好"是 2 个词，一句"今天天气真好"是 5 个词。MLP 要求所有输入维度相同，所以变长本身就是个麻烦。

## 怎么算（How）

序列建模的核心公式：

```
P(xₜ | x₁, x₂, ..., xₜ₋₁)
```

读作："给定前面 t-1 个时刻的输入，预测第 t 个时刻是什么"。这就是语言模型的本质——根据历史预测未来。

### 数值小例子：用 MLP 预测下一个词

假设词表里每个词用一个 1 维数字表示（实际中是高维向量，这里简化）：

- "我" → 0.1
- "爱" → 0.5
- "编程" → 0.9

句子"我 爱 编程"想预测"编程"，MLP 的做法是：

```
输入 = [我, 爱] = [0.1, 0.5]
MLP: y = W·[0.1, 0.5] + b
目标: y ≈ 0.9 (编程)
```

看起来能跑？问题出在另一个句子上——"我 爱 你 也 爱 编程"。这里出现了**两个"爱"**：

- 第一个"爱"后面跟"你"
- 第二个"爱"后面跟"编程"

如果 MLP 只看当前输入 `xₜ = [0.5]`（"爱"），它无法区分这两个"爱"——因为输入完全一样！要正确预测，必须看"爱"前面的内容：

- "我 爱 ___" → 后面是"你"
- "也 爱 ___" → 后面是"编程"

MLP 没有记忆机制，看不到"爱"前面的词，自然分不清这两个"爱"。这就是 MLP 处理序列的根本缺陷——**无法利用上下文区分相同输入的不同含义**。

### MLP 处理变长序列的另一个坑

假设你硬要 MLP 处理变长，最朴素的做法是"补零对齐"：

```
句子1: "我 爱 编程"        → [0.1, 0.5, 0.9, 0.0, 0.0]   # 补2个0
句子2: "你 也 爱 看 编程"  → [0.3, 0.4, 0.5, 0.7, 0.9]   # 不用补
```

但补零的位置 MLP 当成"正常输入"参与计算，会污染结果。而且最大长度一旦确定，超过的句子就被截断——信息丢失。

## 怎么用（Use）

代码文件：`深度学习从0到Transformer教程/code/ch17_sequence_intro.py`

关键片段：

```python
import numpy as np

# 不同长度的句子，MLP 无法用固定维度处理
sentence1 = [1, 2, 3]           # 3 个词
sentence2 = [1, 2, 3, 4, 5]     # 5 个词

# MLP 的输入维度是写死的，比如 3 维
mlp_input_dim = 3

# 句子1 能直接塞进去
print(f"句子1 长度 {len(sentence1)}，匹配 MLP 输入维度 {mlp_input_dim}: OK")

# 句子2 塞不进去——要么补零要么截断，都会丢信息
print(f"句子2 长度 {len(sentence2)}，超出 MLP 输入维度 {mlp_input_dim}: 需要补零或截断")

# 演示 MLP 无法区分两个"爱"
def mlp_predict(x, W, b):
    """最简 MLP：y = W·x + b"""
    return W @ x + b

W = np.array([[1.0]])  # 1维->1维
b = np.array([0.0])

ai_alone = np.array([0.5])  # "爱" 这个词
print(f"\n两个'爱'的输入都是: {ai_alone}")
print(f"MLP 对两个'爱'的预测完全一样: {mlp_predict(ai_alone, W, b)}")
print("→ MLP 无法区分上下文不同的同一个词")
```

## 想多一点

> 能不能用 MLP + 滑动窗口处理序列？
>
> 答案是：**可以，但有大局限**。比如用窗口大小为 3 的 MLP 预测下一个词，每次看 3 个词预测第 4 个。
>
> 问题在于：窗口大小是**固定**的，模型最多只能"记住"3 个词的上下文。如果一句话的关键信息在第 1 个词，而当前要预测的词离它 50 个词远，3 窗口 MLP 完全看不到——它无法记住远超窗口的上下文。
>
> 这正是 RNN 要解决的核心问题：**用隐藏状态当记忆，理论上能记住任意长的上下文**。下一章我们就看 RNN 怎么做到这一点。

## 易错点预警

- ❌ 把序列当无序集合处理（认为"我爱编程"和"编程爱我"是一回事）→ ✅ 正确：**序列的顺序携带关键信息**，打乱顺序含义改变。这是序列数据与集合数据的本质区别。
- ❌ 用固定窗口 MLP 处理长序列（觉得窗口开大点就行）→ ✅ 正确：**窗口大小固定就无法记住远超窗口的上下文**，需要 RNN/LSTM/Transformer 等有记忆或全局注意力的模型。
- ❌ 以为补零对齐就解决了变长问题 → ✅ 正确：补零会污染计算，且最大长度外的信息会丢失。RNN 通过逐时间步处理天然支持变长。

## 章末小结

| 概念 | 一句话解释 | 易错点 |
|------|-----------|--------|
| 序列数据（Sequence Data） | 有顺序的数据点列表 | 打乱顺序含义改变 |
| 上下文（Context） | 前面信息影响后面理解 | MLP 没有记忆，捕捉不到上下文 |
| 变长输入（Variable Length） | 不同样本长度不同 | MLP 要求固定维度，变长需特殊处理 |
| 序列建模（Sequence Modeling） | P(xₜ \| x₁,...,xₜ₋₁) | 核心是"用历史预测未来" |
| MLP 的局限 | 无记忆、固定输入维度 | 滑动窗口只能记窗口内的信息 |
