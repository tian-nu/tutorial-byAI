# 09 — IP 地址（上）——IPv4 的出身与结构

## 学习目标

- 理解 IPv4 地址的二进制本质，知道 32 位从哪里来

- 能说出 5 种特殊 IP 地址的含义和用途
- 能用命令查看本机 IP 地址

## 9.1 你家门牌号是怎么设计的

想象你搬到一座新城市。打开手机地图，所有地址都长这样：省 → 市 → 区 → 街道 → 门牌号。你立刻就发现了一个聪明的设计——**地址是分层的**。

快递员不需要认识每栋楼，他只需要按层级来：
1. 先看"省"，把包裹送到那个省的分拣中心
2. 再看"市"，在省内继续分拣
3. 再看"区""街道""门牌号"，逐层缩小范围

如果全中国所有地址都是一个无规律的编号（比如"第 82374912 号建筑"），快递系统会立刻崩溃——没人知道这个编号在哪里。

IP 地址用了完全相同的思路。它把 32 位二进制数分成**两层**——前面是"网络号"（相当于"省+市+区+街道"），后面是"主机号"（相当于"门牌号"）。路由器就像快递分拣中心，只关心网络号，不关心具体门牌号。到了目标网络内部，才由交换机根据主机号找到具体设备。

## 9.2 IPv4 的本质——32 位二进制

IP 地址本身是一个**32 位的二进制数**。比如：

```
11000000 10101000 00000001 00000001
```

这就是 `192.168.1.1` 的真面目——它本来长这样，全是 0 和 1。

### 为什么用点分十进制？

32 个 0 和 1，别说普通人，就是网络工程师也很难一眼认出来。于是人们发明了**点分十进制**（dotted-decimal notation）：

1. 把 32 位分成 4 组，每组 8 位
2. 把每组的 8 位二进制转成十进制数
3. 用点（`.`）分隔

```
11000000 . 10101000 . 00000001 . 00000001
   192    .   168    .    1     .    1
```

> 💡 **想多一点**：8 位二进制能表示多少个数？每一位可以是 0 或 1，8 位就是 2⁸ = 256 种组合。所以点分十进制的每一段，范围是 0 到 255。你不会看到 `192.168.1.300` 这样的地址——300 超过了 8 位能表示的最大值 255，这是非法的 IP 地址。

### 动手验证

打开终端，试试 ping 一个 IP 和它的"域名写法"：

**Windows（PowerShell）：**
```
ping 192.168.1.1
```

**Mac / Linux（bash）：**
```bash
ping 192.168.1.1
```

不用真的能 ping 通——重点是观察：计算机内部处理的全是数字 IP，域名只是给人看的"别名"。这就像你给手机联系人存了名字，但拨号时手机拨的是号码。

## 9.3 网络号 vs 主机号——同一个局域网，同一个"楼号"

回到门牌号的类比。同一栋楼的不同房间，**楼号相同，房间号不同**。

IP 地址也是这样设计的：**同一个局域网内的所有设备，网络号部分相同，主机号部分不同**。

举个例子。你家有三台设备连在同一个 Wi-Fi 上：

| 设备 | IP 地址 | 网络号部分 | 主机号部分 |
|------|---------|-----------|-----------|
| 笔记本 | 192.168.1.10 | 192.168.1 | .10 |
| 手机 | 192.168.1.20 | 192.168.1 | .20 |
| 电视 | 192.168.1.30 | 192.168.1 | .30 |

这三台设备的前三段（`192.168.1`）完全一样——这就是它们的"楼号"（网络号）。最后一段各不相同——这就是"房间号"（主机号）。

那路由器怎么知道网络号在哪里结束、主机号从哪里开始呢？**子网掩码**来标记分界线。这个我们在第 10 章会详细展开。

> ❌ **错误认知**：以为 `192.168.x.x` 的地址是全球唯一的。你隔壁邻居家的 Wi-Fi 很可能也在用 `192.168.1.1`——这类地址是**私网地址**，只在你自己家局域网里有效，出了路由器的大门就无效了。
>
> ✅ **正确理解**：`192.168.x.x`、`10.x.x.x` 等属于私网 IP（RFC 1918 定义），只能在局域网内使用。全世界有千千万万个家庭同时用着同样的 `192.168.1.1`，但它们互不干扰——因为每个家庭的路由器通过 NAT（第 12 章详解）把私网地址翻译成了全球唯一的公网地址才发出去。

## 9.4 有类编址——互联网的"童年记忆"

1981 年，互联网还很小。设计者想了一个简单粗暴的方案，把 IPv4 地址空间切成五块：

| 类别 | 开头二进制 | 第一个字节范围 | 网络号长度 | 主机号长度 | 每个网络最多主机数 |
|------|-----------|---------------|-----------|-----------|-------------------|
| **A 类** | `0xxxxxxx` | 0 ~ 127 | 8 位 | 24 位 | 约 1677 万 |
| **B 类** | `10xxxxxx` | 128 ~ 191 | 16 位 | 16 位 | 65534 |
| **C 类** | `110xxxxx` | 192 ~ 223 | 24 位 | 8 位 | 254 |
| D 类 | `1110xxxx` | 224 ~ 239 | 组播地址（不分网络号/主机号） | — | — |
| E 类 | `1111xxxx` | 240 ~ 255 | 保留实验（不分网络号/主机号） | — | — |

注意：D 类和 E 类不参与普通的主机通信，我们只关心 A/B/C 三类。

### A 类地址——给"超级大客户"的

如果一个组织拿到了 A 类地址（比如 `10.0.0.0`），它的网络号只有 8 位（第一个字节），剩下的 24 位全是主机号。这意味着这一个网络里可以放**约 1600 万台设备**。

现实中什么组织会有 1600 万台设备在同一个局域网？**没有。** 这就是有类编址最大的问题——浪费极其严重。

### B 类地址——还是太大

B 类网络号 16 位，主机号 16 位，最多 65534 台设备。对于一个大学或大企业来说也偏多，但还是比 A 类合理一点。

### C 类地址——太小了

C 类网络号 24 位，主机号 8 位，最多 254 台设备（为什么不是 256？主机号全 0 是网络地址，全 1 是广播地址，这两个不能用）。一个小公司可能刚好够，超过 254 台设备就得上 B 类——又跳到 65534，太浪费了。

> 💡 **想多一点**：有类编址就像一家餐厅只卖三种套餐——儿童餐（C 类，254 个座位）、家庭餐（B 类，65534 个座位）、宴会厅（A 类，1677 万个座位）。你是一个 300 人的公司，儿童餐坐不下，但你得买一个宴会厅。这种浪费在上世纪 90 年代互联网爆发时变得不可接受。于是 CIDR（无类域间路由）诞生了——相当于餐厅改成了"自助按需取量"，你要多少座位就给你多少。第 10 章我们会详细讲 CIDR 怎么精准分配地址。

### 有类编址已经被 CIDR 取代了，为什么还学它？

两个原因：
1. **面试爱考**——网络工程师面试题里，"A 类地址范围""B 类地址开头几位"是经典考点
2. **理解动机**——理解了有类编址的浪费，你才会真正理解 CIDR 和子网划分为什么是"救世主"。知其然也知其所以然。

## 9.5 特殊 IP 地址——这些地址不能随便用

IPv4 地址空间里留了几块"特区"，每一块有特殊用途。记住它们，因为日常排错经常会遇到。

### 9.5.1 网络地址——主机号全 0

`192.168.1.0`（主机号部分全是 0）**不代表某一台设备**，而是代表"`192.168.1` 这整个网络"。你不能把 `192.168.1.0` 配给一台电脑——它是网络的"名字"，不是设备的"名字"。

### 9.5.2 广播地址——主机号全 1

`192.168.1.255`（主机号部分全是 1）是**广播地址**。给这个地址发数据，网络内所有设备都会收到。同样，不能给设备配置广播地址。

> ❌ **常见错误**：算可用 IP 数量时忘了减掉网络地址和广播地址。比如 `/24` 子网有 256 个地址，但只有 254 个可以分配给设备。我们第 10 章练习时会反复强调这一点。

### 9.5.3 回环地址——127.0.0.1

`127.0.0.1` 是回环地址（loopback address）。给这个地址发数据，数据不会离开你的电脑网卡——**你自己发，自己收**。

它有什么用？测试本机网络协议栈是否正常工作。如果你 `ping 127.0.0.1` 能通，说明你电脑的 TCP/IP 协议栈安装正确。如果这个都不通，你的网卡驱动或者协议栈配置出了问题。

实际上整个 `127.0.0.0/8` 这个范围（`127.0.0.0` 到 `127.255.255.255`）全是回环地址，只是大家约定俗成都用 `127.0.0.1`。

### 9.5.4 0.0.0.0——来者不拒

`0.0.0.0` 有两个完全不同的含义，取决于出现的场景：

**场景一：作为目标地址——"我还没拿到 IP"**

设备在 DHCP（自动获取 IP）过程中，还没有被分配 IP 地址时，会用 `0.0.0.0` 作为源地址发送请求。意思就是"我现在还没有地址，但我需要你给我一个"。

**场景二：服务端监听——"来者不拒"**

当你启动一个 Web 服务器并让它"监听 0.0.0.0"时，这不是在说"监听一个叫 0.0.0.0 的地址"。而是说——**接收来自本机所有网络接口的连接**。

好比你在店门口挂一块"来者不拒"的牌子——不管客人从正门、侧门还是后门进来，你都接待。服务器监听 `0.0.0.0` 就是挂这样一块牌子：不管请求从哪个网卡（Wi-Fi、有线、虚拟网卡）进来，照单全收。

如果服务器只监听 `127.0.0.1`，那只有本机自己发的请求能被接收——相当于关起门来自己跟自己玩。如果你监听 `192.168.1.100`，那就只有发到这个特定 IP 的请求才被接收。

> 💡 **想多一点**：你可能会问，服务器为什么不直接监听它的实际 IP 而要监听 `0.0.0.0`？因为一台服务器可能有多个 IP——Wi-Fi 网卡一个、有线网卡一个、Docker 虚拟网卡一个。如果每个服务都要手动指定监听哪个 IP，运维会疯掉。`0.0.0.0` 是"全都要"的简便写法。

## 9.6 查看本机 IP 地址

马上动手，看看你自己电脑的网络配置。

**Windows（PowerShell / CMD）：**
```
ipconfig
```

你会看到一大串输出。找到"IPv4 地址"那一行——那就是你电脑当前的 IP。你可能还会看到"默认网关"（Default Gateway）——那是你家路由器的地址，通常是 `192.168.1.1` 或 `192.168.0.1`。

**Mac / Linux（bash）：**
```bash
ifconfig
```
或者（更现代的命令）：
```bash
ip addr show
```

Mac 用户注意：较新的 macOS 版本中 `ifconfig` 可能需要完整路径 `/sbin/ifconfig`。如果提示 `command not found`，试试 `ip addr show`。

### 怎么判断哪部分是网络号、哪部分是主机号？

看**子网掩码**（Subnet Mask）。`ipconfig` 或 `ifconfig` 的输出里紧挨着 IP 地址的那一串（比如 `255.255.255.0`）就是子网掩码。它告诉你网络号和主机号的分界线在哪。如果你的 IP 是 `192.168.1.10`，掩码是 `255.255.255.0`，那么网络号是 `192.168.1`，主机号是 `10`。

子网掩码的详细计算，我们第 10 章会展开。

## 9.7 题外话——MTU 与分片（为第 32 章排错埋种子）

在网络世界里，不是你想发多大的包就能发多大的包。每一段物理链路都有一个**最大传输单元**（MTU，Maximum Transmission Unit）——就是这一跳能承载的最大数据包尺寸。

### 以太网的 MTU 典型值：1500 字节

你家里的网线（以太网）的 MTU 通常是 1500 字节。如果 IP 层要发一个 4000 字节的数据包，超过了 1500，怎么办？**切成碎片**——这就叫**IP 分片**（fragmentation）。

路由器把 4000 字节切成 3 片（1500 + 1500 + 剩下的），每一片加上 IP 头部，单独发送。到了目的地再拼回去。

### 为什么不直接切？——PMTUD

现实中路由器其实**不想帮你切**。切包消耗 CPU、容易丢片（丢一片整个包作废）、而且某些防火墙直接丢弃分片。

于是有了 **PMTUD**（Path MTU Discovery，路径 MTU 发现）：发送方在 IP 头部设置"禁止分片"标志（DF flag），然后探测整条路径上最小的 MTU，主动把自己的包控制在那个尺寸以内。这样就不用麻烦中间路由器帮你切了。

你不需要现在就完全搞懂 PMTUD——第 32 章（排错篇）我们会回到这个话题，讲"为什么网页能打开但 SSH 连不上"这种疑难杂症时，MTU 往往是隐藏元凶。

## 9.8 验证方法

学完这一章，你能做到以下四点吗？

1. 把任意一个点分十进制 IPv4 地址手写出它的 32 位二进制形式（比如 `10.0.0.1` → `00001010 00000000 00000000 00000001`）
2. 说出你的电脑当前 IP 地址，并指出网络号和主机号部分
3. 解释 `127.0.0.1` 和 `0.0.0.0` 分别代表什么
4. 说出有类编址 A/B/C 三类各自的主机号位数和每网络最大主机数

如果都能做到，你对 IPv4 地址的理解已经比大部分开发者都扎实了。

## 本章术语（此术语需进附录）

| 术语 | 简要解释 |
|------|----------|
| **IPv4** | Internet Protocol version 4，互联网协议第 4 版，使用 32 位地址，是当前互联网最广泛使用的网络层协议 |
| **点分十进制** | dotted-decimal notation，把 32 位二进制分成 4 组 8 位，每组转十进制后加点分隔的写法（如 192.168.1.1） |
| **网络号** | IP 地址中标识"属于哪个网络"的前半部分，同一局域网内所有设备的网络号相同 |
| **主机号** | IP 地址中标识"网络内哪台设备"的后半部分，同一局域网内每台设备的主机号不同 |
| **有类编址** | classful addressing，1981 年的 IP 地址分类方案，把地址分为 A/B/C/D/E 五类，因浪费已被 CIDR 取代 |
| **回环地址** | loopback address，127.0.0.1（整个 127.0.0.0/8 范围），发给自己的数据不经过网卡，用于测试本机协议栈 |
| **0.0.0.0** | 两种含义：① 设备无 IP 地址时的占位源地址；② 服务端监听所有网络接口（来者不拒） |
| **MTU** | Maximum Transmission Unit，最大传输单元，链路层能承载的最大数据包尺寸（以太网典型值 1500 字节） |
| **PMTUD** | Path MTU Discovery，路径 MTU 发现机制，发送方探测端到端路径最小 MTU 以避免分片 |
