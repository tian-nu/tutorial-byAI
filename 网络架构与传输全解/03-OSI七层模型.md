# 03 — OSI 七层模型：网络的"金字塔"

## 学习目标

- 理解分层思想——为什么要分层、怎么分层
- 能按顺序说出 OSI 七层的名称和每层的一句话核心职责
- 理解封装与解封装过程，能画出简图
- 知道每层数据单元的名称（PDU：段→包→帧→比特）

---

## 3.1 为什么要分层——拆复杂为简单

你可能玩过乐高。一座乐高城堡不是"刷"一下出来的，而是：地基 → 城墙 → 塔楼 → 屋顶，一层一层搭。

计算机网络也一样。从物理信号到网页显示，这中间的复杂度太高了。如果全揉在一起，你改一行网卡驱动代码可能就让微信登录崩了——这种耦合方式在实际工程中不可接受。

分层的核心好处：

1. **把大问题拆成小问题**：物理层只管 0 和 1，传输层只管丢不丢包，各自专注
2. **每层独立演进**：物理层从铜线升级到光纤，上层 TCP 一行代码不用改。就像你从 4G 换到 5G，微信本身的聊天功能不需要更新
3. **标准化接口**：只要上下层之间的接口不变，每一层内部可以随便换实现

## 3.2 OSI 七层逐个看

OSI（Open Systems Interconnection，开放系统互连）模型由 ISO 在 1984 年提出。我们把七层从下往上走一遍，每层配一个生活类比：

### 第 1 层：物理层（Physical Layer）

- **核心职责**：在物理介质上传输比特流——就是把 0 和 1 变成电信号、光信号、无线信号发出去
- **生活类比**：**邮递员的摩托车**。邮递员不管信里写的啥、不管信封地址对不对——他只负责把信从 A 点运到 B 点
- **关键词**：电压、频率、光脉冲、双绞线、光纤、无线电

### 第 2 层：数据链路层（Data Link Layer）

- **核心职责**：在同一个局域网内，把数据从一块网卡可靠地传到另一块网卡
- **生活类比**：**同一栋写字楼的收发室**。收发室只管楼内各公司的信件分发，不看地址属于哪个城市（那是邮局的事）
- **关键词**：MAC 地址、帧（Frame）、交换机、ARP

### 第 3 层：网络层（Network Layer）

- **核心职责**：跨不同网络进行路由和寻址——决定数据走哪条路从源到目的地
- **生活类比**：**邮局分拣中心**。分拣员看包裹上的城市名："去广州的走京广线，去上海的走京沪线"
- **关键词**：IP 地址、路由器、路由表、分片

### 第 4 层：传输层（Transport Layer）

- **核心职责**：提供端到端（进程到进程）的可靠或不可靠传输服务
- **生活类比**：**快递保价 vs 普通包裹**。保价（TCP）＝每个环节确认、丢件赔偿、保证送到；普通包裹（UDP）＝扔出去，丢了不管
- **关键词**：TCP、UDP、端口号、重传、流量控制

### 第 5 层：会话层（Session Layer）

- **核心职责**：在通信双方之间建立、管理和终止会话
- **生活类比**：**微信视频通话的完整流程**：拨号（建立会话）→ 接通 → 通话中（维持会话）→ 挂断（终止会话）。如果中途网络断开，会话层负责恢复而不是让你重新拨一次
- **关键词**：会话建立、会话恢复、同步点

### 第 6 层：表示层（Presentation Layer）

- **核心职责**：数据格式转换、加密解密、压缩解压
- **生活类比**：**翻译官**。你和外商开会，翻译官把你说的中文译成英文——对方才看得懂。表示层就是把应用数据"翻译"成网络能传输的标准格式
- **关键词**：编码转换（ASCII/UTF-8）、加密（TLS/SSL）、压缩（gzip）

### 第 7 层：应用层（Application Layer）

- **核心职责**：为用户直接提供网络服务——这是离你最近的一层
- **生活类比**：**你写的书信内容本身**。信封、邮递员、分拣中心——这些底下的事你都不用管，你只关心信的内容。应用层就是你真正想传输的数据
- **关键词**：HTTP、FTP、SMTP、DNS

## 3.3 记忆口诀

从第 7 层往下到第 1 层的英文首字母：**A**pplication → **P**resentation → **S**ession → **T**ransport → **N**etwork → **D**ata Link → **P**hysical

取每个单词的首字母：**A P S T N D P**

金句：**All People Seem To Need Data Processing**

或者反过来（从第 1 层到第 7 层）：**Please Do Not Throw Sausage Pizza Away**（Physical → Data Link → Network → Transport → Session → Presentation → Application）

## 3.4 封装与解封装——网络通信的核心动作

> 📊 可视化演示见本教程系列的可视化文件（对应 OSI 封装/解封装流程）

如果说 OSI 七层是"分类法"，那封装（Encapsulation）和解封装（Decapsulation）就是"怎么做"。

### 发送过程：逐层加头

```
[应用层] 你写的数据
    ↓ 交给传输层
[传输层] 在前面加 TCP头 →    |TCP头| 数据 |
    ↓ 交给网络层
[网络层] 在前面加 IP头   → |IP头| TCP头| 数据 |
    ↓ 交给链路层
[链路层] 在前面加 MAC头，尾部加校验 → |MAC头| IP头| TCP头| 数据 |FCS尾|
    ↓ 交给物理层
[物理层] 转成电信号/光信号发出去 → 101001110...
```

> ⚠️ 暂停一下：这里出现了 TCP头、IP头、MAC头——如果你还不知道它们是什么，完全正常！**第 2～4 篇会逐个详解这几种头的内部结构**。现在你只需要理解"逐层加头"这个动作——就像往包裹外面一层层套箱子。

### 接收过程：逐层剥头

接收方反过来操作：

```
[物理层] 收到信号 → 转成比特
    ↓
[链路层] 剥离 MAC头，校验帧尾FCS → |IP头| TCP头| 数据 |
    ↓
[网络层] 剥离 IP头 → |TCP头| 数据 |
    ↓
[传输层] 剥离 TCP头 → |数据|
    ↓
[应用层] 拿到原始数据
```

关键点：**每层只关心自己的头部，看不懂也不会去动其他层的头**。链路层只认 MAC 头，网络层只认 IP 头——各司其职。

> 💡 **想多一点**：封装就像俄罗斯套娃。外层套娃（MAC 头）被路由器打开后，路由器看到内层套娃（IP 头），根据 IP 头决定发往哪个方向——然后重新包一层外层的 MAC 头发出去。这就是"转发时换 MAC 头、不换 IP 头"的来源。第 09 章讲路由时会展开。

## 3.5 每层的数据单元——PDU 概念

PDU（Protocol Data Unit，协议数据单元）是每一层处理的数据单位。不同层有不同的叫法：

| OSI 层 | PDU 名称 | 说明 |
|--------|----------|------|
| 应用层 | **数据**（Data） | 你的原始信息 |
| 传输层 | **段**（Segment） | 数据 + TCP 头（或 UDP 头） |
| 网络层 | **包**（Packet） | 段 + IP 头 |
| 链路层 | **帧**（Frame） | 包 + MAC 头 + 帧尾校验 |
| 物理层 | **比特**（Bit） | 0 和 1 的序列，变成电/光/无线信号发出去 |

你不需要一次性记住全部，记住转换方向就够了：**数据→段→包→帧→比特**（从上到下），反过来就是接收过程。

## 3.6 验证方法

拿出一张白纸，做这个练习：

1. 从上到下写出 OSI 七层的名称
2. 在每层旁边写出：这一层加了什么头？
3. 在每层旁边写出：这一层的 PDU 叫什么？

例如（部分示例）：
```
应用层 → 数据
传输层 → TCP头 → 段
网络层 → IP头   → 包
...
```

能独立画完，这一章你就学透了。

## 本章术语（此术语需进附录）

| 术语 | 简要解释 |
|------|----------|
| **OSI 七层模型** | 国际标准化组织（ISO）提出的网络分层参考模型，共 7 层，是理解网络的经典框架而非实际协议 |
| **封装（Encapsulation）** | 发送数据时，每层在前一层数据前面加上自己的控制信息（头部），像一层层套箱子 |
| **解封装（Decapsulation）** | 接收数据时，每层剥离对应层添加的头部，取出交给上层的数据 |
| **PDU** | Protocol Data Unit，协议数据单元——每一层处理的数据块的统称 |
| **段（Segment）** | 传输层的 PDU，数据 + TCP/UDP 头 |
| **包（Packet）** | 网络层的 PDU，段 + IP 头 |
| **帧（Frame）** | 链路层的 PDU，包 + MAC 头 + 帧尾 |
