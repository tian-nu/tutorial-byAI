# 附录A：术语表

> 本术语表收录教程中出现的所有技术术语，按分组排列，同组内按拼音/字母顺序。每个术语标注英文原名、通俗解释、出处章节，以及容易误解的字面陷阱。

---

## 一、基础概念

| 术语 | 英文 | 通俗解释 | 出处 | 字面陷阱 |
|------|------|----------|------|----------|
| 后端 | Backend | 运行在服务器上的程序，负责处理数据、业务逻辑、与数据库交互。 | 00 | 不是"后面的端"——是"服务器端"，用户看不见的程序。 |
| 前端 | Frontend | 运行在浏览器中的程序，负责界面展示和用户交互。 | 00 | 不是"前面的端"——是"客户端"，用户能看见的界面。 |
| API | Application Programming Interface | 前后端之间的"服务员"——前端告诉他要什么，他去后厨准备，再把结果端回来。 | 03 | 不是"接口"= 硬件插口——是"程序间通信的约定"，规定了怎么请求、怎么响应。 |
| RESTful | Representational State Transfer | 一种 API 设计风格：用 URL 表示资源，用 HTTP 方法表示操作。 | 03 | 不是"休息"——REST 是缩写，核心思想是"把一切看作资源，用标准方法操作"。 |
| HTTP | HyperText Transfer Protocol | 浏览器和服务器之间通信的"语言规则"。 | 03 | 不是"超文本"= 超级文本——HyperText 指"带链接的文本"，即网页。 |
| HTTP 方法 | HTTP Method | 请求的"动作类型"：GET（看）、POST（创建）、PUT（改）、DELETE（删）。 | 05 | 不是"方法"= 函数——是"动词"，告诉服务器你要做什么操作。 |
| URL | Uniform Resource Locator | 互联网上资源的"地址"，如 `http://localhost:3000/api/articles`。 | 03 | 不是"链接"——URL 是地址，链接是可以点击的 URL。 |
| 端口 | Port | 服务器上不同程序的"门牌号"——3000 号门是 Express，3306 号门是 MySQL。 | 02 | 不是"接口"= 物理插口——是数字编号，同一台电脑上不同程序用不同端口号区分。 |
| localhost | — | 你正在用的这台电脑的网络别名，相当于"我家"。 | 02 | 不是"本地主机"= 另一台电脑——就是指你当前这台机器。 |
| JSON | JavaScript Object Notation | 一种用字符串表示数据结构的格式，前后端通用。 | 03 | 不是"JavaScript 对象"——JSON 是字符串，JS 对象是内存中的数据结构，两者用 `JSON.parse()`/`JSON.stringify()` 互相转换。 |
| 状态码 | Status Code | HTTP 响应中的三位数字，表示请求结果：200 成功、404 未找到、500 服务器错误。 | 03 | 不是"状态"= 心情状态——是"结果代码"，有标准定义。 |
| npm | Node Package Manager | Node.js 的"应用商店"——帮你下载、安装、管理第三方库。 | 01 | 不是"Node 包"——是"包管理器"，管理工具。 |
| 依赖 | Dependency | 项目用到的第三方库，列在 `package.json` 的 `dependencies` 中。 | 01 | 不是"依赖"= 不独立——是"这个项目需要这些库才能运行"。 |
| 开发依赖 | DevDependency | 只在开发/测试时需要的库，生产环境不需要，列在 `devDependencies` 中。 | 26 | 不是"开发时依赖"= 可有可无——是"开发工具链的一部分"，生产部署时不安装。 |
| 模块 | Module | Node.js 中一个文件就是一个模块，通过 `require` 引用，通过 `module.exports` 导出。 | 04 | 不是"功能模块"= 大块功能——是"一个文件"，Node.js 的基本组织单位。 |
| require | — | Node.js 中导入模块的函数，类似"我需要这个文件里的东西"。 | 04 | 不是"要求"= 命令——是"引入"，从其他文件导入功能。 |
| module.exports | — | Node.js 中导出模块的语法，类似"这个文件对外提供这些东西"。 | 04 | 不是"模块导出"= 输出——是"暴露接口"，决定其他文件能用到什么。 |
| 回调函数 | Callback | 一个函数作为参数传给另一个函数，在某个时机被调用。 | 10 | 不是"回调"= 打回去——是"回头再叫你"，异步操作完成后通知你。 |
| Promise | — | JavaScript 中处理异步操作的对象，代表"未来会有一个结果"。 | 10 | 不是"承诺"= 保证——是"未来值"，可能成功也可能失败。 |
| async/await | — | JavaScript 中写异步代码的语法糖，让异步代码看起来像同步代码。 | 11 | 不是"异步等待"——`async` 标记函数为异步，`await` 等待 Promise 的结果。 |
| try/catch | — | JavaScript 的异常处理机制：`try` 中放可能出错的代码，`catch` 中处理错误。 | 08 | 不是"尝试/捕获"= 抓东西——是"尝试运行，如果出错就捕获错误"。 |
| 环境变量 | Environment Variable | 操作系统级别的键值对配置，在 Node.js 中通过 `process.env` 访问。 | 18 | 不是"环境"= 自然环境——是"程序运行环境"的配置参数。 |
| dotenv | — | Node.js 库，把 `.env` 文件中的键值对加载到 `process.env`。 | 18 | 不是"dot" = 点号——是 "dot" + "env"，".env 文件"的意思。 |
| 进程 | Process | 正在运行的程序实例。一个 Node.js 程序 = 一个进程。 | 27 | 不是"进度"——是"运行中的程序"，操作系统分配资源的基本单位。 |
| 容器 | Container | Docker 中打包应用及其依赖的"标准化箱子"，在哪都能跑。 | 29 | 不是"容器"= 杯子——是"隔离的运行环境"，包含代码、运行时、系统工具。 |
| 镜像 | Image | Docker 中容器的"模板"——从镜像创建容器，镜像只读，容器可写。 | 29 | 不是"镜像"= 镜子里的影像——是"文件系统快照"，包含运行应用所需的一切。 |

## 二、Express 框架

| 术语 | 英文 | 通俗解释 | 出处 | 字面陷阱 |
|------|------|----------|------|----------|
| Express | — | Node.js 最流行的 Web 框架，帮你处理路由、请求、响应。 | 02 | 不是"快递"——是"快速"，Express 意为"快速构建 Web 应用"。 |
| 中间件 | Middleware | Express 的"流水线工人"，每个中间件对请求做一件事，做完传给下一个。 | 06 | 不是"中间的软件"——而是"处理请求的中间环节"。 |
| 路由 | Route | URL 路径到处理函数的映射——"这个 URL 来了，谁来处理"。 | 05 | 不是"路线"= 导航路线——是"路径的映射规则"，决定请求去哪个函数。 |
| Router | — | Express 的路由分组工具，把相关路由放在一起，方便管理。 | 05 | 不是"路由器"= 硬件——是"路由分组器"，`express.Router()` 创建一个小路由对象。 |
| 请求对象 (req) | Request Object | 包含客户端发来的所有信息：URL、方法、请求头、请求体。 | 03 | 不是"请求"= 动词——是"请求信息的容器"，一个 JS 对象。 |
| 响应对象 (res) | Response Object | 用来向客户端发送数据：设置状态码、设置响应头、发送 JSON。 | 03 | 不是"响应"= 动词——是"响应工具"，一个 JS 对象，上面有很多方法。 |
| next() | — | 中间件中的函数，调用它表示"我干完了，传给下一个中间件"。 | 06 | 不是"下一个"= 下一个中间件本身——是"调用下一个"的函数，不调就卡住。 |
| 路由参数 | Route Parameter | URL 中的变量部分，如 `/articles/:id` 中的 `:id`，通过 `req.params.id` 获取。 | 06 | 不是"路由"= 路线 + "参数"——是"URL 路径中的变量"。 |
| 查询参数 | Query Parameter | URL 中 `?` 后面的键值对，如 `?page=1&limit=10`，通过 `req.query` 获取。 | 06 | 不是"查询"= SQL 查询——是"URL 中的过滤/排序参数"。 |
| 请求体 | Request Body | POST/PUT 请求中携带的数据，如 `{ "title": "xxx" }`，通过 `req.body` 获取。 | 07 | 不是"请求"= 动词 + "体"=身体——是"请求中携带的数据内容"。 |
| express.json() | — | Express 内置中间件，解析 JSON 格式的请求体，把结果放到 `req.body`。 | 07 | 不是"JSON 中间件"——是"解析 JSON 请求体"的中间件，没有它 `req.body` 是 `undefined`。 |
| express.static() | — | Express 内置中间件，把文件夹暴露为静态文件服务——浏览器能直接访问里面的文件。 | 24 | 不是"静态"= 不动的——是"不经过代码处理的文件"，直接返回给浏览器。 |
| CORS | Cross-Origin Resource Sharing | 跨域资源共享——允许不同域名的前端访问你的 API。 | 06 | 不是"跨域"= 跨地区——是"跨域名"，浏览器安全策略限制。 |
| 404 兜底 | 404 Fallback | 放在所有路由之后的中间件，匹配所有未被处理的路由，返回 404。 | 08 | 不是"兜底"= 兜底裤——是"最后的捕获器"，没人处理的请求都到这里。 |
| 全局错误处理中间件 | Global Error Handler | 有 4 个参数 `(err, req, res, next)` 的特殊中间件，Express 根据参数数量自动识别。 | 08 | 不是"全局"= 全世界——是"应用级别"，捕获所有未被路由处理的错误。 |
| morgan | — | 第三方 HTTP 请求日志中间件，自动在终端打印每个请求的方法、路径、状态码、耗时。 | 06 | 不是人名——是"Morgan"（摩根），HTTP 日志记录器。 |

## 三、异步编程

| 术语 | 英文 | 通俗解释 | 出处 | 字面陷阱 |
|------|------|----------|------|----------|
| 同步 | Synchronous | 一行一行执行，上一行没执行完，下一行等着。 | 10 | 不是"同步"= 同时进行——恰恰相反，是"排队执行"，一个接一个。 |
| 异步 | Asynchronous | 不按顺序执行——发起一个操作后不等着，先去干别的，操作完成后再回来处理。 | 10 | 不是"异步"= 不一样——是"不阻塞"，发起操作后不等结果，继续执行。 |
| 事件循环 | Event Loop | Node.js 的核心机制——一个无限循环，不断检查"有没有事情要做"。 | 10 | 不是"事件"= 活动 + "循环"= 转圈——是"任务调度器"，决定什么时候执行什么代码。 |
| 非阻塞 I/O | Non-blocking I/O | Node.js 的招牌特性——读写文件、网络请求等操作不阻塞后续代码执行。 | 10 | 不是"非阻塞"= 不堵——是"不等待"，操作发起后立即返回，结果通过回调通知。 |
| 回调地狱 | Callback Hell | 多层嵌套的回调函数，代码像金字塔一样向右缩进，难以阅读和维护。 | 10 | 不是"地狱"= 真的地狱——是"代码可读性灾难"，深层嵌套让人抓狂。 |
| 错误优先回调 | Error-First Callback | Node.js 的回调约定：第一个参数是错误对象（没有则为 null），第二个参数才是结果。 | 10 | 不是"错误优先"= 先犯错——是"错误参数放在第一位"的编码约定。 |
| fs 模块 | File System Module | Node.js 内置的文件系统模块，用于读写文件、创建目录等。 | 11 | 不是"fs"= 什么缩写——是 "File System" 的缩写。 |

## 四、数据库

| 术语 | 英文 | 通俗解释 | 出处 | 字面陷阱 |
|------|------|----------|------|----------|
| 数据库 | Database | 结构化存储数据的"仓库"——数据存进去，随时能查出来，重启也不丢。 | 12 | 不是"库"= 图书馆——是"数据存储系统"，有组织地存数据。 |
| SQL | Structured Query Language | 操作关系型数据库的"通用语言"——增删改查都用它。 | 12 | 不是"SQL"= 一种数据库——是"语言"，操作数据库的标准化语言。 |
| SQLite | — | 零配置的轻量级数据库——整个数据库就是一个文件，不需要安装服务器。 | 12 | 不是"轻量"= 功能弱——是"嵌入式"，数据和程序在一起，适合小项目和学习。 |
| 表 | Table | 数据库中存储数据的"表格"——一行一条记录，一列一个字段。 | 13 | 不是"表"= 手表——是"二维表格"，和 Excel 的 sheet 一样。 |
| 行 | Row | 表中的一条记录——如一个用户、一篇文章。 | 13 | 不是"行"= 可以——是"一行数据"，英文 row。 |
| 列 | Column | 表中的一个字段——如 `username`、`email`。 | 13 | 不是"列"= 排列——是"一列数据"，英文 column，也叫字段（field）。 |
| 主键 | Primary Key | 表中唯一标识一条记录的列——如 `id`，每个值都是唯一的，不能为 NULL。 | 13 | 不是"主"= 主要的 + "键"= 钥匙——是"唯一标识符"，每行数据的身份证号。 |
| 外键 | Foreign Key | 指向另一张表主键的列——如 `comments.article_id` 指向 `articles.id`。 | 13 | 不是"外"= 外来的——是"跨表引用"，建立表与表之间的关联。 |
| 自增 | AUTOINCREMENT | SQLite 的关键字——插入新记录时，自动生成比上一条大的 ID。 | 13 | 不是"自增"= 自己增加——是"自动编号"，每次插入 ID 自动 +1。 |
| 约束 | Constraint | 数据库层面的"规则"——如 NOT NULL（不能为空）、UNIQUE（不能重复）。 | 13 | 不是"约束"= 限制自由——是"数据完整性规则"，防止脏数据。 |
| 索引 | Index | 数据库的"目录"——加快查询速度，但会减慢写入速度。 | 13 | 不是"索引"= 书的目录——原理一样，但数据库索引是自动维护的数据结构。 |
| 事务 | Transaction | 一组 SQL 操作打包成一个"原子操作"——要么全成功，要么全失败。 | 14 | 不是"事务"= 事情——是"原子操作组"，保证数据一致性。 |
| 参数化查询 | Parameterized Query | 用 `?` 占位符代替拼接字符串，防止 SQL 注入攻击。 | 14 | 不是"参数化"= 传参数——是"用占位符安全传值"，防注入的核心手段。 |
| SQL 注入 | SQL Injection | 攻击者通过精心构造的输入，篡改 SQL 语句，获取或破坏数据。 | 14 | 不是"注入"= 打针——是"把恶意 SQL 代码注入到正常查询中"。 |
| PRAGMA | — | SQLite 的特殊命令，用于配置数据库行为——如 `PRAGMA foreign_keys = ON` 开启外键约束。 | 13 | 不是"pragma"= 编译指令——是"数据库配置指令"，SQLite 特有。 |
| better-sqlite3 | — | Node.js 的 SQLite 驱动——同步 API，比异步驱动简单得多。 | 12 | 不是"更好的 SQLite"——是一个具体的 npm 包名，特点是同步、快速。 |
| db.prepare() | — | better-sqlite3 的方法——预编译 SQL 语句，返回一个语句对象，可复用。 | 14 | 不是"准备"= 准备一下——是"预编译"，把 SQL 编译成可重复执行的语句。 |
| db.run() | — | better-sqlite3 的方法——执行写操作（INSERT/UPDATE/DELETE），返回 `{ changes, lastInsertRowid }`。 | 14 | 不是"运行"——是"执行修改"，返回影响行数和新 ID。 |
| db.get() | — | better-sqlite3 的方法——执行查询，返回单行对象或 `undefined`。 | 14 | 不是"获取"——是"取一行"，只返回第一条匹配记录。 |
| db.all() | — | better-sqlite3 的方法——执行查询，返回所有匹配行的数组。 | 14 | 不是"全部"——是"取所有行"，返回数组。 |
| 单例模式 | Singleton Pattern | 设计模式：保证一个类只有一个实例，并提供全局访问点。在 Node.js 中，`require` 缓存天然实现单例。 | 15 | 不是"只有一个例子"——是"只有一个实例"，整个应用共享同一个对象。 |
| 连接生命周期 | Connection Lifecycle | 数据库连接从创建到关闭的整个过程。在 Express 中，连接在服务器启动时创建，关闭时释放。 | 15 | 不是"生命"——是从 `new Database()` 到 `db.close()` 的整个时间段。 |
| JOIN | — | SQL 中关联多张表查询的关键字——通过外键把两张表的数据"拼"在一起。 | 15 | 不是"加入"= 加入组织——是"关联查询"，根据外键把两张表的数据合并。 |
| INNER JOIN | — | 只返回两表都有匹配记录的行——如果 A 文章没有评论，INNER JOIN 不会返回它。 | 15 | 不是"内部"= 在里面——是"取交集"，两边都有才返回。 |
| LEFT JOIN | — | 返回左表所有行，即使右表没有匹配——如果 A 文章没有评论，评论字段为 NULL。 | 21 | 不是"左"= 方向——是"以左表为准"，左表的所有行都保留。 |
| 一对多关系 | One-to-Many | 一条"一"方记录对应多条"多"方记录——如一个用户对应多篇文章。 | 21 | 不是"一"比"多"——是"数量关系"，数据库中最常见的关系类型。 |
| 级联删除 | CASCADE DELETE | 删除父记录时，自动删除所有关联的子记录——如删除文章时自动删除其评论。 | 21 | 不是"级联"= 层级连接——是"连锁删除"，删一个带一片。 |
| LIKE | — | SQL 的模糊搜索关键字——`LIKE '%关键词%'` 表示"包含关键词"。 | 23 | 不是"喜欢"——是"模糊匹配"，`%` 是通配符。 |
| LIMIT | — | SQL 中限制返回行数的关键字——`LIMIT 10` 只返回前 10 行。 | 22 | 不是"限制"= 禁止——是"限制数量"，控制返回多少行。 |
| OFFSET | — | SQL 中分页查询的关键字，跳过前 N 行。`LIMIT 10 OFFSET 20` = 跳过前 20 行，取 10 行。 | 22 | 不是"偏移"——是"跳过"，OFFSET 的值 = (页码 - 1) × 每页条数。 |
| COUNT | — | SQL 聚合函数——统计行数，`SELECT COUNT(*) FROM articles` 返回文章总数。 | 22 | 不是"计数"= 数数——是"统计行数"，返回一个数字。 |

## 五、认证与安全

| 术语 | 英文 | 通俗解释 | 出处 | 字面陷阱 |
|------|------|----------|------|----------|
| 认证 | Authentication (AuthN) | 回答"你是谁？"——出示身份证证明身份。 | 19 | 不是"认证"= 认可证明——是"身份验证"，确认你是你声称的那个人。 |
| 授权 | Authorization (AuthZ) | 回答"你能不能干这事？"——身份证显示你满 18 岁了吗。 | 19 | 不是"授权"= 给予权力——是"权限检查"，确认你有资格做某件事。 |
| 401 Unauthorized | — | HTTP 状态码——"你还没证明你是谁"（没带 token 或 token 无效）。 | 19 | 不是"未授权"——字面意思是"未授权"，但实际含义是"未认证"，历史命名错误。 |
| 403 Forbidden | — | HTTP 状态码——"你已经证明你是谁了，但你没权限做这件事"。 | 19 | 不是"禁止"= 永远不行——是"你权限不够"，不是永远不行，是你不行。 |
| 密码哈希 | Password Hashing | 把密码变成不可逆的"指纹"。验证时，把输入的密码再哈希一次，比对指纹是否一致。 | 17 | 不是"加密"——加密可解密，哈希不可逆。 |
| bcrypt | — | 专门为密码设计的哈希算法，自带盐值和可调节的计算轮数。 | 17 | 不是通用的哈希算法（如 SHA-256）——bcrypt 专门为密码设计，故意慢。 |
| 盐值 | Salt | 哈希时混入的随机字符串，让相同密码产生不同哈希结果。 | 17 | 不是"盐"= 真的食盐——是"给哈希加佐料"，让结果独一无二。 |
| 彩虹表 | Rainbow Table | 预先计算好的"常见密码 → 哈希值"对照表。攻击者拿到哈希值后查表还原密码。 | 17 | 不是"彩虹"= 颜色丰富——是"彩虹链"攻击技术的缩写，用不同颜色区分归约函数。 |
| 明文密码 | Plaintext Password | 未经过任何处理的原始密码，如 `"mypassword123"`。 | 17 | 不是"明文"= 看得很清楚——是"原文"，未经哈希或加密。 |
| JWT | JSON Web Token | 一种自包含的令牌，由 Header + Payload + Signature 三部分组成。用于在前后端之间安全地传递用户身份信息。 | 18 | 不是"加密"——JWT 是签名的，Payload 是 Base64 编码（可解码），不是加密（不可解）。 |
| Bearer Token | — | 放在 HTTP 请求头 `Authorization: Bearer <token>` 中的令牌。谁持有这个 token，谁就被认为是该用户。 | 18 | 不是"熊"——Bearer 意为"持有者"，"持有令牌的人"。 |
| Token 过期 | Token Expiration | JWT 的 `exp` 字段标识的过期时间。过期后 `jwt.verify()` 会拒绝该 token。 | 18 | 不是"过期"= token 失效就没了——token 本身还在，只是服务器不再接受。 |
| 用户枚举攻击 | User Enumeration | 攻击者通过不同的错误信息判断哪些邮箱/用户名已注册。 | 18 | 不是"枚举"= 一一列举——是"逐个试探"，通过系统反馈确认有效账号。 |
| 409 Conflict | — | HTTP 状态码，表示请求与服务器当前状态冲突（如用户名已存在）。 | 17 | 不是"冲突"= 打架——是"你要创建的资源已经存在，无法创建第二个"。 |
| jwt.sign() | — | jsonwebtoken 库的方法——用密钥签发 JWT 令牌。 | 18 | 不是"签名"= 手写签字——是"数字签名"，用密钥生成防篡改令牌。 |
| jwt.verify() | — | jsonwebtoken 库的方法——验证 JWT 签名并解码。 | 19 | 不是"验证"= 检查就行——是"验证签名 + 解码"，两步合一。 |
| bcrypt.hash() | — | bcrypt 库的方法——对密码进行哈希，返回哈希字符串。异步方法，必须 `await`。 | 17 | 不是"哈希"= 杂凑——是"生成密码哈希值"，结果是 `$2b$10$...` 格式。 |
| bcrypt.compare() | — | bcrypt 库的方法——比对明文密码和数据库中的哈希值是否匹配。异步方法，必须 `await`。 | 18 | 不是"比较"= 简单对比——是"哈希后再对比"，内部会提取盐值重新哈希。 |

## 九、HTTP 状态码速查

| 状态码 | 英文名称 | 含义 | 教程中出现场景 |
|--------|----------|------|----------------|
| 200 | OK | 请求成功 | GET 获取数据成功 |
| 201 | Created | 资源创建成功 | POST 创建文章/用户/评论/上传文件 |
| 204 | No Content | 请求成功，但无返回内容 | DELETE 删除成功 |
| 400 | Bad Request | 客户端请求有误 | 缺少必填字段、格式错误、密码太短 |
| 401 | Unauthorized | 未认证——没带 token 或 token 无效/过期 | 没登录访问受保护接口 |
| 403 | Forbidden | 已认证但无权限——不是你的资源 | 尝试修改别人的文章 |
| 404 | Not Found | 资源不存在 | 文章不存在、接口路径不存在 |
| 409 | Conflict | 资源冲突——已存在 | 用户名/邮箱已被注册 |
| 413 | Payload Too Large | 请求体过大 | 上传文件超过 5MB |
| 500 | Internal Server Error | 服务器内部错误 | 未捕获的异常、数据库错误 |
