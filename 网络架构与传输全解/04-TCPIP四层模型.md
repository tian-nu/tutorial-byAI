## 4.1 OSI 七层为什么没成为标准

上一章我们花了很大篇幅讲 OSI 七层。你可能会问："既然七层这么漂亮，为什么实际网络不用它？"

原因有三：

1. **太完美了，也太慢了**：OSI 模型在 1984 年才正式发布，而 TCP/IP 协议族早在 1983 年就已经在 ARPANET 上跑起来了。市场不等理论家
2. **实现复杂度高**：七层每一层都有完整规范，实现一套 OSI 协议栈的成本远超 TCP/IP
3. **TCP/IP 先占市场**：UNIX 系统（包括后来的 Linux）原生支持 TCP/IP；当互联网爆发时，所有设备已经说 TCP/IP 了

一句话总结：**OSI 七层是最好的教科书，TCP/IP 四层是最广泛的工程实践**。

## 4.2 TCP/IP 四层结构

TCP/IP 模型把网络分成四层。下图展示了它和 OSI 七层的对应关系：

```
OSI 七层                    TCP/IP 四层
═══════════════          ═══════════════
 7  应用层    ┐
 6  表示层    ├──────→    应用层 (Application)
 5  会话层    ┘

 4  传输层    ──────→    传输层 (Transport)

 3  网络层    ──────→    网际层 (Internet)

 2  链路层    ┬──────→    网络接口层 (Network Access)
 1  物理层    ┘
```

你可能注意到了：TCP/IP 把 OSI 的上面三层合并为一个"应用层"，把下面两层合并为一个"网络接口层"。一种简便的对应方式：

| TCP/IP 层 | = OSI 哪些层 | 你在这一层记住一个词就够了 |
|------------|-------------|--------------------------|
| 应用层 | 会话 + 表示 + 应用 | **数据内容**（HTTP、DNS、SMTP…） |
| 传输层 | 传输层 | **可靠/不可靠**（TCP 保送到、UDP 不保） |
| 网际层 | 网络层 | **寻址路由**（IP 地址、路由器） |
| 网络接口层 | 物理 + 链路 | **局域网传输**（MAC 地址、交换机、网线） |

## 4.3 互联网协议族全景图——建立你的学习地图

在 TCP/IP 四层框架下，把各层的主要协议填进去，就得到了整本书的地图。这里列出大量协议缩写——**不要慌，这些名字先混个脸熟，不用记，从第 5 篇起我们会逐一展开讲解**：

```
┌──────────────────────────────────────────────────────┐
│ 应用层        HTTP  HTTPS  DNS  FTP  SMTP  SSH  DHCP │
│              Web  加密   域名  传文件 邮件  远程  自动  │
│                           获取IP                       │
├──────────────────────────────────────────────────────┤
│ 传输层        TCP              │        UDP          │
│          可靠传输/流量控制       │   不可靠/低延迟快速传输  │
├──────────────────────────────────────────────────────┤
│ 网际层        IP  (IPv4 / IPv6)                      │
│              ICMP (ping 用的)  ARP (IP→MAC 翻译)     │
├──────────────────────────────────────────────────────┤
│ 网络接口层    以太网  WiFi  光纤  ...                  │
│              网线    无线  光缆                        │
└──────────────────────────────────────────────────────┘
```

> 💡 **想多一点**：你可能注意到 ARP 被放在了"网际层"。严格按 OSI 逻辑，ARP 工作在局域网内、用 MAC 地址通信——它属于链路层。但 ARP 处理的是 IP 地址和 MAC 地址的映射，逻辑上又和 IP 紧密耦合。所以多数教材把它放在网际层讨论。**分层是模型不是法律，真实协议可能跨层或部分越界**，不必纠结——记住 ARP 的作用（第 08 章详解）比记住它"属于哪一层"重要得多。

## 4.5 验证方法

做这个小测验：

1. 对着 TCP/IP 四层，说出每一层至少两个协议（应用层多几个也正常）
2. 想象 ARP 协议——你在哪一层讲它？为什么？
3. 说出"网络接口层 = OSI 哪两层"、"应用层 = OSI 哪三层"

三题都答上来，这一章过关。

## 本章术语（此术语需进附录）

| 术语 | 简要解释 |
|------|----------|
| **TCP/IP 协议栈** | 互联网实际使用的协议族，四层模型：网络接口层→网际层→传输层→应用层 |
| **网络接口层** | TCP/IP 的最底层，对应 OSI 的物理层 + 数据链路层，负责局域网内帧的传输 |
| **网际层** | TCP/IP 的第二层，对应 OSI 的网络层，负责 IP 寻址和路由 |
