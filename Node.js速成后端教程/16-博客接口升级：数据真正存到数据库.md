### 步骤 2：GET /api/articles——获取所有文章（数据库版）

```javascript
// GET /api/articles — 获取所有文章（支持分页）
router.get('/', (req, res) => {
    const page = parseInt(req.query.page) || 1;
    const limit = parseInt(req.query.limit) || 10;
    const offset = (page - 1) * limit;

    // 查询文章列表（带作者名，按创建时间倒序）
    const selectArticles = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        ORDER BY articles.created_at DESC
        LIMIT ? OFFSET ?
    `);

    const articles = selectArticles.all(limit, offset);

    // 查询总数
    const { total } = db.prepare('SELECT COUNT(*) AS total FROM articles').get();

    res.json({
        success: true,
        data: {
            page: page,
            limit: limit,
            total: total,
            articles: articles
        }
    });
});
```

**对比内存版的变化**：

| 内存版 | 数据库版 |
|--------|---------|
| `articles.slice(startIndex, endIndex)` | `LIMIT ? OFFSET ?`（数据库层面分页） |
| `articles.length` | `SELECT COUNT(*) AS total`（数据库层面统计） |
| 没有作者名 | `INNER JOIN users` 带出 `author` 字段 |
| 数据在内存中，重启丢失 | 数据在 `blog.db` 文件中，重启保留 |

### 步骤 3：GET /api/articles/:id——获取单篇文章

```javascript
// GET /api/articles/:id — 获取单篇文章
router.get('/:id', (req, res) => {
    const { id } = req.params;

    const selectArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `);

    const article = selectArticle.get(id);

    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    res.json({
        success: true,
        data: article
    });
});
```

**关键点**：
- `WHERE articles.id = ?` —— 按 ID 查询。
- `.get(id)` —— 返回单行对象或 `undefined`。
- `if (!article)` —— 返回 `undefined` 时抛 404 错误。

> 🔥 **魔鬼细节**：`req.params.id` 是**字符串**（如 `"1"`），但 `better-sqlite3` 会**自动转换类型**——`WHERE id = '1'` 和 `WHERE id = 1` 在 SQLite 中等价。所以不需要 `parseInt(req.params.id)`。

**关键点**：
- `author_id` 暂时写死为 `1`（alice 用户）。在注释中标注 `TODO`，后面引入认证后会改。

> 🔥 **魔鬼细节**：`new Date().toISOString()` 返回的是 UTC 时间（末尾带 `Z`）。SQLite 的 `datetime('now')` 也返回 UTC 时间。两者格式一致，所以可以混用——应用层生成的时间戳和数据库默认时间戳不会冲突。

### 步骤 5：PUT /api/articles/:id——更新文章

```javascript
// PUT /api/articles/:id — 更新文章
router.put('/:id', (req, res) => {
    const { id } = req.params;
    const { title, content } = req.body;

    // 必填字段验证
    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(title, content, now, id);

    // changes 为 0 表示没有行被更新——文章不存在
    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    // 查询更新后的完整文章
    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});
```

**关键点**：
- `result.changes === 0` —— 判断文章是否存在。`changes` 为 0 表示 `WHERE id = ?` 没有匹配到任何行。
- 更新 `title`、`content` 和 `updated_at`。`created_at` 不更新（创建时间不应改变）。
- 更新后重新查询，返回最新的完整数据。

> 🔥 **魔鬼细节**：`db.prepare().run()` 返回的 `changes` 为 0 表示**没有行被影响**。这可能是 ID 不存在（404），也可能是新值和旧值完全一样（SQLite 的 UPDATE 在值不变时 `changes` 也为 0）。对本教程来说，两种情况都返回 404 可以接受——因为如果值没变，返回 404 提示"没找到需要更新的文章"也是合理的。

### 步骤 6：DELETE /api/articles/:id——删除文章

```javascript
// DELETE /api/articles/:id — 删除文章
router.delete('/:id', (req, res) => {
    const { id } = req.params;

    const deleteArticle = db.prepare('DELETE FROM articles WHERE id = ?');
    const result = deleteArticle.run(id);

    // changes 为 0 表示没有行被删除——文章不存在
    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    // 204 No Content：操作成功，但没有返回内容
    res.status(204).send();
});
```

**关键点**：
- `result.changes === 0` —— 判断文章是否存在。
- 删除成功返回 204（空响应体），和内存版保持一致。
- SQLite 默认开启了外键约束——如果 `comments` 表中有引用这篇文章的评论，删除会失败（`FOREIGN KEY constraint failed`）。这是一个安全特性——防止出现"孤儿评论"（评论引用了不存在的文章）。

> 如果你想在删除文章时自动删除关联的评论，可以给外键添加 `ON DELETE CASCADE`。但本教程暂时不这样做——删除文章前应该先提示用户确认。

### 🤔 想多一点：为什么 `result.changes` 有时为 0？

`db.prepare().run()` 返回的 `changes` 属性表示"受影响的行数"。以下情况 `changes` 为 0：

1. **UPDATE/DELETE 的 WHERE 条件不匹配**：如 `WHERE id = 999` 但不存在该 ID。
2. **UPDATE 的新值和旧值完全一样**：SQLite 发现不需要修改，`changes` 为 0。
3. **INSERT 失败**（如违反 UNIQUE 约束）：插入失败时 `changes` = 0，且会抛出异常。

**最佳实践**：在 UPDATE 和 DELETE 后检查 `result.changes`，如果为 0 则返回 404。

### ❌ 常见错误 → ✅ 解决方案

| 错误信息 / 现象 | 原因 | 解决 |
|-----------------|------|------|
| `POST /api/articles` 返回 `FOREIGN KEY constraint failed` | `author_id = 1` 但 `users` 表中没有 `id = 1` 的用户 | 运行 `node database/seed.js` 插入测试用户 |
| `PUT /api/articles/1` 返回 404 | 数据库中不存在 `id = 1` 的文章 | 先运行 `node database/seed.js`，或用 `GET /api/articles` 查看现有 ID |
| `DELETE /api/articles/1` 返回 `FOREIGN KEY constraint failed` | 该文章有评论引用，外键约束阻止删除 | 先删除关联的评论，或给外键加 `ON DELETE CASCADE` |
| `GET /api/articles` 返回的 `total` 是字符串而不是数字 | 用 `db.exec()` 或 `sql.js` 时类型处理问题 | 确保用 `COUNT(*)` 并在 JS 中转换：`parseInt(total)` 或解构时自动转换 |
| `result.changes` 在 UPDATE 值不变时为 0，误判为 404 | SQLite 的优化行为 | 接受这个行为——如果值没变，返回 404 提示"没找到需要更新的文章"也是合理的 |
| 创建文章后 `author` 字段为 `null` | `author_id` 对应的用户在 `users` 表中不存在 | 确认 `author_id` 的值正确，且对应 `users` 表中存在该用户 |

            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `);

    const article = selectArticle.get(id);

    if (!article) {
        throw new AppError('文章不存在', 404);
    }

    res.json({
        success: true,
        data: article
    });
});

// POST /api/articles — 创建文章
router.post('/', (req, res) => {
    const { title, content } = req.body;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    // 暂时写死 author_id 为 1（alice 用户）
    // TODO: 引入用户认证后，从 JWT 中获取当前用户 ID
    const author_id = 1;

    const now = new Date().toISOString();

    const insertArticle = db.prepare(`
        INSERT INTO articles (title, content, author_id, created_at, updated_at)
        VALUES (?, ?, ?, ?, ?)
    `);

    const result = insertArticle.run(title, content, author_id, now, now);

    const newArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(result.lastInsertRowid);

    res.status(201).json({
        success: true,
        data: newArticle
    });
});

// PUT /api/articles/:id — 更新文章
router.put('/:id', (req, res) => {
    const { id } = req.params;
    const { title, content } = req.body;

    if (!title || !content) {
        throw new AppError('标题和内容为必填字段', 400);
    }

    const now = new Date().toISOString();

    const updateArticle = db.prepare(`
        UPDATE articles 
        SET title = ?, content = ?, updated_at = ?
        WHERE id = ?
    `);

    const result = updateArticle.run(title, content, now, id);

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    const updatedArticle = db.prepare(`
        SELECT 
            articles.id,
            articles.title,
            articles.content,
            articles.author_id,
            articles.created_at,
            articles.updated_at,
            users.username AS author
        FROM articles
        INNER JOIN users ON articles.author_id = users.id
        WHERE articles.id = ?
    `).get(id);

    res.json({
        success: true,
        data: updatedArticle
    });
});

// DELETE /api/articles/:id — 删除文章
router.delete('/:id', (req, res) => {
    const { id } = req.params;

    const deleteArticle = db.prepare('DELETE FROM articles WHERE id = ?');
    const result = deleteArticle.run(id);

    if (result.changes === 0) {
        throw new AppError('文章不存在', 404);
    }

    res.status(204).send();
});

module.exports = router;

## 八、已知坑点与禁止事项

1. **`author_id` 暂时写死为 1**：在认证系统（下一阶段）引入之前，所有通过 API 创建的文章都属于 `author_id = 1`（alice）。代码中已标注 `TODO`，后面会改。

2. **`result.changes` 为 0 不一定是"不存在"**：如果 UPDATE 的新值和旧值完全一样，SQLite 会认为不需要修改，`changes` 也为 0。本教程将这种情况也当作 404 处理——因为"值没变"意味着"没有需要更新的文章"。

3. **删除有评论的文章会失败**：外键约束阻止删除被评论引用的文章。这是正确的行为——防止出现"孤儿评论"。如果需要级联删除，给外键加 `ON DELETE CASCADE`。

4. **`req.params.id` 是字符串，但 SQLite 自动转换**：`WHERE id = '1'` 和 `WHERE id = 1` 在 SQLite 中等价，所以不需要 `parseInt()`。但这是 SQLite 特有的宽松行为，其他数据库（如 PostgreSQL）会严格区分类型。

5. **时间戳统一用 ISO 8601 格式**：`new Date().toISOString()` 返回 UTC 时间，`datetime('now')` 在 SQLite 中也返回 UTC。两者格式一致，可以混用。

6. **`db.prepare()` 语句对象可以提到路由外面**：如果每次请求都 `db.prepare()`，会重复编译 SQL。更好的做法是把 `prepare` 放在路由处理函数外面，让语句对象只创建一次。但本教程为代码清晰，每个路由内部 `prepare`。
