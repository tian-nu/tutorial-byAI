# 02 — 协议：计算机之间的"语言"

## 学习目标

- 理解协议的三要素：语法、语义、时序
- 能举出生活中的协议例子并拆解其三要素
- 知道没有协议会导致什么混乱
- 认识 IETF、IEEE、W3C 三家标准化组织及其分工
- 知道 RFC 是什么

---

## 2.1 协议不是规矩，而是约定好的"语言"

我们每天都在用协议，只是你没意识到。

你拿起电话打给朋友。你不会开口就讲正事——你大概率会这样：

```
你：拨号 → 听到嘟声 → 等对方接 → "喂？"
朋友："喂？"
你："是我，跟你说个事……"
（通话内容）
你："好，那就这样，拜拜。"
朋友："拜拜。"
→ 挂断
```

这套"拨号→等待→问候→通话→道别→挂断"的流程，就是**人类打电话的协议**。没有人写成法律条文，但人人都这么做。如果你一接通就吼"你欠我的 500 块什么时候还！"然后直接挂断——这就叫**不按协议办事**，对方会懵。

计算机网络协议也是同样的道理：**两台设备要做同一件事，必须先约定好怎么做**。

---

## 2.2 协议的三个要素

RFC（后面会讲）对协议的定义包含三个要素：

| 要素 | 含义 | 寄信类比 |
|------|------|----------|
| **语法**（Syntax） | 数据的格式长什么样 | 信封格式：收件人地址在上、寄件人地址在下、邮票贴右上角 |
| **语义**（Semantics） | 每部分数据代表什么含义 | 收件人地址 = 信寄到哪；寄件人地址 = 退信退到哪 |
| **时序**（Timing） | 先做什么、后做什么、什么时候重试 | 先写地址再贴邮票，贴了邮票才能投递——顺序不能乱 |

我们再来拆解另一个例子：**微信点外卖**。

- **语法**：你在 App 上选菜品 → 下单 → 支付界面显示的金额格式（¥XX.XX）
- **语义**：¥28.00 的意思是"你要付 28 元"，不是"28 积分"也不是"28 公里"
- **时序**：你必须先下单才能支付，支付完成后商家才开始做

> ❌ **错误认知**：协议就是"规矩"——太模糊了。开车靠右是规矩，但规矩没有定义数据格式。
>
> ✅ **正确理解**：协议是**精确到比特级别的约定**。TCP 协议规定了一个 TCP 段（segment）的第 13 个字节的第 1 个 bit 是 SYN 标志——这个精确程度才叫协议。

## 2.3 没有协议的混乱世界

想象一下，如果每家汽车厂商的油门和刹车位置都不一样——有的油门在左边，有的在右边。你每换一辆车就得重新学一遍。这就是没有标准的后果。

在网络世界里，没有协议意味着：

1. **不同厂商设备互不通信**：思科交换机的"Hello"消息含义和华为交换机不同，两边永远说不上话
2. **数据无法解析**：你收到一串 `01101001`，这是"105"还是字母"i"？取决于编码协议
3. **重传时机混乱**：数据丢了，你的设备等 1 秒重传，对方等 10 秒重传——双方节奏错位

## 2.4 谁在制定这些协议——三大标准化组织

协议不能靠自觉，得有人拍板。网络世界主要有三个"立法机构"：

| 组织 | 全称 | 管什么 | 一句话管辖边界 |
|------|------|--------|----------------|
| **IETF** | Internet Engineering Task Force | TCP/IP、HTTP、DNS、TLS 等 | **管"数据怎么传"**——定义包格式、传输逻辑、应用协议 |
| **IEEE** | Institute of Electrical and Electronics Engineers | 以太网（802.3）、WiFi（802.11）等 | **管"信号怎么发"**——定义物理层和链路层的电气/光学规范 |
| **W3C** | World Wide Web Consortium | HTML、CSS、DOM、Web API | **管"网页怎么展示"**——定义浏览器渲染标准 |

一个简便记忆法：
- 你在淘宝下单 → 数据怎么加密传输到服务器？**IETF** 的 TLS 协议在管
- 你的电脑怎么连上 WiFi 路由器？**IEEE** 的 802.11 标准在管
- 淘宝网页怎么在浏览器里排列商品图片？**W3C** 的 HTML/CSS 标准在管

> 💡 **想多一点**：IETF 管数据、IEEE 管信号、W3C 管展示——三层分工对应的是 OSI 模型的三个不同层级。IETF 在上面（传输层/应用层），IEEE 在下面（物理层/链路层），W3C 在最上面（应用层呈现）。分工清晰，各管一段。

## 2.5 RFC——互联网的"事实法律"

你可能听过"RFC 793 定义了 TCP"。那 RFC 到底是个什么东西？

**RFC**（Request for Comments，征求评论稿）——这个名字有点反直觉。"征求意见"听起来像"大家来提意见啊"，但实际上，一个 RFC 一旦发布并成为标准，它就是互联网的**事实法律**。

为什么叫这个名字？历史原因：1969 年 ARPANET 时期，研究者们通过备忘录（memo）交流想法，为了显得谦虚，他们用了"Request for Comments"——大家来评论一下。但后来这些备忘录中最好的那些变成了实际标准，名字却保留了下来。

一些你以后会反复遇到的 RFC：

| RFC 编号 | 定义了 | 备注 |
|----------|--------|------|
| RFC 791 | IP 协议 | 1981 年——至今在用 |
| RFC 793 | TCP 协议 | 第 2 篇的核心 |
| RFC 2616 | HTTP/1.1 | 后来被更新的 RFC 取代 |
| RFC 1035 | DNS 协议 | 把域名翻译成 IP 的协议 |

> ❌ **错误认知**：RFC 既然是"征求意见"，那就是非正式的、参考用的。
>
> ✅ **正确理解**：虽然名字叫"征求意见稿"，但互联网标准（Internet Standard）RFC 是硬标准。你不按 RFC 写 TCP 实现，你的程序就没法和全世界通信。

---

## 2.6 验证方法

做个练习：挑一个你日常生活中最熟悉的"协议"场景（刷卡乘地铁、发微信红包、预约挂号都行），写出它的三要素：

1. **语法**：每条信息长什么样？
2. **语义**：每部分代表什么含义？
3. **时序**：参与者按什么顺序操作？

能写出来，你就抓住了协议的本质。
