## 三、分步操作

### 步骤 1：Node.js 是什么？

在学安装之前，先把"装的是什么东西"搞清楚。

#### JavaScript 原本只能在浏览器里跑

你可能已经知道 JavaScript——网页上的按钮点击、表单验证、动画效果，背后都是 JavaScript 在干活。但 JavaScript 有一个天生的限制：**它只能在浏览器里运行**。浏览器内置了一个"JS 引擎"，负责读取并执行 JS 代码。

2009 年，一个叫 Ryan Dahl 的程序员想："如果我把 Chrome 浏览器的 JS 引擎（V8）单独拿出来，再给它加上操作系统相关的功能（读文件、网络通信、创建服务器……），JavaScript 不就能在服务器上跑了吗？"

**他做到了。这个项目叫 Node.js。**

#### Node.js ≠ 一门新语言

> ⚠️ **重要**：Node.js 不是一门新语言。它和你写网页用的 JavaScript 是**同一门语言**。Node.js 只是给这门语言换了一个"运行环境"——从"浏览器"换成了"服务器"。

用比喻来理解：

| 场景 | 运行环境 | 能做什么 |
|------|----------|----------|
| 前端 JavaScript | 浏览器（Chrome / Edge / Firefox） | 操作网页 DOM、发 AJAX 请求、处理用户点击 |
| 后端 JavaScript（Node.js） | 服务器（你的电脑 / 云服务器） | 读写文件、操作数据库、创建 HTTP 服务 |

**一句话总结**：Node.js 是一个"拆掉了浏览器界面的 Chrome V8 引擎，外加操作系统的各种能力"。

### 步骤 2：安装 Node.js

推荐用 **nvm**（Node Version Manager）安装 Node.js。nvm 的好处是：你可以随时切换 Node.js 的版本，比如某个老项目需要 Node 16，新项目需要 Node 20，nvm 一条命令就能切换。

#### 2.1 Windows：用 nvm-windows

1. 打开浏览器，访问：https://github.com/coreybutler/nvm-windows/releases
2. 找到最新的 Release，下载 `nvm-setup.exe`
3. 运行安装程序，一路默认（Next → Next → Install）
4. 安装完成后，**重启你的终端**（关掉所有 PowerShell / CMD 窗口，重新打开）

> 🔥 **魔鬼细节**：nvm 安装后不重启终端，`nvm` 命令会提示"不是内部或外部命令"。这是因为终端在打开时会加载一次 PATH 环境变量，nvm 安装程序修改了 PATH，但已打开的终端不知道。**关掉重开就行。**

5. 验证 nvm 安装成功：

```powershell
nvm version
```

应该输出类似 `1.1.12` 的版本号。

6. 用 nvm 安装 Node.js 18 LTS（长期支持版）：

```powershell
nvm install 18
nvm use 18
```

> **为什么选 18？** Node.js 偶数版本是 LTS（Long Term Support，长期支持），奇数版本是实验版。18 是目前最稳定的 LTS 版本之一，本教程所有代码基于 18+ 编写。

#### 2.2 macOS：用 Homebrew + nvm

```bash
# 方法一：用 Homebrew 安装 nvm（推荐）
brew install nvm

# 创建 nvm 目录
mkdir ~/.nvm

# 把以下内容追加到 ~/.zshrc（如果用的是 bash，改 ~/.bash_profile）
echo 'export NVM_DIR="$HOME/.nvm"' >> ~/.zshrc
echo '[ -s "/opt/homebrew/opt/nvm/nvm.sh" ] && \. "/opt/homebrew/opt/nvm/nvm.sh"' >> ~/.zshrc
echo '[ -s "/opt/homebrew/opt/nvm/etc/bash_completion.d/nvm" ] && \. "/opt/homebrew/opt/nvm/etc/bash_completion.d/nvm"' >> ~/.zshrc

# 重新加载配置
source ~/.zshrc

# 安装 Node.js 18
nvm install 18
nvm use 18

# 方法二：不用 nvm，直接去官网下载 pkg 安装包
# 访问 https://nodejs.org/zh-cn/ 下载 macOS 安装包，双击安装即可
```

#### 2.3 Linux（Ubuntu/Debian）

```bash
# 用 curl 安装 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 重新加载配置（或关闭终端重新打开）
source ~/.bashrc

# 安装 Node.js 18
nvm install 18
nvm use 18
```

> 如果没有 curl：先装 `sudo apt install curl -y`。

### 步骤 4：npm 是什么？

你已经看到 `npm --version` 输出了版本号。那 npm 到底是什么？

**比喻**：如果说 Node.js 是**汽车的发动机**，npm 就是**加油站**。

- **Node.js** 提供了让 JavaScript 在服务器上运行的能力（发动机让你能开车）。
- **npm**（Node Package Manager）让你可以下载别人写好的代码包（加油），不用什么都自己从零造轮子。

| 场景 | 类比 |
|------|------|
| 你需要一个 Web 框架 | 去 npm "加油"：`npm install express` |
| 你写了一个好用的工具想分享 | 发布到 npm（就像开一家加油站） |
| 你的项目需要特定版本的包 | npm 帮你管理版本，不会搞混 |

> npm 是**全球最大的软件注册表**，上面有超过 200 万个包。Express、React、Vue、TypeScript——你听过的几乎所有 JS 工具，都是通过 npm 分发的。

### 步骤 6：创建项目目录 + npm init

#### 6.1 创建项目文件夹

在你想放代码的地方创建一个文件夹。推荐放在用户目录下：

```powershell
# Windows（PowerShell）
mkdir ~\blog-backend
cd ~\blog-backend

# macOS / Linux
mkdir ~/blog-backend
cd ~/blog-backend
```

然后用 VS Code 打开这个文件夹：

```bash
code .
```

> 如果提示 `code` 命令不存在：在 VS Code 里按 `Ctrl+Shift+P`，输入 `Shell Command: Install 'code' command in PATH`，回车。

#### 6.2 初始化项目

在终端（确保当前目录是 `blog-backend/`）中执行：

```bash
npm init -y
```

输出类似：

```
Wrote to D:\...\blog-backend\package.json:

{
  "name": "blog-backend",
  "version": "1.0.0",
  ...
}
```

> `-y` 是什么意思？`npm init` 原本会问一连串问题（"项目叫什么？版本号？描述？入口文件？……"），每个问题都要你按回车确认。加上 `-y`（yes 的缩写），等于对每个问题都说"用默认值就好"——**跳过所有问题，直接生成。**

#### 6.3 逐行解释 package.json

打开 `blog-backend/package.json`，你会看到类似这样的内容。我们来逐行解释每一个字段：

```json
{
  "name": "blog-backend",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}
```

| 字段 | 含义 | 通俗解释 |
|------|------|----------|
| **name** | 项目名称 | 你的项目的"身份证名字"。发布到 npm 时这个名字不能跟别人重复。本地开发无所谓。 |
| **version** | 版本号 | 用 `1.0.0` 格式（主版本.次版本.补丁版本）。改了大功能就加主版本，加了小功能就加次版本，修了 bug 就加补丁版本。 |
| **description** | 项目描述 | 一句话描述这个项目是干什么的。别人看到 `package.json` 时能快速了解。 |
| **main** | 入口文件 | **这是最重要的字段之一。** 当别人 `require('blog-backend')` 时，Node.js 会去找这个字段指定的文件。默认是 `index.js`，我们后面会改成 `server.js`。 |
| **scripts** | 脚本命令 | 在这里定义快捷命令。比如后面我们会加 `"dev": "nodemon server.js"`，然后 `npm run dev` 就能启动。不用每次敲一长串命令。 |
| **keywords** | 关键词 | 发布到 npm 时用于搜索。本地开发用不上。 |
| **author** | 作者 | 你的名字或昵称。 |
| **license** | 开源许可证 | ISC 是一个宽松的许可证，允许别人自由使用你的代码。 |

> 🔥 **魔鬼细节：`main` 字段**。如果你在 `server.js` 里写 `require('./routes/articles')`，Node.js 会去找 `routes/articles.js`。但如果有人写 `require('blog-backend')`（通过 npm 包名引用你的项目），Node.js 看的就是 `main` 字段。我们习惯把入口文件叫 `server.js`，但 `main` 默认是 `index.js`。不用担心——本教程后面启动服务器用 `node server.js`，直接指定文件名，不依赖 `main` 字段。

### 步骤 7：创建 .gitignore 文件

在 `blog-backend/` 目录下新建一个文件，命名为 `.gitignore`（注意开头有个点）。写入以下内容：

```gitignore
# 依赖目录——永远不要上传到 Git！
node_modules/

# 环境变量文件（可能包含密钥）
.env

# 操作系统生成的文件
.DS_Store
Thumbs.db

# 编辑器配置（如果你用 VS Code）
.vscode/
```

> **为什么文件名前面有个点？** 在 Unix/Linux 系统中，以 `.` 开头的文件是"隐藏文件"。`.gitignore` 就是一个隐藏的配置文件，告诉 Git "这些文件/文件夹你不用管"。

#### 为什么 node_modules/ 必须忽略？

你需要理解三个关键事实：

1. **node_modules/ 非常大**：装几个包之后，这个文件夹可能几百 MB、几万个文件。它是从 npm 下载的第三方代码的存放位置。

2. **node_modules/ 可以完美还原**：只要你有 `package.json`，在任何地方执行 `npm install`，npm 就会根据 `package.json` 里的依赖列表，重新下载所有包，精确还原 `node_modules/`。

3. **永远不要手动修改 node_modules/ 里的文件**：这个文件夹是 npm 自动管理的。你在里面改任何东西，下次 `npm install` 就会被覆盖。而且出问题时，标准的排错方法是"删掉 node_modules/，重新 npm install"，就像电脑出问题重启一样。

> **一句话总结**：把 node_modules/ 想象成"打包好的外卖"——你不需要知道外卖是怎么做的，也不应该打开盒子往里面加东西。不好吃就重新点一份（`rm -rf node_modules && npm install`）。

## 八、已知坑点与禁止事项

1. **nvm 装完不重启终端**：这是最高频的坑。nvm 修改了系统 PATH，但已打开的终端不知道。**关掉所有终端窗口，重新打开，问题解决。**

2. **不要把 `node_modules/` 提交到 Git**：`node_modules/` 体积巨大且可以 100% 还原。提交它只会让你的 Git 仓库变成几百 MB 的怪物，而且每次 `npm install` 都会产生大量变更，merge 时全是冲突。`.gitignore` 里第一行必须是 `node_modules/`。

3. **不要手动修改 `node_modules/` 里的任何文件**：里面的代码是别人维护的，你改了也没用——下次 `npm install` 就把你的修改覆盖了。如果需要改第三方包的行为，正确做法是 fork 那个包或者用 patch 工具。

4. **Node.js 17 和更早的奇数版本不要用于生产**：奇数版本（17、19、21……）是实验性质，只有 6 个月的支持周期。偶数版本（18、20、22……）是 LTS，有 30 个月的支持周期。本教程使用 Node.js 18 LTS。

5. **Windows 用户注意路径分隔符**：Windows 用反斜杠 `\`，macOS/Linux 用正斜杠 `/`。在代码中统一用正斜杠（Node.js 在 Windows 上也能识别正斜杠）。终端命令中，PowerShell 两种都接受。
